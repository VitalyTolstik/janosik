## 2. Встраиваемый снапшот доски (embed)

- **Статус:** 🔵 спроектировано
- **Приоритет:** 🟡 средний (нужен бэкенд для полной версии; фаза 0 возможна сразу)
- **Запрос (своими словами):**
  Хочу, чтобы доску можно было встраивать как HTML-страничку в чужие сайты.
  Условно: у сайта `blabla.com` админ создаёт эндпоинт `blabla.com/mytodos.html`,
  внутри которого — снапшот моей доски. Без фильтров, без редактирования,
  но с сохранением дизайна, фона, CSS. В шапке приложения (рядом с фоном /
  языком / темой) появляется кнопка «Сделать встраиваемый снапшот». На выходе —
  не скачиваемый файл (это устарело), а ссылка на HTML, который хранится в нашей
  базе и отдаётся по URL.

### 2.1. Как делают другие (исследование)

| Продукт | Механизм | Что берём на вооружение |
| --- | --- | --- |
| **Airtable** | Кнопка «Embed this view» → генерирует `<iframe>`-сниппет, указывающий на публичную read-only share-ссылку. Снапшот можно отключить/пересоздать (регенерирует токен). | Паттерн «кнопка → iframe-сниппет + публичная ссылка + отзыв/пересоздание». |
| **Notion** | «Publish to web» → публичный read-only URL (notion.site/…), который встраивают через iframe. | Паттерн «публичная страница по ссылке, доступная без логина». |
| **Trello** | Полноценные доски встраивать нельзя (whitelist доменов против clickjacking). Карточки — через скрипт-виджет `<blockquote class="trello-card">` + `embed.min.js`, который на клиенте инжектит iframe. | Урок: полноценный embed — это iframe, а не скрипт-инъекция в DOM хост-сайта. |
| **Практика (r/SaaS)** | Script-tag/Web Component виджеты ломаются от глобального CSS хост-сайта: Tailwind resets, `box-sizing`, специфичные селекторы. | Главный аргумент за iframe: полная изоляция стилей, нет конфликтов. |

**Вывод:** индустрия использует **iframe → публичную read-only страницу, живущую на нашем сервере**. Снапшот хранится в БД, отдаётся по не-угадываемому токену, может быть отозван и пересоздан.

### 2.2. Предлагаемое решение

**Главный принцип — легковесность.** Снапшот — это **статичная HTML-страница
без JavaScript и без React**. Никакого React-рантайма, `dnd-kit`, гидрации и
клиентского бандла: генератор один раз собирает плоскую HTML-строку из данных
доски и инлайнит минимальный CSS. Вес — единицы килобайт, открывается
мгновенно и работает даже с выключенным JS.

**Один снапшот → два способа доставки:**

1. **Публичная страница** `GET https://janosik.app/s/{token}` — самодостаточная
   HTML-страница (server-rendered, весь CSS инлайнен), показывающая доску
   read-only. Открывается по прямой ссылке (аналог Notion publish).
2. **Embed-сниппет** — `<iframe src="https://janosik.app/s/{token}">`, который
   админ вставляет в свой `mytodos.html` (аналог Airtable embed).

Обе формы читают **один и тот же снапшот из БД** — это не дублирование, а два
вью над одним ресурсом.

**Что попадает в снапшот (фиксируется на момент создания):**

- доска целиком: колонки, карточки, метки (данные — frozen-копия, не ссылка);
- оформление: фон доски (`flat/paper/dots/grid`), тема (`dark/light`), локаль (`en/ru`);
- шрифт Space Grotesk (встраивается в страницу), лейбл-палитра;
- метаданные: `title`, `createdAt`, `updatedAt`, опционально `expiresAt`.

**Что НЕ попадает (сознательно):**

- активные фильтры (показываем все карточки);
- любые контролы редактирования (drag, меню, диалоги, кнопки);
- приватные/служебные данные.

**Почему iframe, а не script-tag/Web Component/скачивание:**

- **iframe** — полная изоляция CSS и JS (хост-сайт не может сломать вёрстку),
  безопасен (свой документ), просто (`<iframe>` без скриптов на стороне клиента).
  Это то, что делают Airtable и Notion.
- **Script-tag виджет** — инжектится в DOM хост-сайта и наследует его CSS →
  конфликты resets/box-sizing (реальная боль из практики). Отвергаем.
- **Web Component + Shadow DOM** — изоляция стилей есть, но сложнее (ленивая
  загрузка, авторасчёт высоты, SSR). Возможен как премиум-фаза 2, не сейчас.
- **Скачивание .html** — работает офлайн, но устарело: нет единого источника
  правды, файл устаревает, не отзовёшь. Оставляем только как stopgap фазы 0.

### 2.3. Модель данных и API (бэкенд NestJS + Prisma)

```prisma
model Snapshot {
  id         String    @id @default(cuid())
  token      String    @unique           // не-угадываемый публичный токен
  boardId    String
  title      String
  background String    // "flat" | "paper" | "dots" | "grid"
  theme      String    // "dark" | "light"
  locale     String    // "en" | "ru"
  payload    Json      // frozen Board (columns + cards + labels)
  html       String?   @db.Text          // предсобранный статичный HTML (кэш)
  createdAt  DateTime  @default(now())
  updatedAt  DateTime  @updatedAt
  expiresAt  DateTime?                    // null = бессрочно
  enabled    Boolean   @default(true)     // false = отозван
}
```

`html` опционален: если хранить готовый HTML, `GET /s/:token` отдаёт его без
рендера (максимально быстро); иначе HTML собирается на лету из `payload` той же
чистой функцией.

**REST-эндпоинты (приватные, требуют авторизации):**

- `POST   /api/boards/:boardId/snapshots` — создать (или пересоздать) снапшот;
- `GET    /api/boards/:boardId/snapshots` — список снапшотов доски;
- `DELETE /api/snapshots/:id` — отозвать (или перегенерировать токен);
- `PATCH  /api/snapshots/:id` — сменить `theme`/`expiresAt`/`enabled`.

**Публичные эндпоинты (без авторизации):**

- `GET /s/:token` — server-rendered HTML страница (read-only доска, inline CSS);
- `GET /s/:token/embed` — тот же HTML, но без внешних отступов (вариант для iframe).

**Заголовки публичной страницы:**

- `Content-Type: text/html; charset=utf-8`, `Cache-Control: public, max-age=…`, `ETag`;
- НЕ ставить `X-Frame-Options: DENY/SAMEORIGIN` (мы наоборот разрешаем iframe);
- можно `Content-Security-Policy: frame-ancestors *` (или whitelist доменов, если нужно).

**Безопасность:**

- `token` — криптостойкий случайный (cuid/nanoid), действует как capability-ключ;
- отзыв/пересоздание токена (как Airtable «regenerate link»);
- опциональный срок действия `expiresAt`;
- снапшот — read-only: никакие POST/PUT с публичной стороны не принимаются.

### 2.4. Как делать (по шагам)

**Фаза 0 — без бэкенда (сейчас, только фронтенд):**

1. Написать **чистую функцию-рендерер без React** `renderSnapshotHTML(snapshot): string`
   в `src/utils/snapshot.ts`. Вход — `{ title, background, theme, locale, board }`,
   выход — плоская HTML-строка (`<section>`/`<article>` + данные доски).
   Никакого JSX, никаких компонентов, никакого `dnd-kit`.
2. Подготовить **минимальный CSS-фрагмент** `snapshot.css`: только токены цветов,
   фоновые классы `janosik-bg-*`, чипы меток и раскладку «колонки/карточки».
   Это выжимка на 2–3 КБ, а не весь `index.css` (~63 КБ).
3. Собрать «снапшот-объект» из текущего состояния (хуки `useBoard`,
   `useBoardBackground`, `useTheme`, `useI18n`) — единственное место, где
   фронтенд касается React.
4. Обернуть результат `renderSnapshotHTML` в полный `<!doctype html>` документ
   с инлайн-`<style>` — и отдать кнопками **«Скачать .html»** / **«Скопировать HTML»**
   (временный stopgap). Проверить: открытый файл — чистая статика, ноль JS.

**Фаза 1 — с бэкендом (NestJS + Prisma + SQL):**

1. Prisma-модель `Snapshot` (см. 2.3) + миграция. Храним `payload`; опционально
   кэшируем готовый `html`.
2. API create/list/delete/regenerate с авторизацией. Создание снапшота вызывает
   **ту же чистую функцию** `renderSnapshotHTML` (выносится в общий модуль,
   который используют и фронтенд, и сервер) — React нигде не участвует.
3. `GET /s/:token` — отдаёт статичный HTML (из кэша `html` или рендер на лету),
   с `Cache-Control` + `ETag`. Никакого SSR/`renderToString`/React.
4. UI-кнопка в шапке (рядом с BackgroundSwitcher / LanguageSwitcher / темой),
   иконка `Share2` или `Code2`, тултип «Встраиваемый снапшот». Модалка:
   настройки (тема), «Создать» → показывает публичную ссылку + `<iframe>`-сниппет +
   кнопки «Скопировать» и «Отозвать/пересоздать».
5. Embed-сниппет-шаблон:

   ```html
   <iframe
     src="https://janosik.app/s/AbC123xYz"
     width="100%"
     height="600"
     style="border:0;border-radius:12px"
     loading="lazy"
     title="Product Launch"
   ></iframe>
   ```

**Фаза 2 — опционально (позже):**

 1. Режим **live-embed** (read-only, но отражает изменения доски) — второй
    тип снапшота «live» вместо «frozen» (тут уже нужен лёгкий JS для подгрузки,
    но это отдельный продукт, не снапшот).
 2. **Web Component + Shadow DOM** как премиум-виджет без iframe (если понадобится
    встраивание с авторасчётом высоты и без границ iframe).
 3. Метрики просмотров, пароль на снапшот, срок действия по умолчанию.

## 3. Экспорт/импорт JSON + авто-бэкап (страховка данных)

- **Статус:** 🔵 спроектировано
- **Приоритет:** 🔴 критично (снимает главный риск потери данных до бэкенда)
- **Запрос (своими словами):** localStorage — единственное хранилище: чистка кэша
  браузера стирает всё. Нужна дешёвая страховка, пока бэкенда нет: выгрузить доску
  в файл и восстановить, плюс авто-бэкап.
- **Как делают другие:** Trello — экспорт доски (платно), Notion — экспорт в
  Markdown/CSV/JSON, большинство канбан-сервисов — JSON/CSV + периодический бэкап.
- **Предлагаемое решение:** экспорт/импорт JSON с валидацией
  (`normalizeBoards` уже есть — переиспользовать); авто-бэкап: накопительная
  история снапшотов состояния (например, в IndexedDB или файлом по запросу);
  формат экспорта осознанно равен будущему формату seed для сервера — тогда бэк
  начнётся с готовых данных.
- **Модель данных / API:** JSON-файл вида `{ schemaVersion, exportedAt, boards }`;
  импорт через `<input type="file">` + валидация; кнопка «Экспорт» в настройках.
- **Как делать (по шагам):**
  1. Сервис `exportBoard(): string` + `importBoard(json)` с валидацией (roundtrip:
     экспорт → импорт = исходное состояние, покрыть тестами).
  2. Кнопки «Экспорт JSON» / «Импорт JSON» в UI.
  3. Авто-снапшоты: копия состояния при каждом N-м изменении или раз в день.
- **Открытые вопросы:** где хранить авто-бэкапы (IndexedDB-история vs скачивание
  файла по расписанию); как часто снапшотить.
