## Verification

- Backend, shared and UI typechecks. Backend, UI and site builds.
- 83 targeted backend unit tests and 110 backend HTTP/integration tests against a disposable PostgreSQL database, real Redis and a local SMTP receiver. CI enables the BullMQ case with `TASK1806_TEST_REDIS_URL`.
- 116 focused UI tests for the bell, account profile, board provider, command queue and realtime bridge.
- Lint, Prettier, `git diff --check`, OpenAPI validation and ten validator tests, and 52 docs link tests. The two new section links were also checked in the built EN/RU pages.
- The original TASK-180.6 implementation ran four focused Chrome collaboration scenarios, including a dropped response and a dropped response followed by HTTP 504. The full Docker and browser matrices were outside this revision's scope.

## Manual checks

- An isolated deployment started with Redis stopped. Readiness returned 503 with `db: up` and `redis: down`. After Redis started, the three schedules appeared and readiness returned 200. A `FLUSHDB` against the disposable Redis database removed the schedules and the running API rebuilt them. The persisted schedule settings in PostgreSQL remained intact.
- An nginx container with the generated CSP include matched Node's CSP/HSTS on the site root, app shell, app deep link, embeddable public share, proxied readiness, and API and site 404s. nginx-generated API 413 and 502 responses supplied HSTS and a restrictive CSP. `nginx -t` rejected an absent include.
- The migration was applied to a database seeded under the preceding schema. It linked a pending broadcast to a matching account, retired and scrubbed a pending broadcast with an unmatched address, and preserved both a finished broadcast and a pending attention row.

## Residual risks

- SMTP acceptance and the database commit are separate operations. A lost acceptance reply or a worker crash between the two can result in duplicate mail with the same Message-ID. Downstream bounces occur outside this system.
- The upgrade retires old pending outbox broadcasts whose addresses match no current account. Those payloads cannot distinguish external segment recipients from deleted accounts. Direct BullMQ payloads queued before the outbox rollout retain their legacy delivery behavior. New broadcasts track known accounts and can still include external segment addresses.
- Grouped reminders canceled for opt-out or lost board access retain their card, recipient and due-date markers. A new due date can qualify again. A terminal digest retains its attention reservations through attention retention.
- Schedule recovery restores future ticks. Digests pick up retained, unreserved attention events. Activity summaries and due reminders still use their configured time windows.
- When the command replies and the snapshot remain unavailable, reconciliation resumes on SSE replay or the next successful online or focus refresh.
- The large-audience regression verifies PostgreSQL publication and staging. The dispatch test verifies pagination, and the smaller BullMQ/SMTP tests verify delivery and retries. Full-audience SMTP throughput depends on the relay and worker deployment.
