# TASK-180.5 MCP and public API contracts

| ID | Implementation | Regression evidence |
| --- | --- | --- |
| M32 | `janosik_get_card`, `janosik_get_run` and `janosik_get_approval` accept `outputPath` for the full authorized JSON. Local writes require filesystem opt-in and write-enabled MCP mode. The file is staged with mode `0600` on POSIX and published atomically without replacing an existing path. A failed file write returns `filesystem_error`. | The live stdio MCP test saves all three documents above 25,000 characters and compares the parsed files to the REST results. A duplicate path returns `filesystem_error`. Unit tests cover write annotations in all enabled and disabled modes, confinement, concurrent publishers, permissions and a real injected partial-write failure for each filesystem mode on Linux. |
| M33 | Successful command mutations expose `seq` and `runId` in structured results. Batches carry the server's run ID and highest sequence. A write with no recorded run returns `runId: null`. | MCP client and server tests assert single, retry and batch results. The live test reads the returned batch run, matches its last command sequence and uses that sequence for the next write. |
| M34 | The EN/RU REST references distinguish browser-session, PAT and shared routes. OpenAPI explicitly allows either credential for the revert operation and describes the body-dependent authorization. A PAT is limited to `dryRun: true`. Applying a revert requires a board ADMIN browser session. | OpenAPI tests assert both security alternatives and the apply restriction, including omitted `dryRun`. Backend policy, approval, pause, run and security tests exercise the credential boundaries. The runs suite verifies a PAT dry run and `403 pat_forbidden` on apply. |
| M35 | The owner can edit the token's capability preset in a browser session. The preset never raises the board role, and read-only tokens have effective observer scope. The create and edit controls announce the field label and value. The edit dialog shows a specific message when an impersonated session is read-only. | The validator checks both `ScopePreset.description` and the token PATCH property. The token-update suite verifies a persisted preset change, and UI tests assert the accessible names, the value submitted and the messages for PAT and impersonation refusals. |
| L8 | The OpenAPI error enum matches the shared catalog, and token PATCH describes `409 token_revoked`. | The validator compares the enum and checks the response schema. The token-update suite checks the actual 409. |
| L9 | OpenAPI and the EN/RU REST guides document `expiresInHours` from 1 to 87,600 hours. Relative expiry takes precedence. A supplied non-null `expiresAt` must still pass ISO-8601 validation. | OpenAPI checks both descriptions. The share suite proves precedence over a past ISO timestamp and rejection of a malformed timestamp supplied with a valid relative duration. |
| L10 | Token PATCH lists the editable fields and documents that `expiresAt` is stripped. Token secrets are returned on creation only. | The validator checks the PATCH properties and stripping description. The token-update suite proves that the expiry remains the same and that the PATCH response omits the secret. |
| L11 | OpenAPI and the EN/RU API indexes describe password-reset request and confirmation, including IP quotas of 3/hour and 10/minute respectively. | The OpenAPI test checks public access, success shape, quotas and 429 responses. The backend rate-limit and password-reset suites cover quota enforcement and code handling. |
| L12 | The public `GET /auth/config` contract includes `allowRegistration`, `allowPublicShares` and `limits` with `boards` and `importBytes`. Registration availability includes the one-time no-SMTP bootstrap. | OpenAPI checks required fields. The auth-config and bootstrap e2e suites verify the reported limits and registration behavior. |
| L13 | The REST guides use `/boards/:id/plans` and `/boards/:id/plans/apply`, and the route inventory covers board-context reads, permanent share deletion, pending invitations and OAuth linking. Both OAuth tables list the browser-session link endpoint and its `201 { redirectUrl: string }` response. | The validator checks the board-scoped apply operation. Backend tests cover plan routes and related REST surfaces. Site tests check internal doc links, and comparison of the two OAuth tables confirms all four method/path pairs and the link response. |

## Verification

- UI passed 1,815 tests across 198 suites. The focused account and run preview check passed 34 tests.
- MCP passed 162 tests with one platform-specific test skipped. Backend passed 149 targeted unit tests and 195 targeted e2e tests across 19 suites, including both agent-control security suites and live MCP over stdio against Nest and PostgreSQL.
- OpenAPI validation passed for 83 operations and all 10 validator tests passed. The site passed all 69 tests, including internal docs links, and Astro reported zero errors and warnings.
- UI, shared, backend and MCP type checks passed. UI, backend, MCP and site builds passed. ESLint passed with zero errors. Prettier and `git diff --check` passed.

## Residuals

- M32 uses hard links for atomic publication. Confined writes also require a target filesystem with `O_TMPFILE` support. The live tests used a Linux filesystem with both capabilities.
- M34 retains one revert route for both modes. OpenAPI expresses the body-dependent authorization in the operation description.
- The full Docker and browser matrix was outside this verification. L39 conflict-preview retention is recorded in the TASK-180.4 evidence.
