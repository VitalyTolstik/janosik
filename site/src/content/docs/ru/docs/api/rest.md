Изменения содержимого идут через [API команд](/ru/docs/api/commands/). Эта страница
описывает всё остальное в пользовательском API: доски и членство,
комментарии, вложения, публичные ссылки и поток обновлений. Общие соглашения
(базовый путь, аутентификация, ошибки, ограничения частоты) см. в
[Справочнике по API](./).

## Доски и участники

Создание и удаление доски, а также управление участниками выполняются через
REST. Эти операции не являются действиями редьюсера. Изменения содержимого доски
проходят через журнал команд.

| Метод    | Путь                          | Аутентификация / роль | Запрос            | Ответ              |
| -------- | ----------------------------- | --------------------- | ----------------- | ------------------ |
| `GET`    | `/boards`                     | пользователь          | нет               | `BoardSummary[]`   |
| `POST`   | `/boards`                     | пользователь          | `CreateBoardDto`  | `BoardAggregate`   |
| `POST`   | `/boards/import`              | пользователь          | `BoardEnvelope`   | `BoardAggregate[]` |
| `GET`    | `/boards/:id`                 | участник              | нет               | `BoardAggregate`   |
| `DELETE` | `/boards/:id`                 | `ADMIN`               | нет               | `{ status: "ok" }` |
| `GET`    | `/boards/:id/members`         | участник              | нет               | `BoardMemberDto[]` |
| `POST`   | `/boards/:id/members`         | `ADMIN`               | `InviteMemberDto` | `BoardMemberDto`   |
| `PATCH`  | `/boards/:id/members/:userId` | `ADMIN`               | `UpdateMemberDto` | `BoardMemberDto`   |
| `DELETE` | `/boards/:id/members/:userId` | `ADMIN`               | нет               | `{ status: "ok" }` |
| `GET`    | `/boards/:id/export`          | участник              | нет               | `BoardEnvelope`    |
| `GET`    | `/boards/:id/search`          | участник              | query `q`         | `{ cardIds: string[] }` |

`GET /boards` перечисляет доски, где вызывающий является принятым участником,
сначала новые, каждая со счётчиком карточек и колонок и ролью вызывающего.
Ожидающее приглашение не считается.

`POST /boards` создаёт доску и назначает вызывающему роль `ADMIN`. Если название
пустое, сервер возвращает `400`.

`POST /boards/import` принимает пакет экспорта, либо как разобранный
JSON-объект, либо как сырую JSON-строку; сервер валидирует уже разобранный
объект без round-trip stringify→parse. Сервер нормализует входные данные и создаёт каждую
доску из пакета, где импортирующий становится `ADMIN`. Пустой или неверный
пакет вызывает ответ `400`. `?dryRun=1` возвращает
`{boards, cards, columns, labels, withinLimit}` и ничего не пишет. Формат пакета:

```json
{ "app": "janosik", "schemaVersion": 3, "exportedAt": 0, "boards": [] }
```

Версия 3 добавляет необязательный `agentPolicy` доски; версия 2 добавила
необязательный `workflow`; файлы версий 1/2 по-прежнему импортируются (без
политики). Импорт создаёт новые id
колонок и карточек и переназначает ссылки процесса; переход, чья колонка
отсутствует, отбрасывается, а не ломает импорт.

`GET /boards/:id` возвращает агрегат доски и устанавливает заголовок ответа
`X-Board-Seq`, несущий `seq` команды, который отражает агрегат. Клиент
возобновляет SSE-поток с этого значения. Если доска неизвестна или помечена
удалённой, сервер возвращает `404`. Если у доски есть процесс, агрегат
содержит `workflow`.

`GET /boards/:id/search?q=` возвращает `{ cardIds }` — карточки, у которых
заголовок, описание, пункт чек-листа или комментарий содержит `q`
(подстрока без учёта регистра). Эндпоинт достаёт текст комментариев, которых
нет в агрегате доски. При длине поисковой строки больше 200 символов сервер возвращает `400`.

`DELETE /boards/:id` помечает доску и её дочерние записи удалёнными.
Записи об участниках удаляются окончательно. Ссылки `Live` отзываются, а ссылки на снимки сохраняются.

`POST /boards/:id/members` приглашает пользователя по email. Адрес
обрезается и приводится к нижнему регистру. Ответ никогда не раскрывает, есть
ли у адреса аккаунт: известный адрес, неизвестный и повторное приглашение
того, чьё приглашение ещё ожидает, одинаково отвечают `201` с замаскированным
`BoardMemberDto`. В нём `userId` равен `""`, а `displayName`, `avatarColor` и
`avatarPath` равны `null`; `email`, `role` и `expiresAt` повторяют запрос. Для
известного адреса строка создаётся как ожидающее приглашение и не даёт
доступа до принятия. Для неизвестного адреса ничего не сохраняется, поэтому
пригласите человека снова, когда у него появится аккаунт. `expiresAt`
учитывается только для `VIEWER`. Если пользователь с этим адресом уже принял
приглашение на доску, сервер возвращает `409`.

Приглашённый, чей аккаунт ещё не подтвердил email, не видит приглашение и не
может его принять, пока адрес не подтверждён (см.
[Приглашения](../#приглашения)).

`PATCH /boards/:id/members/:userId` меняет роль и/или срок `VIEWER`.
Последнего `ADMIN` доски нельзя понизить, и последнего `ADMIN` нельзя
удалить: в обоих случаях сервер возвращает `409`.

### Порядок доступа

Маршруты уровня доски отвечают в таком порядке: отсутствующий или неверный
токен — это `401`; неизвестная или мягко удалённая доска — это `404`; отсутствие
членства — это `403`; истёкшее членство `VIEWER` — это `403`, а устаревшая строка
удаляется; роль, не разрешённая маршрутом, это `403`.

Каждый маршрут этой страницы принимает персональный API-токен наравне с
access-токеном. Только для сессии работают лишь маршруты учётных данных
аккаунта (см. [справочник API](../#маршруты-только-для-сессии)).

## Комментарии

Комментарии хранятся как строки Markdown и обрабатываются через REST. `CardAccessGuard` определяет
доску, к которой относится запись по карточке или комментарию и проверяет членство.

| Метод    | Путь                      | Аутентификация / роль | Запрос             | Ответ              |
| -------- | ------------------------- | --------------------- | ------------------ | ------------------ |
| `POST`   | `/cards/:cardId/comments` | `ADMIN` / `MEMBER`    | `CreateCommentDto` | `CommentDto`       |
| `GET`    | `/cards/:cardId/comments` | участник              | query `cursor`, `limit`, `kind` | `CommentPage`      |
| `DELETE` | `/comments/:commentId`    | `ADMIN` / `MEMBER`    | нет                | `{ status: "ok" }` |

`POST` не принимает параметров запроса; тело — это `CreateCommentDto`. Если
текст пуст или `kind` неизвестен, сервер возвращает `400`. Когда передан
`commandId`, повтор с тем же значением возвращает первый комментарий вместо
добавления дубликата. Если `commandId` уже использован на другой карточке, сервер возвращает `409`.

`GET` принимает `?cursor=` (непрозрачный), `?limit=` и `?kind=` (один вид
комментария). Лимит по умолчанию 50, максимум 100; при лимите вне диапазона от
`1` до `100` или неизвестном `kind` сервер возвращает `400`. Страницы идут
сначала новые,
и `nextCursor` равен `null` в конце.

`DELETE` удаляет комментарий. Только автор может удалить свой комментарий;
при попытке удалить чужой комментарий сервер возвращает `403`.

Каждая запись создаёт строку `Activity` и публикует кадр SSE `activity`.

## Сессии агентов и атрибуция

Персональный API-токен может открыть сессию агента на доске. Сессия — это
контекст атрибуции, а не второй аккаунт: она не даёт прав сверх токена.

| Метод  | Путь                                                  | Аутентификация / роль      | Запрос                     | Ответ               |
| ------ | ----------------------------------------------------- | -------------------------- | -------------------------- | ------------------- |
| `POST` | `/boards/:id/agent-sessions`                          | PAT, участник доски        | `CreateAgentSessionDto`    | `AgentSessionDto`   |
| `POST` | `/boards/:id/agent-sessions/:sessionId/heartbeat`     | тот же PAT                 | `AgentSessionHeartbeatDto` | `AgentSessionDto`   |
| `POST` | `/boards/:id/agent-sessions/:sessionId/end`           | тот же PAT или `ADMIN`     | `EndAgentSessionDto`       | `AgentSessionDto`   |
| `GET`  | `/boards/:id/agent-sessions?active=1`                 | любой участник             | нет                        | `AgentSessionDto[]` |
| `GET`  | `/boards/:id/agent-sessions/:sessionId`               | любой участник             | нет                        | `AgentSessionDto`   |

При старте можно передать `name`, `clientName`, `model` (до 100 символов).
Heartbeat принимает `status` (`active`, `idle`, `waiting_approval`),
`currentCardId`, `summary`; end — `status` (`completed`, `failed`,
`cancelled`) и `summary`. Повторный `end` возвращает сохранённое терминальное
состояние. Сессия без heartbeat дольше пяти минут получает вычисляемый
`stale: true` (в БД это не пишется). Завершение сессии освобождает её claim'ы.

PAT-запись может передать `X-Agent-Session: <sessionId>`. Сервер проверяет,
что сессия принадлежит тем же пользователю, токену и доске и не закрыта:
несовпадение — `403 agent_session_invalid`, закрытая сессия —
`403 agent_session_closed`. Start и heartbeat доступны только PAT: браузерная
сессия получает `403 pat_required` (в `endpoint` указано `start` или
`heartbeat`). `end` принимает тот же PAT или браузерную сессию board ADMIN.
Клиенты без заголовка продолжают работать: команды всё равно получают
`apiTokenId`, а `agentSessionId` остаётся `null`. Всю атрибуцию заполняет
сервер из principal; тело запроса не может подделать `apiTokenId`,
`agentSessionId`, `runId`, `agentName`, `claimedByTokenId` или
`claimedBySessionId`.

Записи и SSE-кадры команд содержат необязательные `apiTokenId`,
`agentSessionId`, `runId`, `agentName`. Записи активности содержат те же поля
плюс `actorType`; `CommentDto` отдаёт `actorType`, `apiTokenId`,
`agentSessionId`, `agentName`, а `AttachmentDto` —
`uploadedByTokenId`/`uploadedBySessionId`. `GET /boards/:id/activity` и
`GET /cards/:id/activity` принимают `actorType`, `apiTokenId`,
`agentSessionId`, `runId`, `type`, `from`, `to`; фильтры применяются к обоим
источникам (команды и строки активности). `GET /boards/:id/commands`
принимает только `since`, `runId`, `apiTokenId`, `agentSessionId`. Публичные
share-ответы и потоки удаляют id токена/сессии и имя токена. `GET /auth/me`
для PAT добавляет несекретный объект `token` (`scopePreset`, `trustedCi`,
метки паузы, `effectiveTokenScope`) и блок `server`; у сессии браузера
`token: null`.

## Области токена и destructive gate

Каждый PAT несёт один неизменяемый пресет. Новый ключ создаётся как `worker`;
существующие ключи получили `admin` + `trustedCi` (у read-only эффективный
пресет — `observer`). Пресет выбирается при создании и не меняется: создайте
новый ключ и отзовите старый. `readOnly` остаётся устаревшим совместимым
флагом и всегда побеждает, давая `observer`.

| Пресет     | Чтение | Обычная запись | Переход в Done (`reviewer`) | Destructive | Администрирование доски |
| ---------- | ------ | -------------- | --------------------------- | ----------- | ----------------------- |
| `observer` | да     | нет            | нет                         | нет         | нет                     |
| `worker`   | да     | да             | нет                         | approval / `trustedCi` | нет          |
| `reviewer` | да     | да             | да                          | approval / `trustedCi` | нет          |
| `admin`    | да     | да             | да                          | approval / `trustedCi` | да           |

Пресет не повышает роль на доске: ключ `admin` у участника MEMBER не даёт
управлять участниками, а ключ `worker` у ADMIN не удаляет карточку без
подтверждения. Destructive-действия требуют подтверждения человеком, если у
ключа нет `trustedCi`; `Board.agentPolicy.destructive = "deny"` — жёсткий
запрет, который не обходит даже `trustedCi`. Подтверждение не повышает область:
ключу `worker`, которому нужен `admin`, отвечают `scope_denied`, а не
`approval_required`.

Ключ, привязанный к доске, ограничен этой доской и не может создавать или
импортировать доски. Account-маршруты (запись профиля, управление ключами,
приглашения, экспорт) и их чувствительное чтение доступны только сессии
браузера: PAT получает `403 pat_forbidden`. Чтение идентичности (`GET /auth/me`,
аватар) остаётся доступным.

Коды ошибок аддитивны и стабильны:

| Код | HTTP | Значение |
| --- | --- | --- |
| `scope_denied` | 403 | пресет или роль на доске не разрешают действие; для пресета — `requiredScope`/`action`, для роли — `requiredRoles`, для ключа, привязанного к другой доске, — `reason: "board_scope"` |
| `destructive_denied` | 403 | политика доски `destructive: "deny"`; `reason: "board_policy"` |
| `approval_required` | 409 | destructive-действие без подтверждения; запрос создан, ничего не применено; содержит `approvalId`, `planHash`, `expiresAt` |
| `approval_expired` | 409 | подтверждение истекло до решения/применения; содержит `approvalId`, `expiresAt` |
| `approval_mismatch` | 409 | план/`planHash` или `kind` не совпадают; содержит `approvalId` и префиксы хешей |
| `approval_owner_mismatch` | 403 | подтверждение принадлежит другому токену/агентской сессии |
| `approval_not_pending` | 409 | решение/отмена/применение попали в состояние не `pending`; содержит `status` |
| `approval_rejected` / `approval_cancelled` | 409 | запрос отклонён/отменён; применять его нельзя |
| `approval_consumed` | 409 | подтверждение уже применено; при наличии содержит `runId` |
| `pat_forbidden` | 403 | account-маршрут доступен только сессии |
| `pat_read_only` | 403 | устаревший read-only ключ отклонил запись |

## Подтверждения

Подтверждение разрешает один точный план, но само ничего не применяет. Агент
создаёт запрос своим PAT, человек-ADMIN доски решает его в браузерной сессии,
а агент повторяет тот же план с полученным id.

| Метод | Путь | Доступ | Запрос | Ответ |
| --- | --- | --- | --- | --- |
| `POST` | `/boards/:id/approvals` | PAT, участник доски | `CreateApprovalRequest` | `ApprovalRequestDto` |
| `GET` | `/boards/:id/approvals` | ADMIN доски или создавший PAT | `status`, `kind`, `cardId`, `limit` | `ApprovalRequestDto[]` |
| `GET` | `/boards/:id/approvals/:approvalId` | ADMIN доски или создавший PAT | — | `ApprovalRequestDto` |
| `POST` | `/boards/:id/approvals/:approvalId/decision` | только сессия, ADMIN доски | `{ decision, planHash, comment? }` | `ApprovalRequestDto` |
| `POST` | `/boards/:id/approvals/:approvalId/cancel` | создавший PAT или ADMIN доски | — | `ApprovalRequestDto` |

Тело `POST /boards/:id/approvals` — `{ kind, cardId?, ttlMinutes?, plan }`, где
`kind` ∈ `destructive`/`done`/`custom`, а `plan` — либо
`{ schemaVersion: 1, boardId, commands }`, либо
`{ schemaVersion: 1, boardId, operations }` (ровно одно). `commands`
проверяются тем же валидатором и лимитами, что `/commands/batch` (по умолчанию
100 команд, 50 создаваемых карточек); в `operations` ровно одна разрешённая
lifecycle-операция (`board.delete`, `member.*`, `share.*`,
`attachment.delete`). `action.at` и `boardId` внутри действия не входят в
намерение: сервер убирает их перед вычислением
`planHash = sha256(canonicalJson({schemaVersion, boardId, commands|operations}))`,
поэтому одно и то же тело всегда даёт один хеш. Хеш возвращает сервер; хеш
клиента не принимается как истина.

Если destructive-команда/батч или lifecycle REST-вызов приходят без
`X-Approval-Id`, сервер создаёт такой же запрос для точного плана и отвечает
`409 approval_required` с `approvalId`, `planHash`, `expiresAt`; ничего не
применяется. Пресет должен уже позволять действие после подтверждения: ключ
`worker` не может превратить удаление доски в approval (получит
`scope_denied`), а `destructive: "deny"` — жёсткий `403 destructive_denied` без
создания строки.

Чтобы применить, повторите тот же план/команды с `X-Approval-Id: <id>` на
`POST /commands`, `/commands/batch` или исходном lifecycle-маршруте.
`requestedByTokenId` должен совпадать с текущим PAT; если запрос записал
агентскую сессию, `X-Agent-Session` тоже должен совпасть. Подтверждение
одноразовое: те же уже применённые команды — идемпотентный повтор, другой
план получает `approval_mismatch` или `approval_consumed`. Применение
batch/commands создаёт `AgentRun` с `approvalId`, проставляет `runId` каждой
команде и пишет `approval_consumed`; lifecycle-операция оставляет `runId`
`null`. Решение доступно только браузерной сессии, PAT получает
`pat_forbidden`: человек-владелец токена подтверждает запрос агента, агент не
подтверждает себя сам.

TTL = `min(ttlMinutes ?? policy.approvalTtlMinutes, policy.approvalTtlMinutes)` с
нижней границей 5 минут. Просроченные строки переводятся в `expired` лениво
при чтении, решении и применении; остальные может добрать maintenance-sweep.
Каждый шаг пишет `Activity` (`approval_requested`, `approval_approved`,
`approval_rejected`, `approval_cancelled`, `approval_expired`,
`approval_consumed`) и публикует SSE-кадр `approval`; решение также попадает
в `SecurityAuditLog` (`approval.decided`).

Сессии браузера не проходят через пресет/destructive gate; их правила ролей на
доске не меняются (включая обычный undo). PAT никогда не отправляет команды
`RESTORE_*` (`scope_denied`) — агент делает компенсирующие правки или просит
человека откатить run.

## Вложения

Файлы загружаются через REST как `multipart/form-data` с единственной частью
`file`. `CardAccessGuard` определяет доску, к которой относится запись по карточке или вложению.

| Метод    | Путь                                   | Аутентификация / роль | Ответ              |
| -------- | -------------------------------------- | --------------------- | ------------------ |
| `POST`   | `/cards/:cardId/attachments`           | `ADMIN` / `MEMBER`    | `AttachmentDto`    |
| `GET`    | `/cards/:cardId/attachments`           | участник              | `AttachmentDto[]`  |
| `GET`    | `/attachments/:attachmentId/content`   | участник              | байты блоба        |
| `GET`    | `/attachments/:attachmentId/thumbnail` | участник              | байты изображения  |
| `GET`    | `/attachments/:attachmentId/poster`    | участник              | байты изображения  |
| `DELETE` | `/attachments/:attachmentId`           | `ADMIN` / `MEMBER`    | `{ status: "ok" }` |

`POST` принимает `?inline=1` (или `?inline=true`), чтобы пометить блоб как
медиа, встроенное в тело: скрыто из списка, без счётчика и без активности.
Параметр `?description=1` помечает файл, вставленный в описание: он виден в
списке, пока на него ссылается описание или комментарий, и скрывается, когда
ссылок больше нет. Скрытые файлы остаются доступны и учитываются в лимите,
чтобы работали Undo/Redo и сохранённые снимки. При одновременном указании
обоих параметров приоритет у `inline`. Список скрытых файлов для очистки:
`GET /cards/:cardId/attachments?detached=1`.
Файл не более `LIMITS.attachmentSize` (25 МБ). Сервер применяет allowlist
MIME-типов и проверяет сигнатуры файлов для типов изображений, видео, аудио и
архивов; если заявленный тип не соответствует содержимому файла, сервер
возвращает `400`. Если у карточки уже есть `LIMITS.attachmentsPerCard` (20)
неудалённых вложений, новая загрузка также отклоняется с `400`.

`GET /attachments/:attachmentId/content` отдаёт блоб с
`Content-Disposition: attachment`. Ответ поддерживает диапазоны: заголовок
`Range` даёт `206` с `Content-Range`, а невыполнимый диапазон даёт `416`.

`GET .../thumbnail` отдаёт сгенерированное превью (`image/jpeg`), когда оно
готово, иначе исходный блоб для изображений. У видео нет миниатюры, а
для остальных файлов без готовой миниатюры сервер возвращает `404`.

`GET .../poster` отдаёт первый значимый кадр видео (`image/jpeg`). Когда он
не сгенерирован, отвечает `404`.

## Управление публичными ссылками

Публичная ссылка — отдельная сущность с токеном, режимом, настройками доступа,
сроком действия и статусом отзыва. Маршруты управления находятся внутри доски и
доступны только роли `ADMIN`.

| Метод    | Путь                                  | Аутентификация / роль | Запрос           | Ответ             |
| -------- | ------------------------------------- | --------------------- | ---------------- | ----------------- |
| `GET`    | `/boards/:id/shares`                  | `ADMIN`               | нет              | `BoardShareDto[]` |
| `POST`   | `/boards/:id/shares`                  | `ADMIN`               | `CreateShareDto` | `BoardShareDto`   |
| `POST`   | `/boards/:id/shares/:shareId/refresh` | `ADMIN`               | нет              | `BoardShareDto`   |
| `PATCH`  | `/boards/:id/shares/:shareId`         | `ADMIN`               | `UpdateShareDto` | `BoardShareDto`   |
| `DELETE` | `/boards/:id/shares/:shareId`         | `ADMIN`               | нет              | `BoardShareDto`   |

Ссылка работает в режиме `snapshot` или `live`. Снимок (`snapshot`) сохраняет
состояние доски на момент создания и остаётся доступным после её удаления;
обновить снимок может администратор доски. Ссылка `live` показывает текущую
версию доски и получает изменения по SSE.

`POST` генерирует случайный токен (16 байт, base64url). `includeComments` по
умолчанию `true` для live-share и `false` для snapshot; `includeAttachments`
по умолчанию `false`. Если `expiresAt` находится в прошлом, сервер возвращает `400`.

`POST .../refresh` обновляет снимок до текущего состояния доски. Для ссылки `live` сервер возвращает `400`.

`DELETE` отзывает ссылку: её токен сразу перестаёт работать. Отзыв
идемпотентен.

Если ссылка `:shareId` относится к другой доске, сервер возвращает `403`; если она неизвестна — `404`.

## Публичные ссылки: чтение данных

Публичный API доступен только для чтения и не требует пользовательского JWT.
`ShareAccessGuard` проверяет токен ссылки, срок действия, отзыв и общий
переключатель `ALLOW_PUBLIC_SHARES`. Если ссылка неизвестна, отозвана,
просрочена или отключена, сервер возвращает одинаковый ответ `404`. Ответы
содержат заголовок `X-Robots-Tag: noindex, nofollow`.

Для каждого токена действуют лимиты: 240 запросов в минуту на токен
(`SHARE_RATE_LIMIT`), и 60 в минуту для OG-превью (`SHARE_OG_RATE_LIMIT`).
При превышении лимита сервер возвращает `429`.

| Метод  | Путь                                              | Ответ             |
| ------ | ------------------------------------------------- | ----------------- |
| `GET`  | `/share/:token`                                   | `PublicBoardDto`  |
| `GET`  | `/share/:token/events`                            | поток SSE         |
| `GET`  | `/share/:token/og.png`                            | `image/png`       |
| `GET`  | `/share/:token/cards/:cardId/comments`            | `CommentPage`     |
| `GET`  | `/share/:token/cards/:cardId/attachments`         | `AttachmentDto[]` |
| `GET`  | `/share/:token/attachments/:attachmentId/content` | байты блоба       |
| `POST` | `/share/:token`                                   | `405`             |
| `POST` | `/share/:token/{*rest}`                           | `405`             |

`GET /share/:token` возвращает полные данные публичной доски: доску (живой агрегат
или замороженный snapshot), очищенный состав участников без email и флаги
приватности share. Он считает один просмотр. Live-share, чья доска исчезла,
отвечает `410`; snapshot никогда не зависит от доски.

`GET /share/:token/events` работает только в режиме live; snapshot отвечает
`404`. Он стримит кадры `command` и, когда задан `includeComments`, кадры
`activity`. Кадры presence и membership отбрасываются, поэтому публичный
посетитель не получает события о присутствии участников. Получение пропущенных
событий `?since=` повторяет поток участника,
включая кадр `resync`. Живая доска, которая исчезла, отвечает `410`. Открытый
поток перепроверяет share на каждом тике keep-alive и закрывается, как только
share отозван или истёк, публичные ссылки выключены или доски больше нет.

`GET /share/:token/og.png` возвращает детерминированный PNG-превью доски.

`GET .../comments` и `GET .../attachments` отвечают `404`, когда share не
раскрывает соответственно комментарии или вложения. Карточка, которой нет на
общей доске, отвечает `404`.

Snapshot замораживает и обсуждение: его комментарии, список вложений и
содержимое вложений включают только то, что создано до момента снимка или его
последнего обновления. При запросе вложения, добавленного после снимка, сервер
возвращает `404`.

`POST /share/:token` и любой вложенный `POST` отвечают `405` с
`"Shared boards are read-only"`. Публичный контур заявляет запрет на запись, а
не полагается на отсутствие маршрута.

## Обновления в реальном времени

| Метод  | Путь                   | Аутентификация / роль | Запрос                  | Ответ        |
| ------ | ---------------------- | --------------------- | ----------------------- | ------------ |
| `GET`  | `/boards/:id/events`   | участник              | query `since`, `client` | поток SSE    |
| `POST` | `/boards/:id/presence` | участник              | `PresencePingDto`       | `204`, пусто |

`GET /boards/:id/events` открывает поток server-sent events. Для подключения
нужен Bearer-токен (access-токен или персональный API-токен); любая роль,
включая
`VIEWER`, может подключиться. Поток доставляет журнал команд доски ровно один
раз и по порядку или велит клиенту пересинхронизироваться; пропуски не игнорируются:

- **Получение пропущенных команд.** Соединение воспроизводит дельту журнала команд из `?since=`
  (последний применённый `seq` клиента). Живые кадры, пришедшие тем временем,
  буферизуются, затем сливаются с дедупликацией по `seq`.
- **Resync.** Когда разрыв нельзя воспроизвести точно (больше 5000 команд или
  `since` срезан из журнала), поток вместо частичной истории присылает
  `{ "type": "resync" }` и продолжает с текущей версии доски. Клиент должен
  заново прочитать доску через `GET /boards/:id`.
- **Пропуски.** Если живой кадр показывает, что предыдущий потерялся или
  пришёл не по порядку (например, между узлами), поток дочитывает
  недостающие команды из журнала, а не доставляет их вразнобой.

Комментарий keep-alive `ping` отправляется каждые 25 секунд. На том же тике
сервер перепроверяет вызывающего и закрывает поток, когда доступа больше нет:
членство удалено или больше не принято, доступ `VIEWER` истёк, аккаунт
заблокирован, доска удалена или поток открыт персональным API-токеном,
который с тех пор отозван или истёк.

`?client=` — это необязательный id вкладки, соответствующий
`^[A-Za-z0-9_-]{8,64}$`. Когда он пропущен или неверен, сервер генерирует
свой.

Поток передаёт шесть типов событий:

| `type`       | Нагрузка                                                       | Примечания                                           |
| ------------ | -------------------------------------------------------------- | ---------------------------------------------------- |
| `command`    | `seq`, `action`, `actorId`, `actorType?`, `commandId`, `touches`, `apiTokenId?`, `agentSessionId?`, `runId?`, `agentName?` | зафиксированная команда                              |
| `presence`   | `users[]`                                                      | кто подключён; без `seq`                             |
| `membership` | `boardId`, `userId`, `change`                                  | `change` — это `accepted`, `updated` или `removed`     |
| `activity`   | `id`, `boardId`, `cardId?`, `actorId`, `actorType?`, `at`, `kind`, `detail?`, `apiTokenId?`, `agentSessionId?`, `runId?`, `agentName?` | активность вне редьюсера, например новый комментарий |
| `agent`      | `op` (`started`, `paused`, `resumed`, `ended`), `sessionId?`, `scope?`, `at` | переход управления сессией агента |
| `resync`     | нет                                                            | разрыв не воспроизвести; перечитайте доску           |

`commandId` — это ключ идемпотентности, с которым команда была отправлена,
поэтому клиент узнаёт собственное эхо по ключу, даже когда один аккаунт
отправляет команды из нескольких вкладок или от имени нескольких агентов.

`actorType` — это `"human"` для сессии браузера и `"agent"` для персонального
API-токена; в кадрах до появления поля он отсутствует, поэтому пустое значение
считайте `"human"`. История карточки помечает записи агента значком «Агент».

Если с доски удалён участник, открывший поток, сервер отправляет кадр
`membership` последним и закрывает поток.

`POST /boards/:id/presence` подтверждает активность соединения. У SSE-потока нет обратного канала,
поэтому вкладка подтверждает активность этим ping каждые 25 секунд; если
подтверждения не поступают, сессия удаляется из списка присутствующих через 60
секунд. Тело содержит `clientId`,
с которым был открыт поток. Ping обновляет только сессию, которой владеет
вызывающий. Ответ — это `204` с пустым телом.

## Каталог DTO

Обязательность полей и допустимость `null` указываются отдельно:

- `required`: ключ должен присутствовать.
- `optional`: ключ можно опустить.
- `nullable`: ключ принимает явный JSON `null`.

### CreateBoardDto

| Поле    | Тип    | Обязательно | Ограничения                     |
| ------- | ------ | ----------- | ------------------------------- |
| `title` | string | да          | непустой, не более 100 символов |

```json
{ "title": "Roadmap" }
```

### InviteMemberDto

| Поле        | Тип             | Обязательно   | Ограничения                                                                  |
| ----------- | --------------- | ------------- | ---------------------------------------------------------------------------- |
| `email`     | string          | да            | валидный email; обрезается и приводится к нижнему регистру                   |
| `role`      | string          | да            | одно из `ADMIN`, `MEMBER`, `VIEWER`                                          |
| `expiresAt` | string или null | нет, nullable | ISO-8601; учитывается только для `VIEWER`; пропуск означает отсутствие срока |

```json
{
  "email": "dev@example.com",
  "role": "VIEWER",
  "expiresAt": "2026-12-31T00:00:00.000Z"
}
```

### UpdateMemberDto

| Поле        | Тип             | Обязательно   | Ограничения                                                                |
| ----------- | --------------- | ------------- | -------------------------------------------------------------------------- |
| `role`      | string          | нет           | одно из `ADMIN`, `MEMBER`, `VIEWER`                                        |
| `expiresAt` | string или null | нет, nullable | ISO-8601; `null` очищает срок `VIEWER`; пропуск сохраняет текущее значение |

```json
{ "role": "MEMBER" }
```

### CreateCommentDto

| Поле        | Тип    | Обязательно | Ограничения                                                    |

| `text`      | string | да          | непустой, не более 10000 символов                              |
| `kind`      | string | нет         | один из `note`, `status`, `question`, `blocker`, `evidence`, `handoff` (по умолчанию `note`) |


### CreateShareDto

| `includeAttachments` | boolean         | нет           | по умолчанию `false`                                               |

### Типы ответов

Для тел ответов используются общие типы данных. Ключевые поля:

- `BoardSummary`: `id`, `title`, `archivedAt?`, `counters` (`{ cards, columns }`), `role`.
- `BoardAggregate`: фронтендовый `Board` (`id`, `title`, `columns[]`, карта
  `cards`, `labels[]`, `createdAt`, `updatedAt`, `archivedAt?`).
- `BoardMemberDto`: `userId`, `displayName`, `email`, `role`, `expiresAt`,
  `avatarColor`, `avatarPath`. Ответ на приглашение замаскирован (`userId: ""`,
  поля профиля `null`).
- `CommentDto`: `id`, `cardId`, `authorId`, `text`, `createdAt`. `CommentPage`: `{ items, nextCursor }`.
- `AttachmentDto`: `id`, `cardId`, `fileName`, `mimeType`, `sizeBytes`,
  `uploadedById`, `createdAt`, `transcodeStatus`, `hasThumbnail`, `hasPoster`.
- `BoardShareDto`: `id`, `token`, `boardId`, `boardTitle`, `mode`, `title`,
  `includeComments`, `includeAttachments`, `expiresAt`, `revokedAt`, `views`,
  `lastViewedAt`, `createdAt`, `createdBy`.
- `PublicBoardDto`: `mode`, `title`, `takenAt`, `board`, `seq`, `members[]`,
  `includeComments`, `includeAttachments`. Участники — это `{ id, displayName,
  avatarColor, avatarPath }` без email.
- `BoardEnvelope`: `{ app, schemaVersion, exportedAt, boards[] }`.

## Ошибки

| Статус | Когда                                                                                                                                                                      |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `400`  | валидация провалилась, пустой обязательный текст, неверный лимит или срок, неверный или пустой пакет импорта, отклонённый файл                                                  |
| `401`  | отсутствующий или неверный токен                                                                                                                                           |
| `403`  | не участник; роль, не разрешённая маршрутом; истёкший `VIEWER`; share, не принадлежащий доске; удаление комментария не автором                                             |
| `403`  | `code: "pat_forbidden"`: персональный API-токен на маршруте только для сессии                                                                                              |
| `404`  | неизвестная или мягко удалённая доска, карточка, комментарий, вложение или share; отключённый, отозванный или истёкший публичный share; отсутствующая миниатюра или постер |
| `405`  | попытка записи через публичный API ссылок                                                                                                                                     |
| `409`  | приглашение уже принятого участника; понижение или удаление последнего `ADMIN`; истёкшее приглашение; `commandId`, повторённый на другой карточке                          |
| `410`  | live-share, чья доска больше не существует                                                                                                                                 |
| `413`  | нагрузка команды сверх `MAX_COMMAND_BYTES`; импорт больше 25 МБ; тело команды/плана больше 10 МБ; любое другое JSON-тело больше 256 КБ (`code: "payload_too_large"`)                                    |
| `416`  | невыполнимый `Range` на блобе                                                                                                                                              |
| `429`  | ограничение частоты превышено; `code: "login_backoff"` во время задержки входа                                                                                             |
| `503`  | режим обслуживания; неуспешная проверка готовности; `code: "board_write_timeout"`, когда запись в доску превысила время ожидания (повтор безопасен)                         |
