## Доски и участники

Доска создаётся и удаляется через REST; изменения членства это REST по
замыслу (они не являются действиями редьюсера). Содержимое живёт в журнале
команд.

| Метод    | Путь                          | Аутентификация / роль | Запрос            | Ответ              |
| -------- | ----------------------------- | --------------------- | ----------------- | ------------------ |
| `GET`    | `/boards`                     | пользователь          | нет               | `BoardSummary[]`   |
| `POST`   | `/boards`                     | пользователь          | `CreateBoardDto`  | `BoardAggregate`   |
| `POST`   | `/boards/import`              | пользователь          | `BoardEnvelope`   | `BoardAggregate[]` |
| `GET`    | `/boards/:id`                 | участник              | нет               | `BoardAggregate`   |
| `DELETE` | `/boards/:id`                 | `ADMIN`               | нет               | `{ status: "ok" }` |
| `GET`    | `/boards/:id/members`         | участник              | нет               | `BoardMemberDto[]` |
| `POST`   | `/boards/:id/members`         | `ADMIN`               | `InviteMemberDto` | `BoardMemberDto`   |
| `PATCH`  | `/boards/:id/members/:userId` | `ADMIN`               | `UpdateMemberDto` | `BoardMemberDto`   |
| `DELETE` | `/boards/:id/members/:userId` | `ADMIN`               | нет               | `{ status: "ok" }` |
| `GET`    | `/boards/:id/export`          | участник              | нет               | `BoardEnvelope`    |
| `GET`    | `/boards/:id/search`          | участник              | query `q`         | `{ cardIds: string[] }` |

`GET /boards` перечисляет доски, где вызывающий является принятым участником,
сначала новые, каждая со счётчиком карточек и колонок и ролью вызывающего.
Ожидающее приглашение не считается.

`POST /boards` создаёт доску, где вызывающий первый `ADMIN`. Пустой заголовок
отвечает `400`.

`POST /boards/import` принимает envelope экспорта, либо как разобранный
JSON-объект, либо как сырую JSON-строку. Он нормализует мягко и создаёт каждую
доску из envelope, где импортирующий становится `ADMIN`. Пустой или неверный
envelope отвечает `400`. Envelope выглядит так:

```json
{ "app": "janosik", "schemaVersion": 1, "exportedAt": 0, "boards": [] }
```

`GET /boards/:id` возвращает агрегат доски и устанавливает заголовок ответа
`X-Board-Seq`, несущий `seq` команды, который отражает агрегат. Клиент
возобновляет SSE-поток с этого значения. Неизвестная или мягко удалённая
доска отвечает `404`.

`GET /boards/:id/search?q=` возвращает `{ cardIds }` — карточки, у которых
заголовок, описание, пункт чек-листа или комментарий содержит `q`
(подстрока без учёта регистра). Эндпоинт достаёт текст комментариев, которых
нет в агрегате доски. Запрос длиннее 200 символов отвечает `400`.

`DELETE /boards/:id` мягко удаляет доску и каскадирует флаг на её потомков.
Членства удаляются жёстко; живые shares отзываются; snapshot-shares выживают.

`POST /boards/:id/members` приглашает пользователя по email. Адрес
обрезается и приводится к нижнему регистру. Ответ никогда не раскрывает, есть
ли у адреса аккаунт: известный адрес, неизвестный и повторное приглашение
того, чьё приглашение ещё ожидает, одинаково отвечают `201` с замаскированным
`BoardMemberDto`. В нём `userId` равен `""`, а `displayName`, `avatarColor` и
`avatarPath` равны `null`; `email`, `role` и `expiresAt` повторяют запрос. Для
известного адреса строка создаётся как ожидающее приглашение и не даёт
доступа до принятия. Для неизвестного адреса ничего не сохраняется, поэтому
пригласите человека снова, когда у него появится аккаунт. `expiresAt`
учитывается только для `VIEWER`. Только адрес, уже являющийся принятым
участником, отвечает `409`.

Приглашённый, чей аккаунт ещё не подтвердил email, не видит приглашение и не
может его принять, пока адрес не подтверждён (см.
[Приглашения](../#приглашения)).

`PATCH /boards/:id/members/:userId` меняет роль и/или срок `VIEWER`.
Последнего `ADMIN` доски нельзя понизить, и последнего `ADMIN` нельзя
удалить: оба случая отвечают `409`.

### Порядок доступа

Маршруты уровня доски отвечают в таком порядке: отсутствующий или неверный
токен это `401`; неизвестная или мягко удалённая доска это `404`; отсутствие
членства это `403`; истёкшее членство `VIEWER` это `403`, а устаревшая строка
удаляется; роль, не разрешённая маршрутом, это `403`.

Каждый маршрут этой страницы принимает персональный API-токен наравне с
access-токеном. Только для сессии работают лишь маршруты учётных данных
аккаунта (см. [справочник API](../#маршруты-только-для-сессии)).

## Комментарии

Комментарии это простой текст и обычный REST. `CardAccessGuard` определяет
владеющую доску по карточке или комментарию и проверяет членство.

| Метод    | Путь                      | Аутентификация / роль | Запрос             | Ответ              |
| -------- | ------------------------- | --------------------- | ------------------ | ------------------ |
| `POST`   | `/cards/:cardId/comments` | `ADMIN` / `MEMBER`    | `CreateCommentDto` | `CommentDto`       |
| `GET`    | `/cards/:cardId/comments` | участник              | query `cursor`, `limit`, `kind` | `CommentPage`      |
| `DELETE` | `/comments/:commentId`    | `ADMIN` / `MEMBER`    | нет                | `{ status: "ok" }` |

`POST` не принимает параметров запроса; тело это `CreateCommentDto`. Пустой
текст отвечает `400`, неизвестный `kind` — тоже `400`. Когда передан
`commandId`, повтор с тем же значением возвращает первый комментарий вместо
добавления дубликата. `commandId`, уже использованный на другой карточке,
отвечает `409`.

`GET` принимает `?cursor=` (непрозрачный), `?limit=` и `?kind=` (один вид
комментария). Лимит по умолчанию 50, максимум 100; лимит вне `1` до `100`
отвечает `400`, неизвестный `kind` — тоже `400`. Страницы идут сначала новые,
и `nextCursor` равен `null` в конце.

`DELETE` удаляет комментарий. Только автор может удалить свой комментарий;
другой автор отвечает `403`.

Каждая запись создаёт строку `Activity` и публикует кадр SSE `activity`.

## Вложения

Файлы загружаются через REST как `multipart/form-data` с единственной частью
`file`. `CardAccessGuard` определяет владеющую доску по карточке или вложению.

| Метод    | Путь                                   | Аутентификация / роль | Ответ              |
| -------- | -------------------------------------- | --------------------- | ------------------ |
| `POST`   | `/cards/:cardId/attachments`           | `ADMIN` / `MEMBER`    | `AttachmentDto`    |
| `GET`    | `/cards/:cardId/attachments`           | участник              | `AttachmentDto[]`  |
| `GET`    | `/attachments/:attachmentId/content`   | участник              | байты блоба        |
| `GET`    | `/attachments/:attachmentId/thumbnail` | участник              | байты изображения  |
| `GET`    | `/attachments/:attachmentId/poster`    | участник              | байты изображения  |
| `DELETE` | `/attachments/:attachmentId`           | `ADMIN` / `MEMBER`    | `{ status: "ok" }` |

`POST` принимает `?inline=1` (или `?inline=true`), чтобы пометить блоб как
медиа, встроенное в тело: скрыто из списка, без счётчика и без активности.
Файл не более `LIMITS.attachmentSize` (25 МБ). Сервер применяет allowlist
MIME-типов и сниффит магические байты для типов изображений, видео, аудио и
архивов; клиент, объявивший один из этих типов, но загрузивший
нераспознаваемые байты, отвечает `400`. Карточка при
`LIMITS.attachmentsPerCard` (20) живых вложений отвечает `400`.

`GET /attachments/:attachmentId/content` отдаёт блоб с
`Content-Disposition: attachment`. Ответ поддерживает диапазоны: заголовок
`Range` даёт `206` с `Content-Range`, а невыполнимый диапазон даёт `416`.

`GET .../thumbnail` отдаёт сгенерированный превью (`image/jpeg`), когда он
готов, иначе исходный блоб для изображений. У видео нет миниатюры, а
не-изображение без сгенерированной миниатюры отвечает `404`.

`GET .../poster` отдаёт первый значимый кадр видео (`image/jpeg`). Когда он
не сгенерирован, отвечает `404`.

## Sharing (эндпоинты владельца)

Share это собственная сущность (токен, режим, флаги приватности, TTL,
отзыв). Управление владельца вложено в доску и доступно только `ADMIN`.

| Метод    | Путь                                  | Аутентификация / роль | Запрос           | Ответ             |
| -------- | ------------------------------------- | --------------------- | ---------------- | ----------------- |
| `GET`    | `/boards/:id/shares`                  | `ADMIN`               | нет              | `BoardShareDto[]` |
| `POST`   | `/boards/:id/shares`                  | `ADMIN`               | `CreateShareDto` | `BoardShareDto`   |
| `POST`   | `/boards/:id/shares/:shareId/refresh` | `ADMIN`               | нет              | `BoardShareDto`   |
| `PATCH`  | `/boards/:id/shares/:shareId`         | `ADMIN`               | `UpdateShareDto` | `BoardShareDto`   |
| `DELETE` | `/boards/:id/shares/:shareId`         | `ADMIN`               | нет              | `BoardShareDto`   |

Режим share это `snapshot` или `live`. Snapshot замораживает доску при
создании и выживает при удалении доски; обновить его может только владелец.
Live-share читает доску как она есть сейчас и следует за ней по SSE.

`POST` генерирует случайный токен (16 байт, base64url). `includeComments` по
умолчанию `true` для live-share и `false` для snapshot; `includeAttachments`
по умолчанию `false`. `expiresAt` в прошлом отвечает `400`.

`POST .../refresh` замораживает snapshot-share заново. Live-share отвечает
`400`.

`DELETE` отзывает share: его токен перестаёт разрешаться сразу. Отзыв
идемпотентен.

`:shareId`, не принадлежащий доске, отвечает `403`; неизвестный отвечает
`404`.

## Публичные эндпоинты share

Публичный контур только для чтения и вне пользовательского JWT. Каждый
маршрут за `ShareAccessGuard`, который разрешает `:token` в живой, не
отозванный и не истёкший share, и за мастер-переключателем
`ALLOW_PUBLIC_SHARES`. Отсутствующий, отозванный, истёкший или отключённый
share отвечают одинаково `404`. Ответы на чтение несут
`X-Robots-Tag: noindex, nofollow`.

У контура есть ограничение частоты на токен: 240 запросов в минуту на токен
(`SHARE_RATE_LIMIT`), и 60 в минуту для OG-превью (`SHARE_OG_RATE_LIMIT`).
Превышение отвечает `429`.

| Метод  | Путь                                              | Ответ             |
| ------ | ------------------------------------------------- | ----------------- |
| `GET`  | `/share/:token`                                   | `PublicBoardDto`  |
| `GET`  | `/share/:token/events`                            | поток SSE         |
| `GET`  | `/share/:token/og.png`                            | `image/png`       |
| `GET`  | `/share/:token/cards/:cardId/comments`            | `CommentPage`     |
| `GET`  | `/share/:token/cards/:cardId/attachments`         | `AttachmentDto[]` |
| `GET`  | `/share/:token/attachments/:attachmentId/content` | байты блоба       |
| `POST` | `/share/:token`                                   | `405`             |
| `POST` | `/share/:token/{*rest}`                           | `405`             |

`GET /share/:token` возвращает всю публичную нагрузку: доску (живой агрегат
или замороженный snapshot), очищенный состав участников без email и флаги
приватности share. Он считает один просмотр. Live-share, чья доска исчезла,
отвечает `410`; snapshot никогда не зависит от доски.

`GET /share/:token/events` работает только в режиме live; snapshot отвечает
`404`. Он стримит кадры `command` и, когда задан `includeComments`, кадры
`activity`. Кадры presence и membership отбрасываются, поэтому публичный
зритель не видит личностей. Догон дельты `?since=` повторяет поток участника,
включая кадр `resync`. Живая доска, которая исчезла, отвечает `410`. Открытый
поток перепроверяет share на каждом тике keep-alive и закрывается, как только
share отозван или истёк, публичные ссылки выключены или доски больше нет.

`GET /share/:token/og.png` возвращает детерминированный PNG-превью доски.

`GET .../comments` и `GET .../attachments` отвечают `404`, когда share не
раскрывает соответственно комментарии или вложения. Карточка, которой нет на
общей доске, отвечает `404`.

Snapshot замораживает и обсуждение: его комментарии, список вложений и
содержимое вложений включают только то, что создано до момента снимка (или
последнего обновления). Более позднее вложение отвечает `404`.

`POST /share/:token` и любой вложенный `POST` отвечают `405` с
`"Shared boards are read-only"`. Публичный контур заявляет своё правило
только-для-чтения, а не полагается на отсутствие маршрута.

## Realtime

| Метод  | Путь                   | Аутентификация / роль | Запрос                  | Ответ        |
| ------ | ---------------------- | --------------------- | ----------------------- | ------------ |
| `GET`  | `/boards/:id/events`   | участник              | query `since`, `client` | поток SSE    |
| `POST` | `/boards/:id/presence` | участник              | `PresencePingDto`       | `204`, пусто |

`GET /boards/:id/events` это поток server-sent events. Аутентификация это
Bearer-токен (access-токен или персональный API-токен); любая роль, включая
`VIEWER`, может подключиться. Поток доставляет журнал команд доски ровно один
раз и по порядку или велит клиенту пересинхронизироваться; молчаливых дыр не
бывает:

- **Догон.** Соединение воспроизводит дельту журнала команд из `?since=`
  (последний применённый `seq` клиента). Живые кадры, пришедшие тем временем,
  буферизуются, затем сливаются с дедупликацией по `seq`.
- **Resync.** Когда разрыв нельзя воспроизвести точно (больше 5000 команд или
  `since` срезан из журнала), поток вместо частичной истории присылает
  `{ "type": "resync" }` и продолжает с текущей головы доски. Клиент должен
  заново прочитать доску через `GET /boards/:id`.
- **Пропуски.** Если живой кадр показывает, что предыдущий потерялся или
  пришёл не по порядку (например, между узлами), поток дочитывает
  недостающие команды из журнала, а не доставляет их вразнобой.

Комментарий keep-alive `ping` отправляется каждые 25 секунд. На том же тике
сервер перепроверяет вызывающего и закрывает поток, когда доступа больше нет:
членство удалено или больше не принято, доступ `VIEWER` истёк, аккаунт
заблокирован, доска удалена или поток открыт персональным API-токеном,
который с тех пор отозван или истёк.

`?client=` это необязательный id вкладки, соответствующий
`^[A-Za-z0-9_-]{8,64}$`. Когда он пропущен или неверен, сервер генерирует
свой.

Поток несёт пять типов событий:

| `type`       | Нагрузка                                                       | Примечания                                           |
| ------------ | -------------------------------------------------------------- | ---------------------------------------------------- |
| `command`    | `seq`, `action`, `actorId`, `actorType?`, `commandId`, `touches` | зафиксированная команда                              |
| `presence`   | `users[]`                                                      | кто подключён; без `seq`                             |
| `membership` | `boardId`, `userId`, `change`                                  | `change` это `accepted`, `updated` или `removed`     |
| `activity`   | `id`, `boardId`, `cardId?`, `actorId`, `actorType?`, `at`, `kind`, `detail?` | активность вне редьюсера, например новый комментарий |
| `resync`     | нет                                                            | разрыв не воспроизвести; перечитайте доску           |

`commandId` это ключ идемпотентности, с которым команда была отправлена,
поэтому клиент узнаёт собственное эхо по ключу, даже когда один аккаунт
держит несколько писателей.

`actorType` это `"human"` для сессии браузера и `"agent"` для персонального
API-токена; в кадрах до появления поля он отсутствует, поэтому пустое значение
считайте `"human"`. История карточки помечает записи агента значком «Агент».

Когда удалённый пользователь это вызывающий, сервер отправляет кадр
`membership` последним и закрывает поток.

`POST /boards/:id/presence` это heartbeat. У SSE-потока нет обратного канала,
поэтому вкладка подтверждает живость этим ping каждые 25 секунд; сессия,
переставшая пинговать, вычищается через 60 секунд. Тело несёт `clientId`,
с которым был открыт поток. Ping обновляет только сессию, которой владеет
вызывающий. Ответ это `204` с пустым телом.

## Каталог DTO

Тройное состояние обязательности, используемое ниже:

- `required`: ключ должен присутствовать.
- `optional`: ключ можно опустить.
- `nullable`: ключ принимает явный JSON `null`.

### CreateBoardDto

| Поле    | Тип    | Обязательно | Ограничения                     |
| ------- | ------ | ----------- | ------------------------------- |
| `title` | string | да          | непустой, не более 100 символов |

```json
{ "title": "Roadmap" }
```

### InviteMemberDto

| Поле        | Тип             | Обязательно   | Ограничения                                                                  |
| ----------- | --------------- | ------------- | ---------------------------------------------------------------------------- |
| `email`     | string          | да            | валидный email; обрезается и приводится к нижнему регистру                   |
| `role`      | string          | да            | одно из `ADMIN`, `MEMBER`, `VIEWER`                                          |
| `expiresAt` | string или null | нет, nullable | ISO-8601; учитывается только для `VIEWER`; пропуск означает отсутствие срока |

```json
{
  "email": "dev@example.com",
  "role": "VIEWER",
  "expiresAt": "2026-12-31T00:00:00.000Z"
}
```

### UpdateMemberDto

| Поле        | Тип             | Обязательно   | Ограничения                                                                |
| ----------- | --------------- | ------------- | -------------------------------------------------------------------------- |
| `role`      | string          | нет           | одно из `ADMIN`, `MEMBER`, `VIEWER`                                        |
| `expiresAt` | string или null | нет, nullable | ISO-8601; `null` очищает срок `VIEWER`; пропуск сохраняет текущее значение |

```json
{ "role": "MEMBER" }
```

### CreateCommentDto

| Поле        | Тип    | Обязательно | Ограничения                                                    |
| ----------- | ------ | ----------- | -------------------------------------------------------------- |
| `text`      | string | да          | непустой, не более 10000 символов                              |
| `kind`      | string | нет         | один из `note`, `status`, `question`, `blocker`, `evidence`, `handoff` (по умолчанию `note`) |
| `commandId` | string | нет         | не более 64 символов, `^[A-Za-z0-9_-]+$`; ключ идемпотентности |

```json
{ "text": "Looks good", "kind": "evidence", "commandId": "c-1" }
```

### CreateShareDto

| Поле                 | Тип             | Обязательно   | Ограничения                                                        |
| -------------------- | --------------- | ------------- | ------------------------------------------------------------------ |
| `mode`               | string          | да            | `snapshot` или `live`                                              |
| `title`              | string          | нет           | не более 100 символов                                              |

### Типы ответов

Тела ответов это общие проводные типы. Ключевые поля:

- `BoardSummary`: `id`, `title`, `archivedAt?`, `counters` (`{ cards, columns }`), `role`.
- `BoardAggregate`: фронтендовый `Board` (`id`, `title`, `columns[]`, карта `cards`, `labels[]`, `createdAt`, `updatedAt`, `archivedAt?`).
- `BoardMemberDto`: `userId`, `displayName`, `email`, `role`, `expiresAt`, `avatarColor`, `avatarPath`. Ответ на приглашение замаскирован (`userId: ""`, поля профиля `null`).
- `CommentDto`: `id`, `cardId`, `authorId`, `text`, `createdAt`. `CommentPage`: `{ items, nextCursor }`.
- `AttachmentDto`: `id`, `cardId`, `fileName`, `mimeType`, `sizeBytes`, `uploadedById`, `createdAt`, `transcodeStatus`, `hasThumbnail`, `hasPoster`.
- `BoardShareDto`: `id`, `token`, `boardId`, `boardTitle`, `mode`, `title`, `includeComments`, `includeAttachments`, `expiresAt`, `revokedAt`, `views`, `lastViewedAt`, `createdAt`, `createdBy`.
- `PublicBoardDto`: `mode`, `title`, `takenAt`, `board`, `seq`, `members[]`, `includeComments`, `includeAttachments`. Участники это `{ id, displayName, avatarColor, avatarPath }` без email.
- `BoardEnvelope`: `{ app, schemaVersion, exportedAt, boards[] }`.

## Ошибки

| Статус | Когда                                                                                                                                                                      |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `400`  | валидация провалилась, пустой обязательный текст, неверный лимит или срок, неверный или пустой envelope, отклонённый файл                                                  |
| `401`  | отсутствующий или неверный токен                                                                                                                                           |
| `403`  | не участник; роль, не разрешённая маршрутом; истёкший `VIEWER`; share, не принадлежащий доске; удаление комментария не автором                                             |
| `403`  | `code: "pat_forbidden"`: персональный API-токен на маршруте только для сессии                                                                                              |
| `404`  | неизвестная или мягко удалённая доска, карточка, комментарий, вложение или share; отключённый, отозванный или истёкший публичный share; отсутствующая миниатюра или постер |
| `405`  | запись против публичного контура share                                                                                                                                     |
| `409`  | приглашение уже принятого участника; понижение или удаление последнего `ADMIN`; истёкшее приглашение; `commandId`, повторённый на другой карточке                          |
| `410`  | live-share, чья доска больше не существует                                                                                                                                 |
| `413`  | нагрузка команды сверх `MAX_COMMAND_BYTES`; JSON-тело больше 256 КБ (5 МБ для импорта и команд)                                                                            |
| `416`  | невыполнимый `Range` на блобе                                                                                                                                              |
| `429`  | ограничение частоты превышено; `code: "login_backoff"` во время задержки входа                                                                                             |
| `503`  | режим обслуживания; проваленная проверка здоровья; `code: "board_write_timeout"`, когда запись в доску превысила время ожидания (повтор безопасен)                         |
