Изменения содержимого идут через [API команд](/ru/docs/api/commands/). Эта страница
описывает всё остальное в пользовательском API: доски и членство,
комментарии, вложения, публичные ссылки и поток обновлений. Общие соглашения
(базовый путь, аутентификация, ошибки, ограничения частоты) см. в
[Справочнике по API](./).

## Заголовки записи и конкурентность

На маршрутах записи с поддержкой атрибуции PAT может передать
`X-Agent-Session: <sessionId>` для своей сессии на доске. Сервер проверяет её и записывает атрибуцию в
команду/комментарий/вложение; несовпадение — `403 agent_session_invalid`,
закрытая сессия — `403 agent_session_closed`.

Версия для проверки передаётся в JSON, а не в HTTP-заголовке `If-Match`:
`{ "ifMatch": 42 }` фиксирует `seq` доски (`X-Board-Seq` из
`GET /boards/:id`), а `ifMatchVersions: { "card:<id>": 7 }` — версии отдельных
сущностей. Устаревшее значение даёт `409 version_conflict` с актуальным
значением в `currentVersion`. `Board.version` — версия сущности для
`ifMatchVersions`, а не последовательность команд.

`Idempotency-Key` действует для перечисленных ниже REST-записей (8–128
символов из `A-Z a-z 0-9 _ -`). Записи через журнал команд используют
`commandId`, а `clientRunId` — ключ run для batch/плана. Неудачный запрос
освобождает ключ; повтор возвращает первый результат; другое тело с тем же
ключом — `409 idempotency_conflict`. Успешные команды/batch/план/откат могут
вернуть `X-Run-Id`. `X-Request-Id` совпадает с `requestId` в теле ошибки.
Заголовки лимитов агента описаны в
[Справочнике по API](../#бюджеты-агентов-и-заголовки).

Пагинация курсорная: `?cursor=` непрозрачен, `nextCursor: null` означает
конец. Комментарии и активность по умолчанию отдают 50 записей и не больше
100; approvals и runs — не больше 100. Поиск использует `?q=`. Offset-
пагинации нет.

## Доски и участники

Создание и удаление доски, а также управление участниками выполняются через
REST. Эти операции не являются действиями редьюсера. Изменения содержимого доски
проходят через журнал команд.

| Метод    | Путь                          | Аутентификация / роль | Запрос            | Ответ              |
| -------- | ----------------------------- | --------------------- | ----------------- | ------------------ |
| `GET`    | `/boards`                     | пользователь          | нет               | `BoardSummary[]`   |
| `POST`   | `/boards`                     | пользователь          | `CreateBoardDto`  | `BoardAggregate`   |
| `POST`   | `/boards/import`              | пользователь          | `BoardEnvelope`   | `BoardAggregate[]` |
| `GET`    | `/boards/:id`                 | участник              | нет               | `BoardAggregate`   |
| `DELETE` | `/boards/:id`                 | `ADMIN`               | нет               | `{ status: "ok" }` |
| `GET`    | `/boards/:id/members`         | участник              | нет               | `BoardMemberDto[]` |
| `GET` | `/boards/:id/invitations` | `ADMIN` | нет | `BoardPendingInvitationDto[]` |
| `POST`   | `/boards/:id/members`         | `ADMIN`               | `InviteMemberDto` | `BoardMemberDto`   |
| `PATCH`  | `/boards/:id/members/:userId` | `ADMIN`               | `UpdateMemberDto` | `BoardMemberDto`   |
| `DELETE` | `/boards/:id/members/me`      | участник              | нет               | `{ status: "ok" }` |
| `DELETE` | `/boards/:id/members/:userId` | `ADMIN`               | нет               | `{ status: "ok" }` |
| `GET`    | `/boards/ready`               | пользователь          | query `limit`     | `BoardsReady`      |
| `GET`    | `/boards/search`              | пользователь          | query `q`         | `{ matches: WorkspaceSearchMatch[]; total: number; truncated: boolean }` |
| `GET`    | `/boards/:id/ready`           | участник              | query `limit`, `wait`, `since` | `BoardReady` (или `204`) |
| `GET`    | `/boards/:id/export`          | участник              | нет               | `BoardEnvelope`    |
| `GET`    | `/boards/:id/deleted`         | `ADMIN`/`MEMBER`      | нет               | `DeletedBoardItemsDto` |
| `POST`   | `/boards/:id/deleted/:type/:itemId/restore` | `ADMIN`/`MEMBER` | нет | `{ status: "ok" }` |
| `GET`    | `/boards/:id/search`          | участник              | query `q`, optional `includeMatches` | `{ cardIds: string[]; matches: BoardSearchMatch[]; matchesTotal: number; matchesTruncated: boolean }` |

`GET /boards` перечисляет доски, где вызывающий является принятым участником,
сначала новые, каждая со счётчиком карточек и колонок и ролью вызывающего.
Ожидающее приглашение не считается.

`POST /boards` создаёт доску и назначает вызывающему роль `ADMIN`. Если название
пустое, сервер возвращает `400`. `template: "starter"` добавляет три колонки,
карточку-приветствие и чек-лист; `templateLocale` (`en`/`ru`) выбирает язык
текстов и требует шаблон.

У ответа `503` этого маршрута две формы. Если доска создана, но стартовый набор
не применился, а свежую доску не удалось удалить, ответ — `503
starter_cleanup_failed` с `retryable: false` и `details.boardId`: доска
существует, откройте её через `GET /boards/{details.boardId}`. Если первое
чтение агрегата не удалось, ответ тоже `503` с `retryable: false`
(`starter_read_failed` для шаблона `starter`, `board_read_failed` для любого
создания) и тем же `details.boardId`. В этих случаях повтор с тем же
`Idempotency-Key` вернёт `409 idempotency_in_progress`; не повторяйте создание
с новым ключом — это создаст вторую доску. Если запись в доску не успела по
таймауту, ответ — `503 board_write_timeout` (`retryable: true`, без
`boardId`); ничего не сохранено, повторяйте. Когда стартовый набор не
применился, но свежую доску удалось удалить, маршрут пробрасывает исходную
ошибку (например, `500`) и освобождает ключ, поэтому повтор с тем же ключом
может создать доску (`201`).

`POST /boards/import` принимает пакет экспорта, либо как разобранный
JSON-объект, либо как сырую JSON-строку; сервер валидирует уже разобранный
объект без round-trip stringify→parse. Сервер нормализует входные данные и создаёт каждую
доску из пакета, где импортирующий становится `ADMIN`. Пустой или неверный
пакет вызывает ответ `400`. `?dryRun=1` возвращает
`{boards, cards, columns, labels, withinLimit}` и ничего не пишет. Формат пакета:

```json
{ "app": "janosik", "schemaVersion": 3, "exportedAt": 0, "boards": [] }
```

Версия 3 добавляет необязательный `agentPolicy` доски; версия 2 добавила
необязательный `workflow`; файлы версий 1/2 по-прежнему импортируются (без
политики). Импорт создаёт новые id
колонок и карточек и переназначает ссылки процесса; переход, чья колонка
отсутствует, отбрасывается, а не ломает импорт.

`GET /boards/:id/export` отдаёт один `BoardEnvelope` (`schemaVersion: 3`) и
отклоняет экспорт больше `MAX_BOARD_EXPORT_BYTES` с `413`. `GET
/boards/:id/deleted` перечисляет мягко удалённые карточки, колонки, комментарии
и файлы карточки в пределах срока хранения, сначала новые; тело —
`{ retentionDays, limit, items, truncated }`, элемент — `{ type, id, title,
deletedAt, purgeAt, columnTitle?, cardId?, cardTitle?, authorName?,
sizeBytes? }`. `POST /boards/:id/deleted/:type/:itemId/restore` восстанавливает
элемент (`type`: `cards`, `columns`, `comments` или `attachments`). Карточки и
колонки возвращаются через журнал команд; комментарии и файлы
восстанавливаются на месте и публикуют Activity/SSE. Оба маршрута требуют
роль `ADMIN` или `MEMBER` доски — `VIEWER` получает `403`. Карточка, чья
колонка ещё удалена, отвечает `409 column_deleted`; элемент старше срока
хранения скрыт из списка и отвечает `410 retention_expired`.

`GET /boards/:id` возвращает агрегат доски и устанавливает заголовок ответа
`X-Board-Seq`, несущий `seq` команды, который отражает агрегат. Клиент
возобновляет SSE-поток с этого значения. Если доска неизвестна или помечена
удалённой, сервер возвращает `404`. Если у доски есть процесс, агрегат
содержит `workflow`.

### Готовая работа и long-poll

`GET /boards/:id/ready?limit=&wait=&since=` — это **сводка**, а не чтение доски:
карточки, которые агент может взять сейчас, без описаний, чек-листов, связей,
меток и комментариев. Готовая карточка находится в начальной колонке
(`workflow.initialColumnId`, иначе первая колонка), без исполнителя, не в
архиве и не удалена, без живого claim (пустой или истёкший lease свободен) и не
является целью живого `blocks`-линка. Список отсортирован по приоритету, самые
срочные первыми, и ограничен 100. У карточки есть `id`, `title`, id и названия
доски/колонки, `priority`, `claimedBy`, `leaseUntil`, `version` и
`descriptionChars` (сохранённая длина описания; считаются Unicode code points).
Сам текст не выбирается и не
возвращается, поэтому большой текст не вычитывается из БД. В ответе также есть
`seq` команд доски, продублированный в `X-Board-Seq`.

`wait` — это серверная задержка в **миллисекундах**, 0–60000 (по умолчанию 0 —
мгновенная сводка). Она просыпается только на влияющем на готовность действии
(появление карточки, перемещение, приоритет, исполнитель, claim, связь или
изменение колонки/workflow) либо на `resync` — каждая команда несёт
`board:<id>`, поэтому метки, чек-листы, комментарии и переименование доски
удержание не будят. После пробуждения эндпоинт перечитывает состояние и
отвечает `200`, когда работа есть; если изменение не дало готовой карточки, он
**продолжает удерживать** запрос до дедлайна, а не отдаёт пустой снимок.
Одновременные ожидающие, проснувшиеся на одном событии, делят одно чтение
снимка. Удержанный ответ и таймаут `204` несут `X-Ready-Held: 1`; `204` также
несёт `X-Board-Seq` и `Cache-Control: no-store` без тела.

`since` — это `seq` из предыдущего ответа: если доска изменилась до начала
удержания, сводка отвечает сразу, даже когда готовых карточек нет. Отключение
клиента прерывает удержание и освобождает подписку и слот допуска. Удалённая во
время удержания доска отвечает `404`, а не `204`. Лимиты одновременных
удержаний на процесс отвечают `503 ready_poll_capacity` с `Retry-After`. Из
p50/p95 задержки API исключается только успешный удержанный `200`/`204` с
`X-Ready-Held: 1`; мгновенные снимки и ошибки остаются. Читать эндпоинт может
любая принятая роль, включая `VIEWER`; архивная доска отвечает `200` с
`archived: true` и без карточек. Неверные границы `limit`, `wait` или `since`
дают `400`.

`GET /boards/ready?limit=` — кросс-досочная сводка: все доступные доски в виде
`{ id, title, archived, seq }` плюс не более `limit` готовых карточек (всего, не
на доску) из начальных колонок активных досок. Она строится одним чтением
досок/колонок, одним запросом карточек по колонкам и одним групповым чтением
`seq` — без запросов на каждую доску и без полных агрегатов. PAT, привязанный к
доске, видит только свою доску. Это только снимок; удержание одной доски —
через `/boards/:id/ready?wait=`.

`GET /boards/:id/search?q=` возвращает `{ cardIds, matches }` — карточки, у
которых заголовок, описание, пункт чек-листа, комментарий или имя видимого
вложения содержит `q` (подстрока без учёта регистра). `cardIds` всегда полон
и остаётся компактной проекцией для MCP; `matches` добавляет `matchIn`,
короткий фрагмент для описания/чек-листа/комментария/вложения и `commentId` /
`attachmentId` для глубоких ссылок. Список совпадений дедуплицируется по
карточке/типу и ограничен 200; `matchesTotal` и `matchesTruncated` сообщают,
что пояснение неполно, при этом `cardIds` остаётся полным.
`includeMatches=0` (или `false`) сохраняет полный `cardIds`, но возвращает
`matches: []` и нулевые счётчики — так его запрашивает фильтр доски.
Эндпоинт достаёт текст, которого нет в агрегате доски; скрытые
inline-вложения и `descriptionDetached` исключены, потому что их нельзя
показать в списке вложений карточки. При длине поисковой строки больше 200
символов или повторённом `q` (`?q=a&q=b`) сервер возвращает `400`.

`GET /boards/search?q=` — кросс-досочный спутник палитры. Ищет по тексту
комментариев и именам видимых файлов на всех досках, где у вызывающего есть
принятое, неистёкшее членство, дедуплицирует по доске/карточке/типу, сливает
комментарии и файлы от новых к старым и возвращает не больше 200 `matches` с
названиями доски и карточки. `total` — полное число различных совпадений,
`truncated` показывает, был ли список обрезан. Заголовки, описания и
чек-листы не ищутся (их клиент сопоставляет локально). PAT, ограниченный
доской, видит только свою доску; повторённый `q` даёт `400`.

`DELETE /boards/:id` помечает доску и её дочерние записи удалёнными.
Ссылки `Live` отзываются. Записи об участниках сохраняются до полной очистки
для возможного восстановления доски. Ссылки на снимки продолжают отдавать
сохранённое содержимое после удаления и очистки доски. При полной очистке
удаляются также агентские сессии и согласования доски.

`POST /boards/:id/members` приглашает пользователя по email. Адрес
обрезается и приводится к нижнему регистру. Ответ никогда не раскрывает, есть
ли у адреса аккаунт: известный адрес, неизвестный и повторное приглашение
того, чьё приглашение ещё ожидает, одинаково отвечают `201` с замаскированным
`BoardMemberDto`. В нём `userId` равен `""`, а `displayName`, `avatarColor` и
`avatarPath` равны `null`; `email`, `role` и `expiresAt` повторяют запрос. Для
известного адреса строка создаётся как ожидающее приглашение и не даёт
доступа до принятия. Для неизвестного адреса ничего не сохраняется, поэтому
пригласите человека снова, когда у него появится аккаунт. `expiresAt`
учитывается только для `VIEWER`. Если пользователь с этим адресом уже принял
приглашение на доску, сервер возвращает `409`.

Приглашённый, чей аккаунт ещё не подтвердил email, не видит приглашение и не
может его принять, пока адрес не подтверждён (см.
[Приглашения](../#приглашения)).

`GET /boards/:id/members` по умолчанию возвращает только **активных**
принятых участников; истёкший `VIEWER` скрыт, чтобы списки назначения и
фильтры не предлагали участника, которого сервер откажется назначить. `ADMIN`
доски может добавить `?includeExpired=1`, чтобы увидеть истёкшие строки
`VIEWER` в диалоге управления; остальным ролям этот запрос отвечает `403`.
Ожидающие приглашения здесь не появляются.

`GET /boards/:id/invitations` возвращает ожидающие приглашения на доску.

`PATCH /boards/:id/members/:userId` меняет роль и/или срок `VIEWER`.
Последнего `ADMIN` доски нельзя понизить, и последнего `ADMIN` нельзя
удалить: в обоих случаях сервер возвращает `409`.

`DELETE /boards/:id/members/me` позволяет вызывающему покинуть доску. Любой
принятый `MEMBER` или `VIEWER` может это сделать; `ADMIN` — только пока на
доске остаётся другой активный `ADMIN` (ожидающие и истёкшие строки не
считаются). Последнему `ADMIN` сервер отвечает
`409 { code: "last_admin", action: "leave" }`. Маршрут доступен только
браузерной сессии (PAT получает `403 pat_forbidden`) и идемпотентен: повтор
после успешного выхода или потерянного ответа отвечает `200`; только
отсутствующая/мягко удалённая доска — `404`. Созданные карточки и комментарии
остаются на доске с прежним `actorId`; лента и DTO комментариев дополнительно
отдают `actorName`/`actorEmail` и `authorName`/`authorEmail`, поэтому
покинувший участник остаётся подписанным после исчезновения из ростера. Уход
пишется в Activity как `member_left`, а SSE-кадр `membership: left` закрывает
поток покинувшего; удаление админом по-прежнему шлёт `membership: removed`.
После этого доски нет в `GET /boards`, а прямой URL доски отвечает `403`.

### Порядок доступа

Маршруты уровня доски отвечают в таком порядке: отсутствующий или неверный
токен — это `401`; неизвестная или мягко удалённая доска — это `404`; отсутствие
членства — это `403`; истёкшее членство `VIEWER` — это `403`, а устаревшая строка
удаляется; роль, не разрешённая маршрутом, это `403`.

На маршрутах доски, принимающих PAT, действуют ограничения членства, роли и
области токена. Для маршрутов ниже нужен access JWT браузерной сессии.
Если запрос с PAT доходит до проверки сессии, сервер возвращает
`403 pat_forbidden`.

| Маршрут для сессии браузера | Доступ PAT к связанным маршрутам |
| --- | --- |
| `GET /agents/overview` | Сессии, запросы на подтверждение и прогоны можно читать в рамках доски по правилам видимости каждого маршрута. |
| `GET` / `PATCH /boards/:id/agent-policy` | Участники могут читать доску в пределах области токена. |
| `POST /boards/:id/approvals/:approvalId/decision` | PAT может создать, прочитать или отменить собственный запрос. |
| Применение отката через `POST /boards/:id/runs/:runId/revert` | PAT может вызвать `/revert/preview` или передать `{ "dryRun": true }`. |
| Пауза и возобновление на уровне доски, сессии агента, токена или всех агентов | PAT может начать, обновить и завершить свою сессию агента. |
| Управление персональными API-токенами | `GET /auth/me` возвращает сведения о токене вызывающего. |

Точные маршруты паузы и аккаунта указаны в
[справочнике API](../#маршруты-только-для-сессии). Для приглашений аккаунта
нужна сессия браузера. ADMIN доски может просматривать и отправлять приглашения
доски с PAT с пресетом `admin`.

## Комментарии

Комментарии хранятся как строки Markdown и обрабатываются через REST. `CardAccessGuard` определяет
доску, к которой относится запись по карточке или комментарию и проверяет членство.

| Метод    | Путь                      | Аутентификация / роль | Запрос             | Ответ              |
| -------- | ------------------------- | --------------------- | ------------------ | ------------------ |
| `POST`   | `/cards/:cardId/comments` | `ADMIN` / `MEMBER`    | `CreateCommentDto` | `CommentDto`       |
| `GET`    | `/cards/:cardId/comments` | участник              | query `cursor`, `limit`, `kind` | `CommentPage`      |
| `GET`    | `/comments/:commentId/revisions` | `ADMIN` / `MEMBER` / действующий `VIEWER` | query `cursor`, `limit` | `CommentRevisionPage` |
| `PATCH`  | `/comments/:commentId`    | `ADMIN` / `MEMBER`    | `UpdateCommentDto` | `CommentDto`       |
| `DELETE` | `/comments/:commentId`    | `ADMIN` / `MEMBER`    | нет                | `{ status: "ok" }` |

`POST` не принимает параметров запроса; тело — это `CreateCommentDto`. Если
текст пуст или `kind` неизвестен, сервер возвращает `400`. Когда передан
`commandId`, повтор с тем же значением возвращает первый комментарий вместо
добавления дубликата. Если `commandId` уже использован на другой карточке, сервер возвращает `409`.

Упоминания — это явные ссылки Markdown на зарезервированный адрес
`https://janosik.invalid/mention/<userId>`, например
`[@Анна](https://janosik.invalid/mention/clx…)`. Сервер разрешает каждую
ссылку при записи, отклоняет id вне активного состава доски с
`400 mention_not_member` и возвращает найденные id в
`CommentDto.mentionedUserIds` (в порядке первого упоминания, без повторов).
Упоминания внутри верхнеуровневых блоков кода, блоков кода в цитате и строк
кода инертны. Блок кода внутри элемента списка считается обычным текстом;
редактор создаёт только верхнеуровневые блоки. Экранированные токены и части
больших URL инертны, а HTML-комментарии не отображаются. Закрывающий блок
подчиняется тому же правилу отступа 0–3 пробела, что и открывающий; строка
блока с отступом в четыре пробела считается содержимым и не входит в
поддерживаемую область. Текст с отступом — обычный текст: явная ссылка
`[@Анна](https://janosik.invalid/mention/clx…)` в нём остаётся живой и
отправляет уведомление, а набранное вручную `@Анна` — никогда.

`GET` принимает `?cursor=` (непрозрачный), `?limit=` и `?kind=` (один вид
комментария). Лимит по умолчанию 50, максимум 100; при лимите вне диапазона от
`1` до `100` или неизвестном `kind` сервер возвращает `400`. Страницы идут
сначала новые,
и `nextCursor` равен `null` в конце.

`DELETE` удаляет комментарий. Только автор может удалить свой комментарий;
при попытке удалить чужой комментарий сервер возвращает `403`.

`PATCH` редактирует собственный комментарий. Тело — `{ "text": "...", "kind": "blocker" }`;
оба поля необязательны, но хотя бы одно должно присутствовать, иначе сервер
возвращает `400` (текст по-прежнему непустой и не длиннее 10 000 символов).
Пропущенное поле сохраняет прежнее значение. Редактировать может только автор;
при попытке изменить чужой комментарий сервер возвращает `403`, удалённый
комментарий — `404`. `authorId`, атрибуция и `createdAt` не меняются.
Фактическая правка текста проставляет `editedAt` (Unix ms в `CommentDto`) и
добавляет ревизию; смена только `kind` не делает ни того, ни другого.
Встроенные в текст медиафайлы, убранные при редактировании, мягко удаляются.
Редактирование пишет строку активности `comment_updated` и SSE-кадр; смена
типа на `blocker`/`handoff` не повторяет уведомление, уже отправленное
исходным комментарием.

`GET /comments/:commentId/revisions` возвращает неизменяемую историю правок
текста, сначала новые (`revisionNumber` по убыванию). Читать её могут
`ADMIN`, `MEMBER` и действующий `VIEWER` с JWT или PAT с правом чтения доски;
неучастник или просроченное членство получают `403`, отсутствующий или
удалённый комментарий, карточка, колонка или доска — `404`. `?limit=` по
умолчанию 20, максимум 100. `?cursor=` непрозрачен и привязан к комментарию:
некорректный или чужой cursor даёт `400` после проверки доступа и продолжает
работать даже после обрезки строки, на которую указывал. На каждой странице,
включая пустую, есть `historyIncomplete` и `historyIncompleteReason`
(`legacy_cutover`, `revision_limit`, `gdpr_erase`, `writer_gap` или `null` для
полной истории). Если сохранённый текст расходится с проверенной парой
writer'а, маршрут сразу возвращает пустую страницу с `writer_gap`, ещё до
того, как сверочный sweep сохранит причину. `CommentRevisionDto` содержит
`id`, `revisionNumber`, `createdAt`, `editorId`, `editorName`, `actorType`,
`agentName`, `cause`, `beforeText` и `afterText`; `editorName` — текущее
публичное имя редактора, `null` если редактор или имя недоступны.
Идентификаторы токена и сессии не выдаются. Master читает ту же проекцию по
`GET /admin/comments/:commentId/revisions` с админским JWT и без членства в
доске; оба маршрута только для чтения. Writer хранит 50 последних ревизий на
комментарий: более старые строки и их копии Activity удаляются, а комментарий
получает `revision_limit`. Расхождение с проверенной парой writer'а даёт
`writer_gap`; служебная очистка `sweep-comment-history` принимает текущий
текст как новую проверенную точку и убирает неподтверждённые снимки Activity.
Наблюдаемость показывает число ревизий и Activity, размер их текста, обрезки,
неполные истории и превышения бюджета, но не сам текст. Публичные проекции
комментариев и замороженные snapshot share не содержат ревизий, их ID, текстов
до/после, счётчиков, флагов и причин неполной истории, cutover и проверенных
полей, а токен share не открывает маршруты ревизий.

Каждая запись создаёт строку `Activity` и публикует кадр SSE `activity`.

## Сессии агентов и атрибуция

Персональный API-токен может открыть сессию агента на доске. Сессия — это
контекст атрибуции, а не второй аккаунт: она не даёт прав сверх токена.

| Метод  | Путь                                                  | Аутентификация / роль      | Запрос                     | Ответ               |
| ------ | ----------------------------------------------------- | -------------------------- | -------------------------- | ------------------- |
| `POST` | `/boards/:id/agent-sessions`                          | PAT, участник доски        | `CreateAgentSessionDto`    | `AgentSessionDto`   |
| `POST` | `/boards/:id/agent-sessions/:sessionId/heartbeat`     | тот же PAT                 | `AgentSessionHeartbeatDto` | `AgentSessionDto`   |
| `POST` | `/boards/:id/agent-sessions/:sessionId/end`           | тот же PAT или `ADMIN`     | `EndAgentSessionDto`       | `AgentSessionDto`   |
| `GET`  | `/boards/:id/agent-sessions?active=1`                 | любой участник             | нет                        | `AgentSessionDto[]` |
| `GET`  | `/boards/:id/agent-sessions/:sessionId`               | любой участник             | нет                        | `AgentSessionDto`   |

При старте можно передать `name`, `clientName`, `model` (до 100 символов).
Heartbeat принимает `status` (`active`, `idle`, `waiting_approval`),
`currentCardId`, `summary`; end — `status` (`completed`, `failed`,
`cancelled`) и `summary`. Повторный `end` возвращает сохранённое терминальное
состояние. Сессия без heartbeat дольше пяти минут получает вычисляемый
`stale: true` (в БД это не пишется). Завершение сессии освобождает её claim'ы.

PAT-запись может передать `X-Agent-Session: <sessionId>`. Сервер проверяет,
что сессия принадлежит тем же пользователю, токену и доске и не закрыта:
несовпадение — `403 agent_session_invalid`, закрытая сессия —
`403 agent_session_closed`. Start и heartbeat доступны только PAT: браузерная
сессия получает `403 pat_required` (в `endpoint` указано `start` или
`heartbeat`). `end` принимает тот же PAT или браузерную сессию board ADMIN.
Клиенты без заголовка продолжают работать: команды всё равно получают
`apiTokenId`, а `agentSessionId` остаётся `null`. Всю атрибуцию заполняет
сервер из principal; тело запроса не может подделать `apiTokenId`,
`agentSessionId`, `runId`, `agentName`, `claimedByTokenId` или
`claimedBySessionId`.

Записи и SSE-кадры команд содержат необязательные `apiTokenId`,
`agentSessionId`, `runId`, `agentName`. Записи активности содержат те же поля
плюс `actorType`; `CommentDto` отдаёт `actorType`, `apiTokenId`,
`agentSessionId`, `agentName`, а `AttachmentDto` —
`uploadedByTokenId`/`uploadedBySessionId`. `GET /boards/:id/activity` и
`GET /cards/:id/activity` принимают `actorType`, `apiTokenId`,
`agentSessionId`, `runId`, `type`, `from`, `to`; фильтры применяются к обоим
источникам (команды и строки активности). `GET /boards/:id/commands`
принимает только `since`, `runId`, `apiTokenId`, `agentSessionId`. Публичные
share-ответы и потоки удаляют id токена/сессии и имя токена. `GET /auth/me`
для PAT добавляет несекретный объект `token` (`scopePreset`, `trustedCi`,
метки паузы, `effectiveTokenScope`) и блок `server`; у сессии браузера
`token: null`.

## Обзор агентов

`GET /agents/overview` возвращает страницы запросов на подтверждение, сессий
или прогонов для панели управления в браузере. Запросы на подтверждение
видит ADMIN доски. Сессии и прогоны видят принятые участники доски. Можно
указать `section`, `boardId`, фильтры, `limit` и `cursor`. Параметры и
поля ответа перечислены в [документе OpenAPI](/openapi.yaml).

## Пауза и kill

Человек может остановить агентов, не отзывая ключ. Пауза обратима, kill —
это отзыв токена. Все маршруты паузы/возобновления доступны только сессии
браузера: PAT получает `403 pat_forbidden`, поэтому агент не может снять
паузу, которая его остановила.

| Метод  | Путь                                                | Доступ                | Запрос          | Ответ                 |
| ------ | --------------------------------------------------- | --------------------- | --------------- | --------------------- |
| `POST` | `/boards/:id/agent-sessions/:sessionId/pause`       | `ADMIN` доски, сессия | `AgentPauseDto` | `AgentSessionDto`     |
| `POST` | `/boards/:id/agent-sessions/:sessionId/resume`      | `ADMIN` доски, сессия | `AgentPauseDto` | `AgentSessionDto`     |
| `POST` | `/boards/:id/agents/pause`                          | `ADMIN` доски, сессия | `AgentPauseDto` | `BoardAgentPauseDto`  |
| `POST` | `/boards/:id/agents/resume`                         | `ADMIN` доски, сессия | `AgentPauseDto` | `BoardAgentPauseDto`  |
| `POST` | `/users/me/tokens/:id/pause`                        | владелец, сессия      | `AgentPauseDto` | `UserTokenDto`        |
| `POST` | `/users/me/tokens/:id/resume`                       | владелец, сессия      | `AgentPauseDto` | `UserTokenDto`        |
| `POST` | `/agents/pause-all`                                 | владелец, сессия      | `AgentPauseDto` | `AgentStopAllPauseDto` |
| `POST` | `/agents/resume-all`                                | владелец, сессия      | `AgentPauseDto` | `AgentStopAllPauseDto` |

`AgentPauseDto` — необязательное `{ reason?: string }` (до 500 символов).
Причина сохраняется в метке сессии/доски; для токена и stop-all она попадает
в `SecurityAuditLog`. Приоритет `pauseScope` — **токен → доска → сессия**:
пауза токена (`individualPausedAt` или `stopAllPausedAt`) важнее паузы доски,
а пауза доски важнее паузы сессии. `resume-all` очищает только
`stopAllPausedAt` и **не** снимает индивидуальную паузу токена; токен остаётся
на паузе, пока активен хотя бы один источник.

Любая PAT-запись, заблокированная паузой, отвечает `403` со стабильным кодом:

```json
{
  "message": "Agent access is paused at the board level; resume it before writing",
  "code": "agent_paused",
  "retryable": false,
  "pauseScope": "board",
  "scope": "board",
  "pausedAt": 1762764000000
}
```

Блокируются команды (одиночные и batch), комментарии, загрузка и удаление
вложений, claim'ы, изменение участников/ссылок доски и другие записи на
доске. GET-чтение остаётся доступным, а control plane — открытым: `heartbeat`,
`end` и `GET /boards/:id/agent-sessions/:id` работают во время паузы, чтобы
агент мог корректно завершиться. Пауза проверяется до роли на доске, области
токена и destructive/approval-гейтов: на паузе агент получает `agent_paused`,
а не `scope_denied`, `pat_read_only` или `approval_required`. Пауза не
освобождает claim. Завершение сессии или отзыв её токена освобождает claim'ы
сессии/токена.

Пауза проверяется на границе запроса и повторно внутри транзакции записи
доски после advisory lock. Запрос, прошедший вторую проверку, завершается и
коммитится; пауза, закоммиченная до неё, отклоняет запись. Эта же вторая
проверка отклоняет отозванный/истёкший токен (или отключённого владельца) и
сессию, завершённую до блокировки, поэтому поставленная в очередь запись не
переживёт `end_session` или `DELETE /users/me/tokens/:id`. На следующем
keep-alive PAT-поток получает
`{ "type": "agent", "op": "paused", "scope": "...", "at": ... }` и закрывается.
Пауза сессии закрывает только поток с `?session=<sessionId>`; переподключение
во время активной паузы получает `403 agent_paused`. Человеческие SSE-потоки
не закрываются. Пауза токена или stop-all также публикует кадр
`scope: "token"` на доски, где у токена есть живая сессия, чтобы Board Live
обновился без опроса; человеческие потоки при этом остаются открытыми.

`DELETE /users/me/tokens/:id` — необратимый kill. Он отзывает ключ, помечает
его открытые сессии `cancelled`, освобождает claim'ы с `claimedByTokenId`
(legacy-claim'ы без id токена ждут истечения lease) и закрывает SSE токена на
следующем тике. Новые запросы с ключом получают `401`.

## Области токена и destructive gate

У каждого PAT есть пресет области. По умолчанию новые ключи получают
`worker`. Владелец может изменить `scopePreset` существующего ключа в
разделе «Аккаунт → API-ключи» или через `PATCH /users/me/tokens/:id` из
сессии браузера. Устаревший флаг совместимости `readOnly` всегда даёт
эффективный пресет `observer`.

| Пресет     | Чтение | Обычная запись | Переход в Done (`reviewer`) | Destructive | Администрирование доски |
| ---------- | ------ | -------------- | --------------------------- | ----------- | ----------------------- |
| `observer` | да     | нет            | нет                         | нет         | нет                     |
| `worker`   | да     | да             | нет                         | approval / `trustedCi` | нет          |
| `reviewer` | да     | да             | да                          | approval / `trustedCi` | нет          |
| `admin`    | да     | да             | да                          | approval / `trustedCi` | да           |

Пресет не повышает роль на доске: ключ `admin` у участника MEMBER не даёт
управлять участниками, а ключ `worker` у ADMIN не удаляет карточку без
подтверждения. Destructive-действия требуют подтверждения человеком, если у
ключа нет `trustedCi`; `Board.agentPolicy.destructive = "deny"` — жёсткий
запрет, который не обходит даже `trustedCi`. Подтверждение не повышает область:
ключу `worker`, которому нужен `admin`, отвечают `scope_denied`, а не
`approval_required`.

Ключ, привязанный к доске, ограничен этой доской и не может создавать или
импортировать доски. Account-маршруты (запись профиля, управление ключами,
приглашения, экспорт) и их чувствительное чтение доступны только сессии
браузера. Чтение идентичности (`GET /auth/me`,
аватар) остаётся доступным.

Коды ошибок аддитивны и стабильны:

| Код | HTTP | Значение |
| --- | --- | --- |
| `scope_denied` | 403 | пресет или роль на доске не разрешают действие; для пресета — `requiredScope`/`action`, для роли — `requiredRoles`, для ключа, привязанного к другой доске, — `reason: "board_scope"` |
| `destructive_denied` | 403 | политика доски `destructive: "deny"`; `reason: "board_policy"` |
| `approval_required` | 409 | destructive-действие без подтверждения; запрос создан, ничего не применено; содержит `approvalId`, `planHash`, `expiresAt` |
| `approval_expired` | 409 | подтверждение истекло до решения/применения; содержит `approvalId`, `expiresAt` |
| `approval_mismatch` | 409 | план/`planHash` или `kind` не совпадают; содержит `approvalId` и префиксы хешей |
| `approval_target_mismatch` | 409 | явный `cardId` не совпадает с единственной карточкой плана; ничего не создаётся |
| `approval_owner_mismatch` | 403 | подтверждение принадлежит другому токену/агентской сессии |
| `approval_not_pending` | 409 | решение/отмена/применение попали в состояние не `pending`; содержит `status` |
| `approval_rejected` / `approval_cancelled` | 409 | запрос отклонён/отменён; применять его нельзя |
| `approval_consumed` | 409 | подтверждение уже применено; при наличии содержит `runId` |
| `pat_forbidden` | 403 | account-маршрут доступен только сессии |
| `agent_paused` | 403 | запись заблокирована паузой сессии, токена или доски; `pauseScope`/`pausedAt`, `retryable: false` |
| `pat_read_only` | 403 | устаревший read-only ключ отклонил запись |

## Персональные API-токены

Владелец аккаунта управляет токенами из браузерной сессии.

| Метод | Путь | Запрос | Ответ |
| --- | --- | --- | --- |
| `GET` | `/users/me/tokens` | — | `UserTokenDto[]` |
| `POST` | `/users/me/tokens` | `CreateUserTokenDto` | `{ token, apiToken }` |
| `PATCH` | `/users/me/tokens/:id` | `UpdateUserTokenDto` | `UserTokenDto` |
| `DELETE` | `/users/me/tokens/:id` | — | `{ status: "ok" }` |
| `POST` | `/users/me/tokens/:id/pause` | `AgentPauseDto` | `UserTokenDto` |
| `POST` | `/users/me/tokens/:id/resume` | `AgentPauseDto` | `UserTokenDto` |

Новый токен по умолчанию получает `worker`. PATCH принимает `name`,
`scopePreset`, `boardId`, `readOnly`, `rateLimitPerMinute` и `trustedCi`.
Пропущенные поля сохраняют значения. `null` сбрасывает ограничение доски
или частоты запросов. Сервер отбрасывает `expiresAt` и другие неизвестные
поля при валидации, поэтому срок действия остаётся прежним. Открытый текст
ключа возвращается один раз при создании. PATCH отозванного ключа возвращает
`409 token_revoked`. При отзыве сервер отменяет открытые сессии, освобождает
резервирования токена и закрывает его SSE-потоки.

## Подтверждения

Подтверждение разрешает один точный план, но само ничего не применяет. Агент
создаёт запрос своим PAT, человек-ADMIN доски решает его в браузерной сессии,
а агент повторяет тот же план с полученным id.

| Метод | Путь | Доступ | Запрос | Ответ |
| --- | --- | --- | --- | --- |
| `POST` | `/boards/:id/approvals` | PAT, участник доски | `CreateApprovalRequest` | `ApprovalRequestDto` |
| `GET` | `/boards/:id/approvals` | ADMIN доски или создавший PAT | `status`, `kind`, `cardId`, `limit` | `ApprovalRequestDto[]` |
| `GET` | `/boards/:id/approvals/:approvalId` | ADMIN доски или создавший PAT | — | `ApprovalRequestDto` |
| `POST` | `/boards/:id/approvals/:approvalId/decision` | только сессия, ADMIN доски | `{ decision, planHash, comment? }` | `ApprovalRequestDto` |
| `POST` | `/boards/:id/approvals/:approvalId/cancel` | создавший PAT или ADMIN доски | — | `ApprovalRequestDto` |

Тело `POST /boards/:id/approvals` — `{ kind, cardId?, ttlMinutes?, plan }`, где
`kind` ∈ `destructive`/`done`/`custom`, а `plan` — либо
`{ schemaVersion: 1, boardId, commands }`, либо
`{ schemaVersion: 1, boardId, operations }` (ровно одно). `commands`
проверяются тем же валидатором и лимитами, что `/commands/batch` (по умолчанию
100 команд, 50 создаваемых карточек); в `operations` ровно одна разрешённая
lifecycle-операция (`board.delete`, `member.*`, `share.*`,
`attachment.delete`). `action.at` и `boardId` внутри действия не входят в
намерение: сервер убирает их перед вычислением
`planHash = sha256(canonicalJson({schemaVersion, boardId, commands|operations}))`,
поэтому одно и то же тело всегда даёт один хеш. Хеш возвращает сервер; хеш
клиента не принимается как истина.

Если destructive-команда/батч или lifecycle REST-вызов приходят без
`X-Approval-Id`, сервер создаёт такой же запрос для точного плана и отвечает
`409 approval_required` с `approvalId`, `planHash`, `expiresAt`; ничего не
применяется. Пресет должен уже позволять действие после подтверждения: ключ
`worker` не может превратить удаление доски в approval (получит
`scope_denied`), а `destructive: "deny"` — жёсткий `403 destructive_denied` без
создания строки.

Чтобы применить, повторите тот же план/команды с `X-Approval-Id: <id>` на
`POST /commands`, `/commands/batch` или исходном lifecycle-маршруте.
`requestedByTokenId` должен совпадать с текущим PAT; если запрос записал
агентскую сессию, `X-Agent-Session` тоже должен совпасть. Подтверждение
одноразовое: те же уже применённые команды — идемпотентный повтор, другой
план получает `approval_mismatch` или `approval_consumed`. Ответ
`approval_mismatch` для владельца запроса включает сохранённый `plan`. Применение
batch/commands создаёт `AgentRun` с `approvalId`, проставляет `runId` каждой
команде и пишет `approval_consumed`; lifecycle-операция оставляет `runId`
`null`. Повторный запрос уже применённого lifecycle-плана для той же доски,
токена и агентской сессии возвращает `409 approval_consumed`.
Решение доступно только браузерной сессии.
PAT получает `pat_forbidden`. Запрос агента подтверждает человек-владелец
токена.

TTL = `min(ttlMinutes ?? policy.approvalTtlMinutes, policy.approvalTtlMinutes)` с
нижней границей 5 минут. Просроченные запросы в статусе `pending` переходят
в `expired` при обращении или в ходе плановой задачи `sweep-approvals`.
Пока запись в статусе `approved` хранится, она содержит решение и после
окончания срока применения. Попытка применить такой запрос возвращает
`409 approval_expired`. Отправьте тот же план ещё раз, чтобы создать новый
запрос. Завершение сессии отменяет ожидающие запросы и одобрения этой
сессии, срок действия которых ещё не истёк. Отзыв токена также отменяет
его действующие запросы. Решения записываются в журнал активности и
`SecurityAuditLog` и публикуются в SSE-кадрах `approval`.

Эта задача также удаляет отклонённые, отменённые, истёкшие, использованные
и просроченные одобренные запросы по истечении настроенного срока хранения.
Для просроченных одобренных запросов срок хранения отсчитывается от
`expiresAt`. См. [настройки срока хранения](/ru/docs/admin/settings/#мягко-удалённые-данные-и-срок-хранения).

Очередь в браузере использует
`GET /agents/overview?section=approvals&boardId=<id>`. Параметры
`status=pending` и `status=decided` возвращают отдельные очереди.
Передавайте `nextCursor` с теми же фильтрами для получения следующей
страницы. `total` содержит число совпадений до разбивки на страницы.
`matchingCounts` учитывает поиск и фильтры области по всем статусам,
а `counts` содержит общие показатели области. Счётчик в заголовке Inbox
учитывает истечение TTL при следующем 30-секундном опросе, пока вкладка видима.

Раздел Attention подписывается на SSE подтверждений первых четырёх досок и при
необходимости добавляет доску из фильтра или доску выбранного подтверждения.
Данные по остальным доскам обновляются при 30-секундном опросе, пока вкладка
видима. Сброс и смена пароля, а также перехват аккаунта через OAuth отменяют
действующие подтверждения отозванных токенов в транзакции изменения учётных данных.
Браузер может получить сведения об этой отмене при следующем опросе.

Сессии браузера не проходят через пресет/destructive gate; их правила ролей на
доске не меняются (включая обычный undo). PAT никогда не отправляет команды
`RESTORE_*` (`scope_denied`) — агент делает компенсирующие правки или просит
человека откатить run.

## Планы

План — это сначала dry-run, а затем атомарное применение ровно того намерения,
которое было показано. Оба маршрута — запись на доске: `ADMIN`/`MEMBER` и
пресет токена `worker` или выше. В плане не больше
`min(100, policy.maxCommandsPerRun)` команд и
`min(50, policy.maxCardsPerRun)` созданий карточек (`ADD_CARD`,
`DUPLICATE_CARD`, `DUPLICATE_COLUMN`); больший план получает
`409 limit_exceeded`, и клиент делит работу на несколько планов. Межатомарности
между планами намеренно нет.

| Метод | Путь | Аутентификация / роль | Запрос | Ответ |
| --- | --- | --- | --- | --- |
| `POST` | `/boards/:id/plans` | `ADMIN`/`MEMBER`, пресет `worker` | `{ commands, clientRunId? }` | `PlanPreviewDto` |
| `POST` | `/boards/:id/plans/apply` | то же; необязательный `X-Approval-Id` | `{ commands, planHash, clientRunId? }` | `PlanApplyResponse` |

`commands` — тот же массив, что принимает `/commands/batch`; он проходит тот
же валидатор, проверки WIP/workflow/версий, пресет и destructive-классификацию.
`action.at` и `boardId` уровня действия — транспортный контекст, а не
намерение: сервер их вырезает и считает
`planHash = sha256(canonicalJson({ schemaVersion: 1, boardId, commands }))`
с рекурсивной сортировкой ключей, сохранением порядка массива и без пробелов.
Хеш возвращает сервер; клиентское значение само по себе не принимается.

`POST /boards/:id/plans` ничего не пишет: не создаёт команду, `AgentRun` или
`ApprovalRequest`. Он проигрывает редьюсер в памяти и возвращает:

- `planHash` и канонический `plan` (команды без `at`/`boardId`);
- `diff` — итоговые изменения `create`/`update`/`delete` с затронутой
  сущностью `card:`/`column:`/`label:`/`board:`, полным состоянием для
  создания/удаления и изменёнными полями для обновления;
- `warnings` — `approval_required`, `destructive`, `reviewer_required`,
  `no_op`;
- `conflicts` — `version`, `wip`, `workflow`, `id`, `scope`,
  `destructive_denied` или `invalid`, с `index` команды и `currentVersion`,
  когда он известен;
- `requirement` (kind/scope/risk/summary), эффективные `limits` и `canApply`.

`POST /boards/:id/plans/apply` требует ровно тот `planHash`, который вернул preview.
Изменённый план — `409 approval_mismatch` с префиксами
`expectedPlanHash`/`actualPlanHash` и `approvalId`, если заголовок был
передан. Дальше apply ведёт себя как `/commands/batch`: одна блокировка доски,
одна транзакция, all-or-nothing, результаты в порядке команд, идемпотентность
по `commandId` и `409 idempotency_conflict` при повторном ключе с другим телом.
Destructive-план без `X-Approval-Id` создаёт точный запрос подтверждения и
отвечает `409 approval_required` без частичного применения; с одобренным id
план применяется и одноразово расходует подтверждение. Повтор тех же
применённых команд — идемпотентный replay.

PAT-план создаёт один `AgentRun` (`kind: "plan"`, `planHash` и необязательный
`clientRunId`), сохраняет pre-image для каждой команды и возвращает
`{ runId, results, planHash }` плюс `X-Run-Id`; этот run виден в `GET /runs`
и откатывается человеком-ADMIN доски. План из браузера run не создаёт (его
история — обычный UI undo). План никогда не охватывает несколько досок.

## Runs и откат

Run группирует команды одного PAT-батча, одной одиночной destructive-команды
PAT, применения плана или человеческого отката для аудита и rollback. Run
принадлежит одной доске. Браузерный батч и обычные неразрушающие правки
браузера run не создают (их история — стек undo в UI).

| Метод | Путь | Доступ | Запрос | Ответ |
| --- | --- | --- | --- | --- |
| `GET` | `/boards/:id/runs` | участник (`observer`+) | `status`, `kind`, `apiTokenId`, `agentSessionId`, `clientRunId`, `from`, `to`, `limit`, `cursor` | `RunSummaryDto[]` |
| `GET` | `/boards/:id/runs/:runId` | участник; pre-images — только board `ADMIN` в браузере | — | `RunDetailDto` |
| `POST` | `/boards/:id/runs/:runId/revert/preview` | участник, dry-run | — | `RevertPreviewDto` |
| `POST` | `/boards/:id/runs/:runId/revert` | только сессия `ADMIN` доски, если `dryRun` равен `false` или пропущен | `RevertRunDto` | `RunDetailDto` |
| `POST` | `/boards/:id/runs/:runId/revert` | участник при `{ "dryRun": true }` | `RevertRunDto` | `RevertPreviewDto` |

`RunSummaryDto` содержит `id`, `boardId`, `apiTokenId`, `agentSessionId`,
`actorId`, `kind` (`batch`, `plan`, `single`, `revert`), `status` (`applied`,
`reverted`; неудачная транзакция откатывается и запуск не создаёт), `clientRunId`, `planHash`, `approvalId`, `commandCount`,
`firstSeq`/`lastSeq`, `revertsRunId`, `createdAt`, `appliedAt` и
`revertedAt`. Деталь добавляет таймлайн команд и `preimages`. PAT видит
сводку и команды, но **не** снимки «до», даже если его владелец — board ADMIN.

```json
{
  "id": "run-01",
  "boardId": "board-1",
  "apiTokenId": "tok-1",
  "agentSessionId": "sess-1",
  "actorId": "user-1",
  "kind": "batch",
  "status": "applied",
  "clientRunId": "nightly-import-1",
  "planHash": null,
  "approvalId": null,
  "commandCount": 12,
  "firstSeq": 101,
  "lastSeq": 112,
  "revertsRunId": null,
  "createdAt": 1762764000000,
  "appliedAt": 1762764000000,
  "revertedAt": null
}
```

Preview возвращает `{ dryRun: true, run, conflicts, canRevert }`; `diff`
присутствует только у board ADMIN в браузерной сессии. Конфликт называет
`touch`, `expectedVersion`, записанную при применении run, и `currentVersion`
сейчас. Реальный откат all-or-nothing, повторно проверяет конфликты под
блокировкой доски, разрешён один раз на run (откат отката запрещён) и создаёт
новый run `kind: "revert"` с `revertsRunId`; исходный становится `reverted`.
`409 run_conflict` означает, что состояние run это запрещает, и содержит
`runId` и `currentVersion` доски; `409 run_expired` означает, что команды или
pre-images удалены retention, и содержит `runId` и `retentionDays`. Для
реального отката нужен `commandId`, чтобы сетевой повтор был идемпотентным;
без него ответ — `400 validation_failed` с полем `commandId`. Read-only PAT
может вызвать общий маршрут `revert` с `{ "dryRun": true }`; реальный откат
для PAT по-прежнему запрещён (`403 pat_forbidden`).

## Политика агентов доски

Политикой управляет человек. Оба маршрута доступны только board `ADMIN` в
браузерной сессии. Проверки аутентификации и доступа к доске выполняются
до проверки сессии.

| Метод | Путь | Запрос | Ответ |
| --- | --- | --- | --- |
| `GET` | `/boards/:id/agent-policy` | — | `BoardAgentPolicyStateDto` |
| `PATCH` | `/boards/:id/agent-policy` | `{ policy, version }` | `BoardAgentPolicyStateDto` |

`policy: null` означает, что сохранённого значения нет и действуют безопасные
умолчания; ответ всегда содержит эффективную политику, CAS-токен
`agentPolicyVersion` и текущее состояние паузы. `PATCH` требует актуальный
`version`; устаревший — `409 version_conflict` с
`details.currentVersion`. `policy: null` возвращает умолчания. Лимиты
проверяются строго:

```json
{
  "schemaVersion": 1,
  "destructive": "approval",
  "requireApprovalFor": [
    "member.invite",
    "member.remove",
    "share.create",
    "share.revoke",
    "attachment.delete",
    "delete_board"
  ],
  "approverRoles": ["ADMIN"],
  "maxCommandsPerRun": 100,
  "maxCardsPerRun": 50,
  "approvalTtlMinutes": 60
}
```

`destructive` — `approval` или `deny` (жёсткий запрет, без создания approval);
`maxCommandsPerRun` — 1–100, `maxCardsPerRun` — 1–50,
`approvalTtlMinutes` — 5–1440. Каждое изменение политики пишет Activity и
`SecurityAuditLog`.

## Вложения

Файлы загружаются через REST как `multipart/form-data` с единственной частью
`file`. `CardAccessGuard` определяет доску, к которой относится запись по карточке или вложению.

| Метод    | Путь                                   | Аутентификация / роль | Ответ              |
| -------- | -------------------------------------- | --------------------- | ------------------ |
| `POST`   | `/cards/:cardId/attachments`           | `ADMIN` / `MEMBER`    | `AttachmentDto`    |
| `GET`    | `/cards/:cardId/attachments`           | участник              | `AttachmentDto[]`  |
| `GET`    | `/attachments/:attachmentId/content`   | участник              | байты блоба        |
| `GET`    | `/attachments/:attachmentId/thumbnail` | участник              | байты изображения  |
| `GET`    | `/attachments/:attachmentId/poster`    | участник              | байты изображения  |
| `DELETE` | `/attachments/:attachmentId`           | `ADMIN` / `MEMBER`    | `{ status: "ok" }` |

`POST` принимает `?inline=1` (или `?inline=true`), чтобы пометить блоб как
медиа, встроенное в тело: скрыто из списка, без счётчика и без активности.
Параметр `?description=1` помечает файл, вставленный в описание: он виден в
списке, пока на него ссылается описание или комментарий, и скрывается, когда
ссылок больше нет. Скрытые файлы остаются доступны и учитываются в лимите,
чтобы работали Undo/Redo и сохранённые снимки. При одновременном указании
обоих параметров приоритет у `inline`. Список скрытых файлов для очистки:
`GET /cards/:cardId/attachments?detached=1`.
Файл не более `LIMITS.attachmentSize` (25 МБ). Сервер применяет allowlist
MIME-типов и проверяет сигнатуры файлов для типов изображений, видео, аудио и
архивов; если заявленный тип не соответствует содержимому файла, сервер
возвращает `400`. Если у карточки уже есть `LIMITS.attachmentsPerCard` (20)
неудалённых вложений, новая загрузка также отклоняется с `400`.

`GET /attachments/:attachmentId/content` отдаёт блоб с
`Content-Disposition: attachment`. Ответ поддерживает диапазоны: заголовок
`Range` даёт `206` с `Content-Range`, а невыполнимый диапазон даёт `416`.

`GET .../thumbnail` отдаёт сгенерированное превью (`image/jpeg`), когда оно
готово, иначе исходный блоб для изображений. У видео нет миниатюры, а
для остальных файлов без готовой миниатюры сервер возвращает `404`.

`GET .../poster` отдаёт первый значимый кадр видео (`image/jpeg`). Когда он
не сгенерирован, отвечает `404`.

## Управление публичными ссылками

Публичная ссылка — отдельная сущность с токеном, режимом, настройками доступа,
сроком действия и статусом отзыва. Маршруты управления находятся внутри доски и
доступны только роли `ADMIN`.

| Метод    | Путь                                  | Аутентификация / роль | Запрос           | Ответ             |
| -------- | ------------------------------------- | --------------------- | ---------------- | ----------------- |
| `GET`    | `/boards/:id/shares`                  | `ADMIN`               | нет              | `BoardShareDto[]` |
| `POST`   | `/boards/:id/shares`                  | `ADMIN`               | `CreateShareDto` | `BoardShareDto`   |
| `POST`   | `/boards/:id/shares/:shareId/refresh` | `ADMIN`               | нет              | `BoardShareDto`   |
| `PATCH`  | `/boards/:id/shares/:shareId`         | `ADMIN`               | `UpdateShareDto` | `BoardShareDto`   |
| `DELETE` | `/boards/:id/shares/:shareId`         | `ADMIN`               | нет              | `BoardShareDto`   |
| `DELETE` | `/boards/:id/shares/:shareId/permanent` | `ADMIN` | нет | `204`, пустой ответ |

Ссылка работает в режиме `snapshot` или `live`. Снимок (`snapshot`) сохраняет
состояние доски на момент создания и остаётся доступным после её удаления;
обновить снимок может администратор доски. Ссылка `live` показывает текущую
версию доски и получает изменения по SSE.

`POST` генерирует случайный токен (16 байт, base64url). `includeComments` по
умолчанию `true` для live-share и `false` для snapshot; `includeAttachments`
по умолчанию `false`. Можно задать `expiresAt` в будущем или длительность
`expiresInHours`. Если переданы оба поля, действует относительный срок.
Значение `expiresAt`, отличное от `null`, всегда проверяется на соответствие
ISO-8601. Ответы владельцу включают `effectiveIncludeComments` и
`effectiveIncludeAttachments` вместе с настроенными флагами. Эффективные
флаги показывают, какие категории снапшота доступны публике.

`POST .../refresh` обновляет снимок до текущего состояния доски. Для ссылки
`live` сервер возвращает `400` до создания согласования. Это lifecycle-действие
`share.update`: PAT на доске с обязательным подтверждением получает
`409 approval_required` с `approvalId`/`planHash`, а повтор должен нести
`X-Approval-Id`. Успешное обновление пишется в аудит share; повторное
использование согласования отвечает `409 approval_consumed`. Создание и
обновление снимка возвращают `413 snapshot_attachment_limit`, если нужно
скопировать более 500 файлов или 100 МиБ. Для более чем 1 000 комментариев
или 10 МиБ JSON-данных комментариев в UTF-8 возвращается
`413 snapshot_comment_limit`. При отказе в обновлении предыдущий снимок
сохраняется.

При выключенных публичных ссылках (`ALLOW_PUBLIC_SHARES=false` или флаг
`public_shares`) создание и обновление отвечают `404` до согласований и
idempotency-записей. `PATCH` пишет строку `BoardShareAuditLog` с действием
`updated`; `POST .../refresh` — `refreshed`, отзыв — `revoked`. Жёсткое
удаление отозванной ссылки мастером дополнительно пишется в аудит мастера как
`share.revoked`.

`DELETE` отзывает ссылку: её токен сразу перестаёт работать. Отзыв
идемпотентен. `DELETE .../permanent` удаляет ранее отозванную ссылку. Для
PAT действуют пресет `admin` и правила подтверждения `share.delete`.

Если ссылка `:shareId` относится к другой доске, сервер возвращает `403`; если она неизвестна — `404`.

## Публичные ссылки: чтение данных

Публичный API доступен только для чтения и не требует пользовательского JWT.
`ShareAccessGuard` проверяет токен ссылки, срок действия, отзыв и общий
переключатель `ALLOW_PUBLIC_SHARES`. Если ссылка неизвестна, отозвана,
просрочена или отключена, сервер возвращает одинаковый ответ `404`. Ответы
содержат заголовок `X-Robots-Tag: noindex, nofollow`.

Для каждого токена действуют лимиты: 240 запросов в минуту на токен
(`SHARE_RATE_LIMIT`), и 60 в минуту для OG-превью (`SHARE_OG_RATE_LIMIT`).
При превышении лимита сервер возвращает `429`.

| Метод  | Путь                                              | Ответ             |
| ------ | ------------------------------------------------- | ----------------- |
| `GET`  | `/share/:token`                                   | `PublicBoardDto`  |
| `GET`  | `/share/:token/events`                            | поток SSE         |
| `GET`  | `/share/:token/og.png`                            | `image/png`       |
| `GET`  | `/share/:token/cards/:cardId/comments`            | `CommentPage`     |
| `GET`  | `/share/:token/cards/:cardId/attachments`         | `AttachmentDto[]` |
| `GET`  | `/share/:token/attachments/:attachmentId/content` | байты блоба       |
| `POST` | `/share/:token`                                   | `405`             |
| `POST` | `/share/:token/{*rest}`                           | `405`             |

`GET /share/:token` возвращает полные данные публичной доски: доску (живой агрегат
или замороженный snapshot), очищенный состав участников без email и флаги
приватности share. Он считает один просмотр. Live-share, чья доска исчезла,
отвечает `410`. Доска и состав участников в снимке доступны после удаления
источника. При исчерпании лимита одновременных пересборок агрегата процесс
может вернуть `503` при чтении живой доски.

`GET /share/:token/events` работает только в режиме live; snapshot отвечает
`404`. Он стримит кадры `command` и, когда задан `includeComments`, кадры
`activity`. Кадры presence и membership отбрасываются, поэтому публичный
посетитель не получает события о присутствии участников. Получение пропущенных
событий `?since=` повторяет поток участника,
включая кадр `resync`. Живая доска, которая исчезла, отвечает `410`. Открытый
поток перепроверяет share на каждом тике keep-alive и закрывается, как только
share отозван или истёк, публичные ссылки выключены или доски больше нет.

`GET /share/:token/og.png` возвращает детерминированный PNG-превью доски.

`GET .../comments` и `GET .../attachments` отвечают `404`, когда share не
раскрывает соответственно комментарии или вложения. Карточка, которой нет на
общей доске, отвечает `404`.

Снимок отдаёт сохранённые версии включённых комментариев, метаданных и
файлов вложений. Эти версии доступны после изменений, добавления и удаления
данных, архивации и удаления доски, включая окончательную очистку. Запрос
файла или карточки, которых не было в снимке, возвращает `404`. Выключение
параметра сразу скрывает соответствующие данные. Чтобы показать категорию,
не сохранённую в снимке, нужно обновить снимок. Старые снимки, сохранившие
только доску и состав участников, могут показывать исходные комментарии
и файлы, созданные к моменту снимка, пока исходная доска и записи доступны.
Мягкое удаление исходной доски отключает показ этих данных.
Обновление старого снимка при доступном источнике сохраняет независимые копии.

`POST /share/:token` и любой вложенный `POST` отвечают `405` с
`"Shared boards are read-only"`. Публичный контур заявляет запрет на запись, а
не полагается на отсутствие маршрута.

## Обновления в реальном времени

| Метод  | Путь                   | Аутентификация / роль | Запрос                  | Ответ        |
| ------ | ---------------------- | --------------------- | ----------------------- | ------------ |
| `GET`  | `/boards/:id/events`   | участник              | query `since`, `client` | поток SSE    |
| `POST` | `/boards/:id/presence` | участник              | `PresencePingDto`       | `204`, пусто |

`GET /boards/:id/events` открывает поток server-sent events. Для подключения
нужен Bearer-токен (access-токен или персональный API-токен); любая роль,
включая
`VIEWER`, может подключиться. Поток доставляет журнал команд доски ровно один
раз и по порядку или велит клиенту пересинхронизироваться; пропуски не игнорируются:

- **Получение пропущенных команд.** Соединение воспроизводит дельту журнала команд из `?since=`
  (последний применённый `seq` клиента). Живые кадры, пришедшие тем временем,
  буферизуются, затем сливаются с дедупликацией по `seq`.
- **Resync.** Когда разрыв нельзя воспроизвести точно (больше 5000 команд или
  `since` срезан из журнала), поток вместо частичной истории присылает
  `{ "type": "resync" }` и продолжает с текущей версии доски. Клиент должен
  заново прочитать доску через `GET /boards/:id`.
- **Пропуски.** Если живой кадр показывает, что предыдущий потерялся или
  пришёл не по порядку (например, между узлами), поток дочитывает
  недостающие команды из журнала, а не доставляет их вразнобой.

Комментарий keep-alive `ping` отправляется каждые 25 секунд. На том же тике
сервер перепроверяет вызывающего и закрывает поток, когда доступа больше нет:
членство удалено или больше не принято, доступ `VIEWER` истёк, аккаунт
заблокирован, доска удалена или поток открыт персональным API-токеном,
который с тех пор отозван или истёк.

`?client=` — это необязательный id вкладки, соответствующий
`^[A-Za-z0-9_-]{8,64}$`. Когда он пропущен или неверен, сервер генерирует
свой.

Поток передаёт шесть типов событий:

| `type`       | Нагрузка                                                       | Примечания                                           |
| ------------ | -------------------------------------------------------------- | ---------------------------------------------------- |
| `command`    | `seq`, `action`, `actorId`, `actorType?`, `commandId`, `touches`, `apiTokenId?`, `agentSessionId?`, `runId?`, `agentName?` | зафиксированная команда                              |
| `presence`   | `users[]`                                                      | кто подключён; без `seq`                             |
| `membership` | `boardId`, `userId`, `change`                                  | `change` — `accepted`, `updated`, `removed` (админ) или `left` (сам вышел) |
| `activity`   | `id`, `boardId`, `cardId?`, `actorId`, `actorType?`, `at`, `kind`, `detail?`, `apiTokenId?`, `agentSessionId?`, `runId?`, `agentName?` | активность вне редьюсера, например новый комментарий |
| `agent`      | `op` (`started`, `paused`, `resumed`, `heartbeat`, `ended`), `sessionId?`, `scope?`, `at` | переход управления сессией агента; `heartbeat` — троттлинговая проверка живости сессии |
| `resync`     | нет                                                            | разрыв не воспроизвести; перечитайте доску           |

`commandId` — это ключ идемпотентности, с которым команда была отправлена,
поэтому клиент узнаёт собственное эхо по ключу, даже когда один аккаунт
отправляет команды из нескольких вкладок или от имени нескольких агентов.

`actorType` — это `"human"` для сессии браузера и `"agent"` для персонального
API-токена; в кадрах до появления поля он отсутствует, поэтому пустое значение
считайте `"human"`. История карточки помечает записи агента значком «Агент».

Если участника, открывшего поток, удалил админ или он вышел сам, сервер
отправляет кадр `membership` последним и закрывает поток.

`POST /boards/:id/presence` подтверждает активность соединения. У SSE-потока нет обратного канала,
поэтому вкладка подтверждает активность этим ping каждые 25 секунд; если
подтверждения не поступают, сессия удаляется из списка присутствующих через 60
секунд. Тело содержит `clientId`,
с которым был открыт поток. Ping обновляет только сессию, которой владеет
вызывающий. Ответ — это `204` с пустым телом.

## Ошибки

Каждая ошибка ниже использует общий конверт
[`code`/`message`/`retryable`/`requestId`](../#формат-ошибок). HTTP-статус
сохраняется; `code` называет причину.

| Статус | Когда                                                                                                                                                                      |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `400`  | валидация провалилась, пустой обязательный текст, неверный лимит или срок, неверный или пустой пакет импорта, отклонённый файл                                                  |
| `401`  | отсутствующий или неверный токен                                                                                                                                           |
| `403`  | не участник; роль, не разрешённая маршрутом; истёкший `VIEWER`; share, не принадлежащий доске; удаление комментария не автором                                             |
| `403`  | `code: "pat_forbidden"`: персональный API-токен на маршруте только для сессии                                                                                              |
| `404`  | неизвестная или мягко удалённая доска, карточка, комментарий, вложение или share; отключённый, отозванный или истёкший публичный share; отсутствующая миниатюра или постер |
| `405`  | попытка записи через публичный API ссылок                                                                                                                                     |
| `408`  | `code: "request_timeout"`: команда прервана до применения; ничего не применено; `X-RateLimit-Queued-Ms` показывает время в очереди |
| `409`  | приглашение уже принятого участника; понижение или удаление последнего `ADMIN`; истёкшее приглашение; `commandId`, повторённый на другой карточке                          |
| `410`  | live-share, чья доска больше не существует                                                                                                                                 |
| `413`  | нагрузка команды сверх `MAX_COMMAND_BYTES`; импорт больше 25 МБ; тело команды/плана больше 10 МБ; любое другое JSON-тело больше 256 КБ (`code: "payload_too_large"`)                                    |
| `416`  | невыполнимый `Range` на блобе                                                                                                                                              |
| `429`  | ограничение частоты превышено; `code: "login_backoff"` во время задержки входа                                                                                             |
| `503`  | `code: "rate_limited"`, когда команде не хватило токенов доски или очередь доски полна; повторите после `Retry-After` с тем же `commandId`                                                |
| `503`  | режим обслуживания; неуспешная проверка готовности; `code: "board_write_timeout"`, когда запись в доску превысила время ожидания (повтор безопасен)                         |
| `503`  | `POST /boards`, когда доска уже создана: `code: "starter_cleanup_failed"`, `"starter_read_failed"` или `"board_read_failed"` с `retryable: false` и `details.boardId`; откройте эту доску, а не создавайте новую |
