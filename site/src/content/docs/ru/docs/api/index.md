Бэкенд Janosik это сервис на NestJS. Эта страница фиксирует соглашения, общие
для всех маршрутов, и перечисляет группы эндпоинтов верхнего уровня. Изменения
содержимого идут через [Command API](./commands/); остальная поверхность это
обычный REST, описанный в [REST endpoints](./rest/).

## Базовый путь и транспорт

Каждый маршрут обслуживается под глобальным префиксом `/api/v1`. Маршрут,
названный в этом справочнике как `POST /auth/login`, доступен по
`POST /api/v1/auth/login`.

Запросы и ответы это JSON. Парсер JSON-тела принимает полезную нагрузку до
`MAX_IMPORT_BYTES` (5 МБ, `shared/src/types/kanban.ts`), поэтому большой
envelope импорта или команда `RESTORE_*` доходит до валидации, а не умирает в
парсере. Одна полезная нагрузка команды дополнительно ограничена
`MAX_COMMAND_BYTES` (2 МБ) внутри сервиса команд.

Загрузка файлов использует `multipart/form-data` с единственной частью `file`.

## Аутентификация

Пользовательские маршруты принимают любой из двух учётных данных в заголовке
`Authorization`:

```
Authorization: Bearer <access-token>
Authorization: Bearer jnk_<43 base64url chars>
```

Первый это короткоживущий JWT access-токен из эндпоинтов аутентификации.
Второй это персональный API-токен (PAT): значение, чей префикс `jnk_`
указывает guard аутентифицировать его по таблице `ApiToken`, а не через
JWT-стратегию. Оба открывают маршруты уровня доски одинаково.

Refresh-токен никогда не появляется в теле ответа. Он едет в httpOnly cookie
с именем `refresh_token`, ограниченной путём `/api/v1/auth` и с
`SameSite=Strict`. Только `POST /auth/refresh` и другие маршруты `/auth`,
которым нужна сессия вызывающего, читают её.

Контур мастер-аккаунта использует отдельную cookie (`admin_refresh_token`,
путь `/api/v1/admin/auth`), отдельную JWT-аудиторию (`janosik-admin`) и
отдельный claim `typ`. Пользовательский токен никогда не аутентифицирует
админский маршрут, а админский токен никогда не аутентифицирует
пользовательский маршрут.

## Конверт ошибок

Ошибки используют стандартное тело NestJS:

```json
{
  "statusCode": 400,
  "message": "title must not be blank",
  "error": "Bad Request"
}
```

`ValidationPipe` работает с `whitelist: true` и `transform: true`. Неизвестное
поле тела отбрасывается. Проваленная проверка class-validator отвечает `400`,
где `message` это массив строк, по одной на каждую проваленную проверку.

Две формы отличаются от стандартной и описаны там, где встречаются:

- Эндпоинт команд отвечает `409` телом `{ "conflict": "...", "currentVersion": n }`
  (см. [Command API](./commands/)).
- Некоторые эндпоинты отвечают `400` с добавленной строкой `field`, например
  `{ "message": "...", "field": "text" }`, чтобы клиент мог указать на ввод.

## Ограничения частоты

Глобально работают два ограничителя:

- Фиксированное окно на клиента (IP), `THROTTLE_LIMIT` запросов в минуту
  (по умолчанию 300). Оператор может изменить его в рантайме из панели
  мастера. `/health` освобождён.
- Необязательный бюджет на аутентифицированного пользователя, задаваемый из
  панели мастера. Контуры `/admin`, `/auth` и `/health` освобождены от него.

Отдельные маршруты аутентификации добавляют более узкие окна `@Throttle`:

| Маршрут                              | Лимит             |
| ------------------------------------ | ----------------- |
| `POST /auth/register`                | 5 в минуту на IP  |
| `POST /auth/login`                   | 5 в минуту на IP  |
| `POST /auth/password`                | 5 в минуту на IP  |
| `POST /auth/email/change/request`    | 3 в час на IP     |
| `POST /auth/email/change/confirm`    | 5 в минуту на IP  |
| `POST /auth/verify-email`            | 10 в минуту на IP |
| `POST /auth/verify-email/resend`     | 3 в час на IP     |
| `GET /auth/oauth/:provider/start`    | 20 в минуту на IP |
| `GET /auth/oauth/:provider/callback` | 20 в минуту на IP |

У публичного контура sharing свой бюджет на токен (см.
[REST endpoints](./rest/)). Отказ отвечает `429`.

## Режим обслуживания

Когда оператор включает обслуживание, `MaintenanceGuard` отвечает на каждый
публичный и пользовательский запрос `503` с сообщением оператора. Пути
`/admin`, `/auth` и `/health` остаются доступными, чтобы оператор мог войти и
выключить обслуживание.

## Эндпоинты аутентификации

| Метод  | Путь                         | Аутентификация | Возвращает                               |
| ------ | ---------------------------- | -------------- | ---------------------------------------- |
| `POST` | `/auth/register`             | нет            | `AuthResponseDto`                        |
| `POST` | `/auth/login`                | нет            | `AuthResponseDto`                        |
| `POST` | `/auth/refresh`              | refresh cookie | `AuthResponseDto`                        |
| `POST` | `/auth/logout`               | refresh cookie | `{ status: "ok" }`                       |
| `GET`  | `/auth/config`               | нет            | `AuthConfigResponse`                     |
| `GET`  | `/auth/me`                   | пользователь   | `AuthUserDto`                            |
| `POST` | `/auth/password`             | пользователь   | `{ status: "ok" }`                       |
| `POST` | `/auth/email/change/request` | пользователь   | `{ expiresAt: number, queued: boolean }` |
| `POST` | `/auth/email/change/confirm` | пользователь   | `AuthResponseDto`                        |
| `POST` | `/auth/verify-email`         | пользователь   | `{ user: AuthUserDto }`                  |
| `POST` | `/auth/verify-email/resend`  | пользователь   | `{ expiresAt: number, queued: boolean }` |

`register`, `login`, `refresh` и `email/change/confirm` устанавливают
refresh-cookie и возвращают `{ accessToken, user }`. `register` также
отправляет 6-значный код подтверждения на адрес.

### Регистрация

Тело `POST /auth/register`:

| Поле          | Тип    | Обязательно | Ограничения                                                |
| ------------- | ------ | ----------- | ---------------------------------------------------------- |
| `email`       | string | да          | валидный email; обрезается и приводится к нижнему регистру |
| `password`    | string | да          | от 8 до 100 символов                                       |
| `displayName` | string | нет         | не более 50 символов                                       |

Возвращает `AuthResponseDto` и устанавливает refresh-cookie. Дубликат адреса
отвечает `409`.

### Вход

Тело `POST /auth/login`:

| Поле       | Тип    | Обязательно | Ограничения                                                |
| ---------- | ------ | ----------- | ---------------------------------------------------------- |
| `email`    | string | да          | валидный email; обрезается и приводится к нижнему регистру |
| `password` | string | да          | не более 100 символов                                      |

Минимальная длина при входе не проверяется: короткий пароль отвечает `401`
как и любые другие неверные учётные данные. Возвращает `AuthResponseDto`.

### Refresh и выход

`POST /auth/refresh` читает cookie `refresh_token` и возвращает свежий
`AuthResponseDto`. `POST /auth/logout` отзывает сессию и очищает cookie,
возвращая `{ status: "ok" }`.

### Конфигурация

`GET /auth/config` не требует аутентификации и возвращает два публичных
булевых значения, которые экран входа читает до появления сессии:

```json
{ "allowRegistration": true, "allowPublicShares": true }
```

### Me

`GET /auth/me` возвращает `AuthUserDto` аутентифицированного пользователя.

### Смена пароля

Тело `POST /auth/password`:

| Поле              | Тип    | Обязательно | Ограничения           |
| ----------------- | ------ | ----------- | --------------------- |
| `currentPassword` | string | да          | не более 100 символов |
| `newPassword`     | string | да          | от 8 до 100 символов  |

Возвращает `{ status: "ok" }`. Refresh-cookie определяет, какая сессия
меняется; все остальные сессии отзываются.

### Смена email

`POST /auth/email/change/request` запускает двойное подтверждение. Тело:

| Поле              | Тип    | Обязательно | Ограничения                                                |
| ----------------- | ------ | ----------- | ---------------------------------------------------------- |
| `newEmail`        | string | да          | валидный email; обрезается и приводится к нижнему регистру |
| `currentPassword` | string | да          | минимум 1 символ                                           |

Возвращает `{ expiresAt, queued }` и отправляет 6-значный код на новый адрес.

Тело `POST /auth/email/change/confirm`:

| Поле   | Тип    | Обязательно | Ограничения  |
| ------ | ------ | ----------- | ------------ |
| `code` | string | да          | ровно 6 цифр |

При успехе адрес заменяется, все остальные сессии отзываются, и возвращается
свежий `AuthResponseDto` с refresh-cookie.

### Подтверждение email

Тело `POST /auth/verify-email`:

| Поле   | Тип    | Обязательно | Ограничения  |
| ------ | ------ | ----------- | ------------ |
| `code` | string | да          | ровно 6 цифр |

Возвращает `{ user }` с установленным `emailVerifiedAt`.
`POST /auth/verify-email/resend` отправляет новый код и возвращает
`{ expiresAt, queued }`.

### Двухфакторная аутентификация

У пользовательских аккаунтов нет второго фактора. 6-значный код
(подтверждение email, смена email) это внешнее подтверждение, а не фактор
входа. Двухфакторная аутентификация есть только при входе мастер-аккаунта:
тело входа админа принимает необязательный `totpCode`. См. контур
мастер-аккаунта.

## OAuth-вход

| Метод | Путь                             | Аутентификация | Возвращает                          |
| ----- | -------------------------------- | -------------- | ----------------------------------- |
| `GET` | `/auth/oauth/providers`          | нет            | `{ providers: OAuthProviderDto[] }` |
| `GET` | `/auth/oauth/:provider/start`    | нет            | `302` на провайдера                 |
| `GET` | `/auth/oauth/:provider/callback` | нет            | `302` в UI                          |

Оба редирект-эндпоинта это полные навигации страницы, а не XHR. `providers`
перечисляет только включённые провайдеры; каждая запись это `{ id, label }`,
где `id` один из `google` или `yandex`.

`start` генерирует state, ставит httpOnly state-cookie `SameSite=Lax` с
путём `/api/v1/auth/oauth` и перенаправляет на провайдера. `callback`
проверяет state, ставит refresh-cookie и перенаправляет в корень UI. Любая
ошибка перенаправляет на `?authError=oauth_failed` в корне UI.

## Пользователи и аккаунт

Каждый маршрут за пользовательской аутентификацией (JWT или PAT).

| Метод    | Путь                    | Возвращает                |
| -------- | ----------------------- | ------------------------- |
| `PATCH`  | `/users/me`             | `AuthUserDto`             |
| `PATCH`  | `/users/me/avatar`      | `AuthUserDto`             |
| `GET`    | `/users/:userId/avatar` | байты изображения         |
| `GET`    | `/users/me/tokens`      | `UserTokenDto[]`          |
| `POST`   | `/users/me/tokens`      | `CreateUserTokenResponse` |
| `DELETE` | `/users/me/tokens/:id`  | `{ status: "ok" }`        |

Тело `PATCH /users/me`:

| Поле          | Тип             | Обязательно | Ограничения                                                           |
| ------------- | --------------- | ----------- | --------------------------------------------------------------------- |
| `displayName` | string или null | нет         | не более 50 символов; `null` очищает                                  |
| `avatarColor` | string или null | нет         | одно из `USER_AVATAR_COLORS`; `null` возвращает значение по умолчанию |

Записываются только переданные ключи.

`PATCH /users/me/avatar` это `multipart/form-data` с единственной частью
`file`. Изображение не более 2 МБ (`LIMITS.avatarSize`). Возвращает
обновлённого пользователя.

`GET /users/:userId/avatar` отдаёт изображение аватара любому
аутентифицированному пользователю. Имена блобов уникальны для каждой
загрузки, поэтому ответ можно агрессивно кэшировать. Пользователь без
аватара отвечает `404`.

Тело `POST /users/me/tokens`:

| Поле        | Тип             | Обязательно | Ограничения                                                                   |
| ----------- | --------------- | ----------- | ----------------------------------------------------------------------------- |
| `name`      | string          | да          | не более 50 символов                                                          |
| `expiresAt` | string или null | нет         | ISO-8601; должен быть в будущем; пропуск или `null` означает отсутствие срока |

Возвращает `{ token, apiToken }`. Открытый текст `token` появляется ровно
один раз; далее возвращаются только метаданные `apiToken`.
`GET /users/me/tokens` перечисляет метаданные (никогда открытый текст).
`DELETE /users/me/tokens/:id` отзывает один токен и возвращает
`{ status: "ok" }`.

## Приглашения

Приглашение на доску это ожидающая строка членства (`acceptedAt: null`). Оно
не даёт доступа до принятия. Каждый маршрут за пользовательской
аутентификацией.

| Метод  | Путь                       | Возвращает             |
| ------ | -------------------------- | ---------------------- |
| `GET`  | `/invitations`             | `BoardInvitationDto[]` |
| `POST` | `/invitations/:id/accept`  | пустое тело, `200`     |
| `POST` | `/invitations/:id/decline` | пустое тело, `200`     |

`GET /invitations` перечисляет ожидающие, не истёкшие приглашения вызывающего,
сначала новые. `accept` ставит `acceptedAt`, после чего доска появляется в
`GET /boards`. `decline` удаляет строку. Истёкшее приглашение нельзя принять:
строка удаляется, а вызов отвечает `409`. Неизвестное или чужое приглашение
отвечает `404`.

## Ленты активности

Доступны любому участнику, включая `VIEWER`.

| Метод | Путь                      | Возвращает         |
| ----- | ------------------------- | ------------------ |
| `GET` | `/boards/:id/activity`    | `ActivityFeedPage` |
| `GET` | `/cards/:cardId/activity` | `ActivityFeedPage` |

Оба принимают `?cursor=` (непрозрачный) и `?limit=`. Лимит по умолчанию 50,
максимум 100; лимит вне `1` до `100` отвечает `400`. Записи идут сначала
новые; `nextCursor` равен `null` в конце. Лента доски объединяет журнал
команд со строками `Activity`; лента карточки ограничена одной карточкой.

## Health

`GET /health` это проба liveness и readiness. Он освобождён от глобального
ограничения частоты. Возвращает `200` с `HealthReport`:

```json
{ "status": "ok", "db": "up", "redis": "up" }
```

`redis` равен `disabled`, когда URL Redis не настроен. База данных
обязательна: проваленный ping БД отвечает `503` с
`{ "status": "error", "db": "down", "redis": ... }`. Настроенный, но
недоступный Redis также отвечает `503` с
`{ "status": "error", "db": "up", "redis": "down" }`.

## Объявления

| Метод | Путь                    | Аутентификация | Возвращает          |
| ----- | ----------------------- | -------------- | ------------------- |
| `GET` | `/announcements/active` | пользователь   | `AnnouncementDto[]` |

Возвращает внутриприложенческие объявления, адресованные вошедшему
пользователю. Неавторизованный посетитель не получает ничего.
