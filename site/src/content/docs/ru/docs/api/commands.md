Содержимое доски (колонки, карточки, метки, чек-листы, связи, обложки,
перемещения) не ходит как обычный REST. Клиент отправляет `CommandRequest` на
эндпоинт команд доски, и сервер воспроизводит тот же самый `BoardAction`
через общий `boardReducer`. Членство, создание/импорт/удаление доски и файлы
это исключения, и они живут в [REST endpoints](./rest/).

## Применение команды

```
POST /api/v1/boards/:id/commands
```

Аутентификация: пользовательская (JWT или PAT). Роль: `ADMIN` или `MEMBER`.
`VIEWER` отвечает `403`. Неизвестная или мягко удалённая доска отвечает `404`.

Тело запроса (`CreateCommandDto`):

| Поле              | Тип     | Обязательно | Ограничения                                                           |
| ----------------- | ------- | ----------- | --------------------------------------------------------------------- |
| `commandId`       | string  | да          | непустой, не более 64 символов; ключ идемпотентности                  |
| `action`          | object  | да          | `BoardAction`, строго проверяемый общим валидатором                   |
| `ifMatch`         | integer | нет         | ожидаемый `seq` доски; должен быть `>= 0`                             |
| `ifMatchVersions` | object  | нет         | предусловия на сущность; ключи и целые значения проверяются в сервисе |

Ответ `200` (`CommandResponse`):

```json
{ "seq": 42, "versions": { "card:abc": 7, "column:xyz": 3 } }
```

`seq` это монотонный порядковый номер доски. `versions` содержит счётчик
версии каждой сущности, которую команда действительно записала.

### Идемпотентность

`commandId` это первичный ключ строки `Command`. Повтор, использующий тот же
`commandId`, возвращает сохранённый `result` без второго применения действия
и без второго `seq`. `commandId`, уже использованный на другой доске,
отвечает `409` телом `{ "message": "...", "field": "commandId" }`.

### Оптимистичная конкурентность

Два необязательных предусловия защищают от перезаписи:

- `ifMatch` это `seq` доски, который клиент видел последним. Когда он
  отличается от текущего `seq`, сервер отвечает
  `409 { "conflict": "version", "currentVersion": n }`.
- `ifMatchVersions` это карта, ключом которой служит метка касания
  (`board:<id>`, `column:<id>`, `card:<id>`, `label:<id>`,
  `checklist:<id>`, `checklistItem:<id>`) со значением `version`, которое
  клиент видел последним. Каждый перечисленный ключ должен всё ещё держать
  эту версию. Устаревшая или отсутствующая сущность отвечает
  `409 { "conflict": "version", "currentVersion": n }`. Неизвестный ключ или
  нецелое значение отвечает `400 { "field": "ifMatchVersions" }`. Пропущенные
  ключи не проверяются, поэтому позиционные изменения остаются
  last-write-wins.

Именно `ifMatchVersions` делает отмену правки текста безопасной: если другой
писатель изменил сущность после, сервер отказывает, и клиент отказывает от
отмены вместо перезаписи чужого текста.

### Конфликты

Отклонённая команда отвечает `409` телом `ConflictError`
`{ "conflict": "<category>", "currentVersion": n }`. Категории:

| `conflict` | Значение                                                     |
| ---------- | ------------------------------------------------------------ |
| `version`  | предусловие `ifMatch` или `ifMatchVersions` устарело         |
| `wip`      | команда нарушила бы предел коллекции или WIP                 |
| `id`       | команда называет id сущности, уже принадлежащий другой доске |

Проверка `wip` повторяет ограничения коллекций редьюсера: `LIMITS` на
колонки, карточки в колонке, метки на доске, метки на карточке, связи на
карточке, чек-листы на карточке и пункты на чек-лист, плюс WIP-лимит колонки.
Семейство `RESTORE_*` освобождено (оно возвращает уже существовавшие данные).
Клиентский флаг `inverse: true` не даёт освобождения.

Проверка `id` существует потому, что id сущностей это глобальные первичные
ключи, а команды привязаны к доске: id, уже живущий на другой доске, был бы
молча перезаписан upsert-ами.

### Другие ошибки

| Статус | Причина                                                                        |
| ------ | ------------------------------------------------------------------------------ |
| `400`  | `action` не проходит общий валидатор; тело несёт `field` и `message`           |
| `400`  | неподдерживаемый тип действия; тело несёт `field: "action.type"`               |
| `400`  | ключ или значение `ifMatchVersions` неверны                                    |
| `403`  | вызывающий это `VIEWER`; или не-`ADMIN` шлёт `ARCHIVE_BOARD`/`UNARCHIVE_BOARD` |
| `404`  | доска не найдена                                                               |
| `409`  | конфликт (см. выше), или `commandId` использован на другой доске               |
| `413`  | сериализованный `action` превышает `MAX_COMMAND_BYTES` (2 МБ)                  |

Команды, ссылающиеся на неизвестные сущности, не делают ничего, как и
редьюсер, и всё равно записываются. Повтор возвращает сохранённый результат
no-op.

## Чтение журнала команд

```
GET /api/v1/boards/:id/commands?since=<seq>
```

Аутентификация: пользовательская. Роль: любой участник, включая `VIEWER`.
Возвращает `CommandDeltaEntry[]`, сначала старые: команды с `seq` больше
`since`. `since` это неотрицательное целое или отсутствует (отсутствие
означает `0`); любое другое значение отвечает `400`. Ответ ограничен 5000
записями.

Это догон дельты, который клиент выполняет после разрыва SSE. Живой поток
описан в [REST endpoints](./rest/).

## DTO

### CreateCommandDto

Тело запроса выше. `commandId` и `action` обязательны; `ifMatch` и
`ifMatchVersions` необязательны.

### CommandRequest

Общая проводная форма, которую зеркалит DTO:

| Поле              | Тип                      | Обязательно | Значение                                        |
| ----------------- | ------------------------ | ----------- | ----------------------------------------------- |
| `commandId`       | string                   | да          | ключ идемпотентности клиента                    |
| `action`          | `BoardAction`            | да          | действие редьюсера для применения               |
| `ifMatch`         | number                   | нет         | ожидаемая версия доски                          |
| `ifMatchVersions` | `Record<string, number>` | нет         | предусловия на сущность с ключом-меткой касания |

### CommandResponse

| Поле       | Тип                      | Значение                                                  |
| ---------- | ------------------------ | --------------------------------------------------------- |
| `seq`      | number                   | монотонный порядковый номер доски, порядок и версия доски |
| `versions` | `Record<string, number>` | счётчики версий сущностей, которых коснулась команда      |

### CommandDeltaEntry

Одна запись ленты дельты:

| Поле      | Тип           | Значение                                                                                 |
| --------- | ------------- | ---------------------------------------------------------------------------------------- |
| `seq`     | number        | порядковый номер команды на доске                                                        |
| `action`  | `BoardAction` | зафиксированное действие, точно как применено                                            |
| `actorId` | string        | кто выпустил команду                                                                     |
| `touches` | string[]      | сущности, которые записала команда, как метки касания; пусто, когда ничего не изменилось |

### ConflictError

| Поле             | Тип                          | Значение            |
| ---------------- | ---------------------------- | ------------------- |
| `conflict`       | `"version" \| "wip" \| "id"` | категория конфликта |
| `currentVersion` | number                       | текущий `seq` доски |

## Конверт команды

Каждое действие уровня доски несёт эти поля поверх своих:

| Поле             | Тип                   | Обязательно | Значение                                                                           |
| ---------------- | --------------------- | ----------- | ---------------------------------------------------------------------------------- |
| `boardId`        | string                | нет         | целевая доска; пропуск означает первую доску. Эндпоинт подставляет доску маршрута. |
| `at`             | number                | да          | часы команды в мс; каждая временная метка, которую пишет редьюсер, берётся отсюда  |
| `actorId`        | string или null       | нет         | кто выполнил команду; сервер перезаписывает его аутентифицированным пользователем  |
| `commandId`      | string                | нет         | несётся клиентом; ключ идемпотентности это `commandId` верхнего уровня эндпоинта   |
| `activityIds`    | string[]              | нет         | id событий активности, которые команда добавляет, в порядке добавления             |
| `boardUpdatedAt` | number                | нет         | только для inverse: переопределение `board.updatedAt`                              |
| `cardUpdatedAt`  | number                | нет         | только для inverse: переопределение `updatedAt` затронутой карточки                |
| `inverse`        | boolean               | нет         | помечает команду отмены; сервер не доверяет ей для освобождения от проверок        |
| `cardActivity`   | `CardActivityEvent[]` | нет         | только для inverse: лента карточки, какой она была до отменённой команды           |

## Каталог действий

Эндпоинт команд принимает каждое действие уровня доски ниже. Четыре действия
уровня агрегата перечислены в конце и отклоняются.

### Колонки

| Действие                | Поля                                                                           | Значение                                                                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `ADD_COLUMN`            | `newColumnId` string, `title` string                                           | Создаёт колонку. Заголовок обрезается до `LIMITS.columnTitle` (100). Игнорируется при `LIMITS.columnsPerBoard` (12) или на дубликате id. |
| `RENAME_COLUMN`         | `columnId` string, `title` string                                              | Переименовывает колонку. Пустой или неизменённый заголовок ничего не делает.                                                             |
| `DELETE_COLUMN`         | `columnId` string                                                              | Удаляет колонку и каждую карточку в ней.                                                                                                 |
| `DUPLICATE_COLUMN`      | `columnId`, `newColumnId`, `newCardIds` string[], `title` string необязательно | Копирует колонку сразу справа. Исходная карточка без id в своей позиции в `newCardIds` не копируется. Сохраняет WIP-лимит источника.     |
| `MOVE_COLUMN`           | `columnId`, `fromIndex` number, `toIndex` number                               | Переупорядочивает колонки с семантикой array-move.                                                                                       |
| `SORT_COLUMN`           | `columnId`, `sortBy` `"createdAt" \| "dueDate" \| "title"`                     | Сортирует карточки колонки по критерию. Перетаскивание возвращает ручной порядок.                                                        |
| `SET_COLUMN_CARD_ORDER` | `columnId`, `cardIds` string[]                                                 | Задаёт порядок карточек колонки напрямую. `cardIds` должна быть перестановкой текущих id, иначе команда игнорируется.                    |
| `SET_COLUMN_WIP_LIMIT`  | `columnId`, `wipLimit` number необязательно                                    | Задаёт WIP-лимит колонки; пропуск или `undefined` удаляет его.                                                                           |
| `ARCHIVE_COLUMN_CARDS`  | `columnId`                                                                     | Архивирует каждую карточку колонки за один шаг.                                                                                          |

### Карточки

| Действие            | Поля                                                                                                | Значение                                                                                                                                                   |
| ------------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ADD_CARD`          | `newCardId`, `columnId`, `title`, `labelIds` string[] необязательно, `atIndex` number необязательно | Создаёт карточку. `atIndex` обрезается до `[0, count]`; пропуск добавляет в конец. Прикрепляются только метки, существующие на доске.                      |
| `UPDATE_CARD`       | `cardId`, `title` необязательно, `description` необязательно, `quiet` boolean необязательно         | Частичный патч; задавайте только изменённые поля. `quiet` держит `updatedAt` тихим для правок в реальном времени по нажатию. Пустое описание удаляет поле. |
| `TOUCH_CARD`        | `cardId`                                                                                            | Фиксирует временную метку `updatedAt` после серии тихих правок.                                                                                            |
| `DELETE_CARD`       | `cardId`                                                                                            | Удаляет карточку.                                                                                                                                          |
| `ARCHIVE_CARD`      | `cardId`, `archivedAt` number необязательно                                                         | Архивирует карточку; `archivedAt` по умолчанию `at`.                                                                                                       |
| `UNARCHIVE_CARD`    | `cardId`, `columnId` необязательно, `index` необязательно                                           | Восстанавливает архивную карточку; `columnId` по умолчанию первая колонка, пропущенный `index` добавляет в конец. Уважает WIP-лимит.                       |
| `MOVE_CARD`         | `cardId`, `fromColumnId`, `fromIndex`, `toColumnId`, `toIndex`                                      | Перемещает карточку между колонками или внутри одной.                                                                                                      |
| `DUPLICATE_CARD`    | `cardId`, `newCardId`, `title` необязательно                                                        | Копирует карточку сразу под оригиналом, со свежими id и метками времени. Копия стартует без связей.                                                        |
| `SET_CARD_DUE_DATE` | `cardId`, `dueDate` number необязательно                                                            | Задаёт срок (Unix мс); `undefined` удаляет поле.                                                                                                           |
| `SET_CARD_PRIORITY` | `cardId`, `priority` `"blocker" \| "highest" \| "high" \| "medium" \| "low" \| "lowest"`            | Задаёт приоритет. `"medium"` это значение по умолчанию, оно удаляет поле.                                                                                  |
| `SET_CARD_ASSIGN`   | `cardId`, `assigneeId` string или null                                                              | Задаёт исполнителя; `null` или пустой id очищает. Сервер требует активного участника доски.                                                                |
| `SET_CARD_LABEL`    | `cardId`, `labelId`, `on` boolean, `index` необязательно                                            | Прикрепляет (`on: true`) или открепляет метку. Абсолютно, а не переключатель. Добавление ограничено `LIMITS.labelsPerCard` (20).                           |
| `SET_CARD_COVER`    | `cardId`, `cover` необязательно                                                                     | Задаёт обложку; `undefined` удаляет её. Обложка это `{ "type": "color", "value": ... }` или `{ "type": "gradient", "value": ... }`.                        |

### Метки

| Действие          | Поля                                            | Значение                                                                            |
| ----------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------- |
| `ADD_LABEL`       | `label` (полный `Label`: `{ id, name, color }`) | Добавляет метку. Игнорируется на дубликате id или при `LIMITS.labelsPerBoard` (50). |
| `RENAME_LABEL`    | `labelId`, `name`                               | Переименовывает метку. Пустое значение откатывается к текущему имени.               |
| `SET_LABEL_COLOR` | `labelId`, `color` (`LabelColor`)               | Задаёт цвет метки. Тот же цвет ничего не делает.                                    |
| `DELETE_LABEL`    | `labelId`                                       | Удаляет метку и открепляет её от каждой карточки.                                   |

| Действие                  | Поля                                              | Значение                                                                                  |
| ------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `ADD_CHECKLIST`           | `cardId`, `newChecklistId`, `title`               | Добавляет чек-лист. Игнорируется при `LIMITS.checklistsPerCard` (20) или на дубликате id. |
| `RENAME_CHECKLIST`        | `cardId`, `checklistId`, `title`                  | Переименовывает чек-лист.                                                                 |
| `DELETE_CHECKLIST`        | `cardId`, `checklistId`                           | Удаляет чек-лист.                                                                         |
| `ADD_CHECKLIST_ITEM`      | `cardId`, `checklistId`, `newItemId`, `text`      | Добавляет пункт. Игнорируется при `LIMITS.itemsPerChecklist` (100) или на дубликате id.   |
| `SET_CHECKLIST_ITEM_DONE` | `cardId`, `checklistId`, `itemId`, `done` boolean | Отмечает или снимает отметку пункта. Абсолютно, а не переключатель.                       |
| `RENAME_CHECKLIST_ITEM`   | `cardId`, `checklistId`, `itemId`, `text`         | Переименовывает пункт.                                                                    |
| `DELETE_CHECKLIST_ITEM`   | `cardId`, `checklistId`, `itemId`                 | Удаляет пункт.                                                                            |

### Связи

| Действие           | Поля                                                                                      | Значение                                                                                                                                                                                     |
| ------------------ | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ADD_CARD_LINK`    | `cardId`, `linkId`, `targetCardId`, `linkType` `"blocks" \| "relates_to" \| "duplicates"` | Добавляет строку связи на исходной карточке. Проверки: известные карточки, отсутствие самосвязи, одна связь на неупорядоченную пару, `LIMITS.linksPerCard` (50) и отсутствие цикла `blocks`. |
| `REMOVE_CARD_LINK` | `cardId`, `linkId`, `targetCardId`, `linkType`                                            | Удаляет одну строку связи. `targetCardId` и `linkType` избыточны относительно сохранённой строки, чтобы inverse был вычислим из одной команды.                                               |

### Восстановление и inverse

Они возвращают удалённые данные. Это единственные действия, освобождённые от
проверок коллекций и WIP. Редьюсер также помечает их `inverse` и
переопределениями временных меток только для inverse.

| Действие                 | Поля                                                             | Значение                                                                               |
| ------------------------ | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `RESTORE_CARD`           | `card` (`Card`), `columnId` необязательно, `index` необязательно | Возвращает удалённую карточку с её содержимым и позицией.                              |
| `RESTORE_COLUMN`         | `column` (`Column`), `index`, `cards` (`Card[]`)                 | Возвращает удалённую колонку с её карточками на прежнюю позицию.                       |
| `RESTORE_LABEL`          | `label` (`Label`), `index`, `assignments` необязательно          | Возвращает удалённую метку с её привязками к карточкам.                                |
| `RESTORE_CHECKLIST`      | `cardId`, `checklist` (`Checklist`), `index`                     | Возвращает удалённый чек-лист на его карточку.                                         |
| `RESTORE_CHECKLIST_ITEM` | `cardId`, `checklistId`, `item` (`ChecklistItem`), `index`       | Возвращает удалённый пункт чек-листа.                                                  |
| `RESTORE_COLUMN_CARDS`   | `columnId`, `cardIds` string[], `cards` (`Card[]`)               | Записывает `cards` обратно и задаёт порядок колонки. Inverse к `ARCHIVE_COLUMN_CARDS`. |

### Уровень доски

| Действие          | Поля            | Значение                                                                                                    |
| ----------------- | --------------- | ----------------------------------------------------------------------------------------------------------- |
| `RENAME_BOARD`    | `title`         | Переименовывает доску. Заголовок обрезается до `LIMITS.boardTitle` (100). Разрешено для `ADMIN` и `MEMBER`. |
| `ARCHIVE_BOARD`   | `boardId`, `at` | Архивирует доску. Только `ADMIN`; не-`ADMIN` отвечает `403`.                                                |
| `UNARCHIVE_BOARD` | `boardId`, `at` | Возвращает архивную доску. Только `ADMIN`; не-`ADMIN` отвечает `403`.                                       |

### Уровень агрегата (отклоняются эндпоинтом команд)

Эти четыре действия это создание, импорт и удаление доски. Они обрабатываются
REST (`POST /boards`, `POST /boards/import`, `DELETE /boards/:id`) и
отклоняются эндпоинтом команд с `400`:

| Действие        | Поля                                       |
| --------------- | ------------------------------------------ |
| `RESTORE_BOARD` | `board` (`Board`), `boardId` необязательно |
| `IMPORT_BOARDS` | `boards` (`BoardState`)                    |
| `ADD_BOARD`     | `board` (`Board`)                          |
| `REMOVE_BOARD`  | `boardId`                                  |

## Метки касаний

`touches` и кадр SSE используют эти метки, чтобы назвать сущности, которые
записала команда: `card:<id>`, `column:<id>`, `label:<id>`,
`checklist:<id>`, `checklistItem:<id>`, `board:<id>`. Пустой массив означает,
что команда ничего не изменила. Клиент использует `touches`, чтобы пометить
свою историю отмен чужой без сравнения всей доски.

## Вариант мастер-контура

API мастер-аккаунта предоставляет `POST /admin/boards/:id/commands` с той же
формой действия. Его тело это `AdminBoardCommandRequest`:
`{ commandId? string, action BoardAction }`. Он относится к отдельному
контуру мастер-аккаунта и выходит за рамки этой страницы.
