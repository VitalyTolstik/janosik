Панель администратора это поверхность оператора платформы. Она отдаётся по
адресу `/admin`, подгружается лениво поверх приложения и общается со своим
API-клиентом через свой токен. Она структурно отделена от пользовательского
приложения: дерево маршрутов админки никогда не монтирует пользовательские
`AuthProvider` или `BoardProvider`, и две сессии не могут протечь друг в друга.

## Кто может пользоваться панелью

Панель предназначена для мастер-аккаунтов, а не для обычных пользователей.
Мастер это `AdminUser`, отдельная таблица от `User`, и он входит через
`/api/v1/admin/auth/*` со своей аудиторией JWT (`janosik-admin`) и своим
refresh-cookie.

Мастера бывают двух уровней:

| Роль | Доступ к панели |
| --- | --- |
| `OWNER` | Полный доступ к данным плюс раздел мастеров и все владельческие настройки. |
| `OPERATOR` | Полный доступ к данным, но не может управлять мастерами и менять владельческие настройки. |

Владельческие настройки проверяются на сервере, а не только в интерфейсе.
Оператор, вызвавший такую настройку, получает `403` с текстом `Owner rights
are required`. В боковой панели пункты `Masters`, `Email service` и `OAuth
login` скрыты от операторов. На страницах настроек оператор видит состояние
только для чтения: лимит трафика, демо-запуск, настройки эксплуатации, запись
в коммуникациях, IP-список безопасности и очистку по сроку хранения доступны
только владельцу.

## Три способа создать мастера

Публичного HTTP-эндпоинта, создающего мастера, нет. Мастер-аккаунт появляется
одним из трёх путей.

### 1. Серверный CLI (bootstrap)

CLI это единственный способ создать первого мастера на чистой установке.
Запускайте из корня репозитория с установленными зависимостями backend и
файлом `backend/.env`:

```sh
npm run admin:create -w backend -- --email me@example.com
npm run admin:create -w backend -- --email me@example.com --display-name "Ops" --owner
npm run admin:passwd -w backend -- --email me@example.com
npm run admin:list   -w backend
```

- `create` приводит email к нижнему регистру и отклоняет неверный адрес.
  Первый мастер в пустой базе автоматически становится `OWNER`. Каждый
  следующий становится `OPERATOR`, если не передан `--owner`.
  `--display-name` необязателен.
- Пароль никогда не берётся из командной строки. Он запрашивается скрытым
  вводом с подтверждением либо читается из переменной окружения
  `ADMIN_PASSWORD` для автоматизации. Длина от 8 до 100 символов.
- `passwd` переустанавливает пароль существующего мастера, отзывает все его
  refresh-сессии и снимает блокировку.
- `list` печатает всех мастеров (email, роль, имя, последний вход, флаги
  blocked или locked). Секреты не показываются.
- CLI пишет строку аудита, поэтому создание или смена пароля видны в журнале
  аудита панели.

### 2. Панель (только владелец)

Владелец открывает `Masters` и нажимает `Add master`. Диалог принимает email,
необязательное имя (не более 50 символов) и флажок `Grant owner rights`,
который выбирает `OWNER` или `OPERATOR`. Сервер генерирует одноразовый пароль
и показывает его один раз.

### 3. Повышение существующего пользователя (только владелец)

Владелец открывает страницу пользователя и запускает `Promote to master`. Так
создаётся мастер `OPERATOR` с тем же email и новым временным паролем. Диалог
требует ввести email аккаунта для подтверждения. Если мастер с таким email уже
существует, запрос отвечает `409`.

## Как войти

Откройте `/admin`. Неаутентифицированный визит показывает экран входа мастера,
намеренно отличный от входа пользователя: без ссылки на регистрацию, без
восстановления пароля, без входа через соцсети.

- Форма отправляет `POST /admin/auth/login` с email и паролем плюс
  необязательный шестизначный код двухфакторной аутентификации.
- Сессия использует отдельный access-токен и отдельный refresh-cookie с именем
  `admin_refresh_token`, привязанный к пути `/api/v1/admin/auth` с
  `SameSite=Strict`. Пользовательские маршруты этот cookie не получают, а
  админский cookie не доходит до пользовательских маршрутов.
- Маршрут входа ограничен 10 попытками в минуту на IP.
- После 5 неудачных входов аккаунт блокируется на 15 минут. Заблокированный
  аккаунт отвечает `429`, и форма показывает `Account is temporarily locked`.
  Успешный вход сбрасывает счётчик и блокировку.
- Неизвестный email стоит столько же работы по хешу пароля, сколько неверный
  пароль, поэтому время ответа не выдаёт существование мастера.
- Отключённый аккаунт отклоняется после проверки пароля с `403`.
- Когда включена двухфакторная аутентификация, одного пароля недостаточно.
  Сервер отвечает `401` с `code: "totp_required"`, и форма показывает поле
  кода двухфакторной аутентификации. Код это шесть цифр из приложения
  аутентификатора.
- IP-список, если он задан для мастера, проверяется после пароля, поэтому
  атакующий не узнает список без верных учётных данных.
- Refresh-токены ротируются при каждом использовании. Повторное использование
  отозванного токена отзывает все сессии этого мастера.

Успешный вход ведёт на дашборд. Экран входа также несёт подсказку `Master
accounts are created on the server via the admin CLI.`

## Оболочка

Оболочка это фиксированная боковая панель плюс плотная область контента с
компактным масштабом шрифта.

### Разделы боковой панели

| Раздел | Пункты |
| --- | --- |
| Наблюдение | Дашборд, Активность, Журнал команд, Аудит |
| Люди | Пользователи, Мастера (только владелец) |
| Контент | Доски, Карточки, Колонки, Метки, Чек-листы, Связи карточек |
| Совместная работа | Комментарии, Вложения |
| Безопасность | Сессии, API-токены, Email-рассылка (только владелец), OAuth-вход (только владелец), Безопасность |
| Эксплуатация | Трафик и лимиты, Демо-запуск, Публичные ссылки, Эксплуатация, Коммуникации, Объявления, Наблюдаемость |

Верхняя панель показывает вошедшего пользователя и значок `Master` для
владельцев. Она также содержит переключатель боковой панели, кнопку поиска,
переключатель темы, переключатель языка, ссылку `Back to boards` и `Sign out`.

### Клавиши и предпочтения

- `Ctrl` или `Cmd` + `K` открывает омнибокс из любого места панели.
- `Ctrl` или `Cmd` + `B` сворачивает и разворачивает боковую панель. В свёрнутом
  виде это узкая рейка иконок, а выбор запоминается в `localStorage` под ключом
  `janosik.admin.sidebar`.
- Переключатель темы переключает светлую и тёмную темы.
- Переключатель языка переключает панель между английским и русским.

### Омнибокс

Омнибокс ищет пользователей, доски, карточки, комментарии, вложения и метки
одним запросом. Результаты сгруппированы и доступны с клавиатуры: стрелки
двигают выбор, Enter открывает выделенную строку. Открытие результата ведёт на
связанную страницу деталей. Поиск с задержкой идёт к `GET /admin/search?q=`.
