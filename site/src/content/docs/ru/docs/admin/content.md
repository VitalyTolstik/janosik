:::note
Доски, карточки, колонки, метки, чек-листы и связи — вкладки хаба **Доски**
(`/admin/boards?tab=…`). Комментарии и вложения — в **Модерации**, а сессии,
токены и публичные ссылки — в **Доступе и безопасности** и **Коммуникациях**.
Все старые URL перенаправляются. См. [Редизайн админки](../redesign/).
:::

Раздел контента предназначен для ежедневной модерации досок и связанных данных.
Здесь описаны списки досок, карточек, колонок, меток, чек-листов и связей, а
также страницы комментариев, файлов, сессий, токенов и публичных ссылок.

## Доски

`/admin/boards` перечисляет все доски. Подзаголовок: `{total} boards`.

| Колонка | Значение |
| --- | --- |
| Доска | название |
| Владелец | email владельца, со ссылкой на страницу пользователя |
| Создана | время создания |
| Обновлена | время последнего обновления |
| Статус | `Active`, `Archived` или `Deleted` |

На странице есть поле поиска, вкладки статуса (все, активные, архивные,
удалённые), постраничная навигация, кнопка `Create board` и групповой выбор.

### Создание доски

Диалог `Create board` принимает название и email владельца. Владелец становится
`ADMIN` доски. Если пользователь с указанным адресом не найден, сервер возвращает `404`.

### Действия в строке

| Действие | Эффект | Примечания |
| --- | --- | --- |
| Edit content | открывает редактор контента доски | переход на страницу редавтора действия |
| Archive | выставляет `archivedAt` | с подтверждением; доска становится только для чтения для участников |
| Restore | снимает `archivedAt` | показано, когда доска в архиве |
| Delete | мягко удаляет доску | разрушительное, с подтверждением; очищается по истечении срока хранения |

### Групповые действия

При выбранных строках появляется панель с `N selected (M on this page)`,
`Delete selected`, `Restore selected` и `Clear`. Выбор сохраняется между
страницами: строки, отмеченные на странице 1, остаются выбранными после
перехода на страницу 2, а действие применяется ко всем сохранённым ID —
счётчик, подтверждение и запрос используют один и тот же набор. Смена поиска,
статуса, периода или размера страницы очищает выбор, потому что эти элементы
меняют набор строк под ним. Один групповой запрос ограничен 500 ID; при
большем выборе панель показывает сообщение и не обрезает список молча.
Групповое удаление требует подтверждения и не поддерживает обычную отмену.
Если сервер отказал части строк, выбранными остаются ровно они — для повтора.
Мягко удалённые записи можно восстановить до окончательной очистки. При
удалении колонки её карточки тоже помечаются удалёнными; восстановление
колонки возвращает их.

## Страница доски

`/admin/boards/:id` показывает сведения о доске, актуальные счётчики, участников, колонки
и метки.

- В заголовке показаны название, email владельца, кнопка `Edit content` и меню
  действий с архивом, восстановлением и удалением.
- В строке основных сведений указаны владелец, время создания, последнего обновления и версия (`Version`).
- Показаны девять счётчиков: Участники, Колонки, Карточки, Метки, Связи,
  Комментарии, Файлы, Команды и События.

### Участники

| Колонка | Значение |
| --- | --- |
| Участник | email пользователя, со ссылкой, со значком `Disabled`, когда пользователь заблокирован |
| Роль | роль участника |
| Принято | время принятия или значок `Pending` |
| Истекает | срок или прочерк |
| Пригласил | email пригласившего или прочерк |
| Действия | меню участника |

`Add member` открывает диалог с email пользователя и выбором роли (`MEMBER`,
`ADMIN`, `VIEWER`). Членство, добавленное мастером, действует сразу, поэтому
оно принято немедленно и не имеет пригласившего.

Меню участника предлагает:

| Действие | Эффект |
| --- | --- |
| Change role | две роли, отличные от текущей, каждая отдельным пунктом |
| Make owner | передаёт владение доской этому участнику |
| Remove member | удаляет членство |

Новый владелец должен быть участником, принявшим приглашение. Он получает роль
`ADMIN`, а остальные администраторы — роль `MEMBER`.

### Колонки и метки

Таблица колонок показывает Колонку, Позицию, WIP-лимит, Карточки и Статус.
Панель меток показывает каждую метку цветным чипом.

## Редактор контента доски

`/admin/boards/:id/content` редактирует колонки и карточки, не покидая панель.

- Левая панель перечисляет колонки со счётчиком карточек. У каждой колонки есть
  элементы переименования и удаления; поле внизу добавляет колонку.
- Правая панель перечисляет карточки выбранной колонки. У каждой карточки есть
  элементы переименования и архивирования; поле внизу добавляет карточку.
- Кнопка ручного обновления находится в заголовке.
- Страница обновляет данные доски каждые 2 секунды, пока открыта и находится в
  фокусе. За работой демонстрационного сценария можно следить прямо здесь.

Каждое изменение отправляется как команда доски через
`POST /admin/boards/:id/commands` от имени владельца доски, первого принятого
`ADMIN`. Сервер заново проверяет каждое действие общим строгим валидатором,
поэтому отказ (WIP-лимит, ограничение размера) отображается уведомлением и ничего не
меняет. Редактор отправляет `ADD_COLUMN`, `ADD_CARD`, `RENAME_COLUMN`,
`UPDATE_CARD`, `ARCHIVE_CARD` и `DELETE_COLUMN`, каждое с отметкой времени
команды. Журнал команд, версии и интерфейс доски остаются согласованными.

Удаление колонки — мягкое удаление: колонка и её карточки исчезают для
участников. Диалог подтверждения сообщает это.

### Рабочий процесс

На странице деталей доски есть панель `Рабочий процесс` с текущим состоянием
(включён/выключен, число переходов) и кнопкой `Открыть редактор процесса`.
Редактор тот же, что у администратора доски; здесь он открывается по адресу
`/admin/boards/:id/workflow` и сохраняет через `POST
/admin/boards/:id/commands` от имени владельца доски. Журнал команд, версии и
живые обновления доски сохраняются, а действие мастера попадает в
`AdminAuditLog` как запись `board.command`.

Изменения проверяются так же, как в редакторе доски: форма, существующие
колонки, минимум две колонки и хотя бы один активный переход при включённом
контроле. Страница показывает баннер «действуете от имени владельца» и сама не
обходит правила процесса.

## Карточки

`/admin/cards` перечисляет каждую карточку на платформе. Подзаголовок: `{total}
cards across every board`.

| Колонка | Значение |
| --- | --- |
| Карточка | название, со ссылкой на страницу карточки, усечённое, полный текст при наведении |
| Доска | название доски, со ссылкой |
| Колонка | название колонки |
| Комментарии | число видимых комментариев |
| Приоритет | значок приоритета или прочерк |
| Исполнитель | email исполнителя, со ссылкой, или прочерк |
| Срок | дедлайн или прочерк |
| Обновлено | время последнего обновления |
| Статус | `Active`, `Archived` или `Deleted` |

На странице есть поле поиска, вкладки статуса, постраничная навигация и
групповой выбор.

Действия в строке: `Archive` (с подтверждением), `Restore` (когда в архиве) и
`Delete` (разрушительное, с подтверждением).

## Страница карточки

`/admin/cards/:id` показывает карточку и связанные с ней записи. В заголовке указаны название,
подзаголовок `board · column` и меню действий с архивом, восстановлением и
удалением. Показаны значок статуса, значок приоритета и чип срока.

### Основные сведения

| Поле | Значение |
| --- | --- |
| Доска | название доски, со ссылкой |
| Колонка | название колонки |
| Создана | время создания |
| Обновлена | время последнего обновления |
| Version | версия карточки |
| Создал | выведено из первой команды добавления карточки, или прочерк |
| Исполнитель | исполнитель, со ссылкой, или прочерк |
| Последнее изменение | метка последнего автора действия или прочерк |

Автор карточки не хранится в отдельном поле. Значение `Создал` определяется по первой команде
`ADD_CARD` или `DUPLICATE_CARD`, в payload которой указана эта карточка. Для
карточек, импортированных до журнала команд, стоит прочерк.

### Разделы

- Описание, когда есть, показано как предформатированный текст.
- Метки, цветными чипами.
- Чек-листы, каждый с названием, счётчиком `done/total` и неудалёнными пунктами.
- Связи в обоих направлениях: исходящие со стрелкой вверх-вправо и входящие со
  стрелкой вниз-влево, каждая со значком типа и значком `Deleted`, когда
  применимо. Типы: `blocks`, `relates_to` и `duplicates`.
- Таблица вложений: Файл (миниатюра, имя, скачивание), Размер, Загрузил,
  Создано, Статус.
- Таблица комментариев: Комментарий, Автор, Создан, Статус.
- Таймлайн, объединённая лента строк активности и команд, каждая со значком
  типа, email автора действия, деталями в виде JSON и временем.

Комментарии, вложения и таймлайн — это окна, а не полные списки. В подвале
каждого блока показано `50 из N`, а пока `N` больше, доступна кнопка
`Показать ещё`. Общее число комментариев — точное число живых комментариев
(`Card.commentIds`); общее число вложений считает живые строки, показанные в
блоке, включая файлы, встроенные в описание (значок `attachmentCount` на
карточке учитывает только не встроенные файлы); общее число таймлайна —
точная сумма строк активности и команд, затронувших карточку. Комментарии и вложения по умолчанию показывают только
живые строки; `Показать удалённые (N)` добавляет удалённые. Если результат поиска указывает
на конкретный комментарий или вложение, ссылка использует `?comment=<id>` или
`?attachment=<id>`; страница карточки центрирует блок на этой строке,
подсвечивает её и предлагает `Показать с начала`. Удалённая цель тоже
открывается: блок с якорем включает удалённые строки. Окно блока
останавливается на 5 000 строк; для более глубокой истории используйте списки
«Команды» и «Активность» с поиском по id карточки.

## Вложения

`/admin/attachments` перечисляет файлы, загруженные в карточки. Подзаголовок:
`Files uploaded to cards`.

| Колонка | Значение |
| --- | --- |
| Файл | миниатюра, имя файла и элемент скачивания |
| Карточка | название карточки, со ссылкой |
| Размер | размер файла |
| Тип | MIME-тип |
| Encode | состояние транскодинга видео: `none`, `pending`, `done` или `failed` |
| Загрузил | email загрузившего, со ссылкой |
| Создан | время создания |
| Статус | `Active` или `Deleted` |

На странице есть поле поиска, вкладки статуса, постраничная навигация и
групповой выбор.

Действия в строке:

- `Delete file` (если запись не удалена): мягко удаляет вложение. Диалог
  подтверждения предупреждает, что файл удаляется из хранилища. Затем строка
  показывает `Restore`, а после истечения срока хранения файл окончательно удаляется из хранилища.
- `Restore` (когда строка удалена): снимает `deletedAt`, и файл снова доступен для скачивания.

## Сессии

`/admin/sessions` перечисляет активные refresh-сессии по всем пользователям.
Подзаголовок: `{total} active sessions`. Перечисляются только сессии, которые
не отозваны и не истекли.

| Колонка | Значение |
| --- | --- |
| Пользователь | email пользователя, со ссылкой |
| Начата | время создания |
| Истекает | время истечения |
| IP | IP сессии или прочерк |
| Клиент | user agent или прочерк |
| Сессия | id сессии в виде чипа с копированием |

На странице есть поле поиска, вкладки периода и постраничная навигация.
Действие в строке `Revoke session` отзывает эту одну сессию; остальные сессии остаются активными.

## API-токены

`/admin/tokens` перечисляет персональные API-токены по всем пользователям.
Подзаголовок: `{total} personal tokens`.

| Колонка | Значение |
| --- | --- |

| Создан | время создания |

## Публичные ссылки

`/admin/shares` — список публичных ссылок только для чтения на доски платформы.
Подзаголовок: `Read-only board links minted against any board, inspect and
revoke.`

| Колонка | Значение |
| --- | --- |
| Доска | название доски, со ссылкой, с путём `/s/<token>` ниже; значок `board gone`, когда доска удалена или в архиве |
| Режим | `Live` или `Snapshot` |
| Флаги | `comments` и `attachments`, когда включены, иначе прочерк |
| Просмотры | число просмотров |
| Создана | время создания |
| Действия | копировать, открыть и отозвать |

Можно искать по названию доски, токену или ID доски. Для каждой ссылки доступны действия:

- `Copy` копирует полный URL ссылки.
- `Open` открывает ссылку в новой вкладке.
- `Revoke` отзывает активную ссылку; отозванная ссылка показывает значок
  `revoked`.

После удаления доски её ссылки `Live` автоматически отзываются. Ссылки на снимки
(`Snapshot`) остаются доступны, поскольку сохраняют состояние доски на момент
создания.
