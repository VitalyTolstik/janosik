Доски, карточки, колонки, метки, чек-листы и связи — вкладки хаба **Доски**
(`/app/admin/boards?tab=…`). Комментарии и вложения — в **Модерации**, а сессии,
токены и публичные ссылки — в **Доступе и безопасности** и **Коммуникациях**.
Все старые URL перенаправляются. См. [Редизайн админки](../redesign/).
:::

Раздел контента предназначен для ежедневной модерации досок и связанных данных.
Здесь описаны списки досок, карточек, колонок, меток, чек-листов и связей, а
также страницы комментариев, файлов, сессий, токенов и публичных ссылок.

## Доски

`/app/admin/boards` перечисляет все доски. Подзаголовок: `{total} boards`.

| Колонка | Значение |
| --- | --- |
| Доска | название |
| Владелец | email владельца, со ссылкой на страницу пользователя |
| Создана | время создания |
| Обновлена | время последнего обновления |
| Статус | `Active`, `Archived` или `Deleted` |

На странице есть поле поиска, вкладки статуса (все, активные, архивные,
удалённые), постраничная навигация, кнопка `Create board` и групповой выбор.

Кнопка `Фильтры` предлагает `Администратор доски`. Фильтр совпадает с точным id
пользователя, который является принятым `ADMIN`; это не колонка «Владелец».
Два принятых ADMIN совпадают оба, а `MEMBER`, `VIEWER` и ожидающее приглашение —
нет.

### Создание доски

Диалог `Create board` принимает название и email владельца. Владелец становится
`ADMIN` доски. Если пользователь с указанным адресом не найден, сервер возвращает `404`.

### Действия в строке

| Действие | Эффект | Примечания |
| --- | --- | --- |
| Edit content | открывает редактор контента доски | переход на страницу редавтора действия |
| Archive | выставляет `archivedAt` | с подтверждением; доска становится только для чтения для участников |
| Restore | снимает `archivedAt` | показано, когда доска в архиве |
| Delete | мягко удаляет доску | разрушительное, с подтверждением; очищается по истечении срока хранения |

### Групповые действия

При выбранных строках появляется панель с `N selected (M on this page)`,
`Delete selected`, `Restore selected` и `Clear`. Выбор сохраняется между
страницами: строки, отмеченные на странице 1, остаются выбранными после
перехода на страницу 2, а действие применяется ко всем сохранённым ID —
счётчик, подтверждение и запрос используют один и тот же набор. Смена поиска,
статуса, периода или размера страницы очищает выбор, потому что эти элементы
меняют набор строк под ним. Один групповой запрос ограничен 500 ID; при
большем выборе панель показывает сообщение и не обрезает список молча.
Групповое удаление требует подтверждения и не поддерживает обычную отмену.
Если сервер отказал части строк, выбранными остаются ровно они — для повтора.
Мягко удалённые записи можно восстановить до окончательной очистки. При
удалении колонки её активные карточки мягко удаляются, но сохраняют
`columnId` удалённой колонки; восстановление колонки возвращает их. Архивные
карточки ведут себя иначе: `DELETE_COLUMN` переносит их во внутреннюю
мягко удалённую колонку `orphan:<boardId>`, чтобы исходную колонку можно было
окончательно очистить. Такие архивные orphan-карточки остаются видимыми и
редактируемыми по полям на `/app/admin/cards/:id`, но перемещение отклоняется,
потому что архивные карточки перемещать нельзя.

## Страница доски

`/app/admin/boards/:id` показывает сведения о доске, актуальные счётчики, участников, колонки
и метки.

- В заголовке показаны название, email владельца, кнопка `Edit content` и меню
  действий с архивом, восстановлением и удалением.
- В строке основных сведений указаны владелец, время создания, последнего обновления и версия (`Version`).
- Показаны девять счётчиков: Участники, Колонки, Карточки, Метки, Связи,
  Комментарии, Файлы, Команды и События. Карточки, Комментарии, Файлы, Команды
  и События — ссылки на соответствующий список с точным `boardId` этой доски;
  числа участников, колонок, меток и связей остаются обычными счётчиками.

### Участники

| Колонка | Значение |
| --- | --- |
| Участник | email пользователя, со ссылкой, со значком `Disabled`, когда пользователь заблокирован |
| Роль | роль участника |
| Принято | время принятия или значок `Pending` |
| Истекает | срок или прочерк |
| Пригласил | email пригласившего, со ссылкой на профиль, или прочерк |
| Действия | меню участника |

`Add member` открывает диалог с email пользователя и выбором роли (`MEMBER`,
`ADMIN`, `VIEWER`). Членство, добавленное мастером, действует сразу, поэтому
оно принято немедленно и не имеет пригласившего.

Меню участника предлагает:

| Действие | Эффект |
| --- | --- |
| Change role | две роли, отличные от текущей, каждая отдельным пунктом |
| Make owner | передаёт владение доской этому участнику |
| Remove member | удаляет членство |

Новый владелец должен быть участником, принявшим приглашение. Он получает роль
`ADMIN`, а остальные администраторы — роль `MEMBER`.

### Колонки и метки

Таблица колонок показывает Колонку, Позицию, WIP-лимит, Карточки и Статус.
Панель меток показывает каждую метку цветным чипом. Название колонки или число
карточек открывает список карточек с точным `columnId`; чип метки — список с
`labelId`. Обе ссылки сохраняют страницу доски как путь возврата.

## Редактор контента доски

`/app/admin/boards/:id/content` редактирует колонки и карточки, не покидая панель.

- Левая панель перечисляет колонки со счётчиком карточек. У каждой колонки есть
  элементы переименования и удаления; поле внизу добавляет колонку.
- Правая панель перечисляет карточки выбранной колонки. У каждой карточки есть
  элементы переименования, перемещения и архивирования; поле внизу добавляет
  карточку. Диалог перемещения добавляет карточку в конец другой колонки и
  исключает текущую колонку из списка назначения. Название карточки ведёт на
  `/app/admin/cards/:id`, а кнопка «назад» на странице карточки возвращает в этот
  редактор.
- Кнопка ручного обновления находится в заголовке.
- Страница обновляет данные доски каждые 2 секунды, пока открыта и находится в
  фокусе. За работой демонстрационного сценария можно следить прямо здесь.

Каждое изменение отправляется как команда доски через
`POST /api/v1/admin/boards/:id/commands` от имени владельца доски, первого принятого
`ADMIN`. Сервер заново проверяет каждое действие общим строгим валидатором,
поэтому отказ (WIP-лимит, ограничение размера) отображается уведомлением и ничего не
меняет. Диалог перемещения перепроверяет снимок перед отправкой: если карточка
покинула исходную колонку или целевая колонка исчезла, показывается сообщение с
просьбой перезагрузить. Свежее серверное перемещение с устаревшей исходной
колонкой (включая неархивную карточку в удалённой/orphan-колонке) отклоняется
как `409 conflict: "version"`; отсутствующая, удалённая или чужая целевая
колонка — `404`, в обоих случаях до записи команды и аудита.
Точный повтор сохранённого `commandId` по-прежнему возвращает сохранённый
результат. Редактор отправляет `ADD_COLUMN`, `ADD_CARD`, `RENAME_COLUMN`,
`UPDATE_CARD`, `MOVE_CARD`, `ARCHIVE_CARD` и `DELETE_COLUMN`, каждое с отметкой
времени команды. Журнал команд, версии и интерфейс доски остаются
согласованными.

Перемещение и редактирование описания показывают явный баннер «Вы действуете
от имени владельца доски; это изменение появится в истории доски как действие
владельца». История доски и журнал команд сохраняют владельца как актора;
журнал аудита записывает мастера (`masterId`, `masterEmail`) и общий
`commandId`.

Удаление колонки — мягкое удаление: активные карточки исчезают для участников
и сохраняют `columnId` до восстановления или очистки колонки. Архивные
карточки переносятся во внутреннюю мягко удалённую колонку `orphan:<boardId>`;
они остаются видимыми и редактируемыми по полям на `/app/admin/cards/:id`, а
перемещение отклоняется с архивным `409`. Диалог подтверждения сообщает о
мягком удалении.

### Рабочий процесс

На странице деталей доски есть панель `Рабочий процесс` с текущим состоянием
(включён/выключен, число переходов) и кнопкой `Открыть редактор процесса`.
Редактор тот же, что у администратора доски; здесь он открывается по адресу
`/app/admin/boards/:id/workflow` и сохраняет через `POST
/api/v1/admin/boards/:id/commands` от имени владельца доски. Журнал команд, версии и
живые обновления доски сохраняются, а действие мастера попадает в
`AdminAuditLog` как запись `board.command`.

Изменения проверяются так же, как в редакторе доски: форма, существующие
колонки, минимум две колонки и хотя бы один активный переход при включённом
контроле. Страница показывает баннер «действуете от имени владельца» и сама не
обходит правила процесса.

## Карточки

`/app/admin/cards` перечисляет каждую карточку на платформе. Подзаголовок: `{total}
cards across every board`.

| Колонка | Значение |
| --- | --- |
| Карточка | название, со ссылкой на страницу карточки, усечённое, полный текст при наведении |
| Доска | название доски, со ссылкой |
| Колонка | название колонки |
| Комментарии | число видимых комментариев |
| Приоритет | значок приоритета или прочерк |
| Исполнитель | email исполнителя, со ссылкой, или прочерк |
| Срок | дедлайн или прочерк |
| Обновлено | время последнего обновления |
| Статус | `Active`, `Archived` или `Deleted` |

На странице есть поле поиска, вкладки статуса и периода, постраничная навигация
и групповой выбор.

Кнопка `Фильтры` и её чипы сужают список по:

| Грань | Значения | Примечания |
| --- | --- | --- |
| Доска | один точный id доски | |
| Колонка | один точный id колонки | |
| Метка | один или несколько id меток и **Любая метка** / **Все метки** | «Все» требует каждую выбранную метку |
| Исполнитель | один или несколько id пользователей и `Без исполнителя` | `Без исполнителя` объединяется с выбранными через OR |
| Приоритет | `Блокирующий`, `Наивысший`, `Высокий`, `Средний`, `Низкий`, `Наименьший` | `Средний` включает карточки без приоритета |
| Срок | `Просрочено`, `Срок в течение 24 часов`, `Без срока` | те же границы, что в фильтре доски |
| Файлы карточки | `С файлами карточки`, `Без файлов карточки` | только файлы карточки; встроенные и `descriptionDetached` не считаются |

Вкладки периода применяются к `createdAt` (любое время, 24 часа, 7 дней,
30 дней). Точный id карточки по-прежнему доступен как глубокий ссылочный
фильтр (`?cardId=<id>`) для поддержки и перехода из поиска.

Действия в строке: `Archive` (с подтверждением), `Restore` (когда в архиве) и
`Delete` (разрушительное, с подтверждением).

## Страница карточки

`/app/admin/cards/:id` показывает карточку и связанные с ней записи. В заголовке указаны название,
подзаголовок `board · column` и меню действий с архивом, восстановлением и
удалением. Показаны значок статуса, значок приоритета и чип срока.

### Основные сведения

| Поле | Значение |
| --- | --- |
| Доска | название доски, со ссылкой |
| Колонка | название колонки |
| Создана | время создания |
| Обновлена | время последнего обновления |
| Version | версия карточки |
| Создал | выведено из первой команды добавления карточки, или прочерк |
| Исполнитель | исполнитель, со ссылкой, или прочерк |
| Последнее изменение | последний автор действия, со ссылкой на профиль, или прочерк/id удалённого пользователя |

Автор карточки не хранится в отдельном поле. Значение `Создал` определяется по первой команде
`ADD_CARD` или `DUPLICATE_CARD`, в payload которой указана эта карточка. Для
карточек, импортированных до журнала команд, стоит прочерк.

### Свойства

У неудалённых карточек есть компактная панель `Свойства`: название,
исполнитель, срок, приоритет, обложка и метки. Каждое сохранённое изменение —
отдельная команда: `UPDATE_CARD`, `SET_CARD_ASSIGN`, `SET_CARD_DUE_DATE`,
`SET_CARD_PRIORITY`, `SET_CARD_COVER` или одна `SET_CARD_LABEL` на каждую
переключённую метку. Команда получает новый `commandId` и тот же баннер
атрибуции владельцу. Неизменённые значения не отправляются. У архивных
карточек панель остаётся, потому что их поля можно редактировать; у удалённых
она скрыта.

Снятие исполнителя отправляет `assigneeId: null`; очистка срока или обложки
опускает поле. Приоритет `medium` — значение по умолчанию, поэтому хранится как
отсутствующее. В списке исполнителей только принятые участники с действующим
членством; отключённые пользователи скрыты из новых вариантов для удобства
(текущий отключённый исполнитель остаётся видимым как выбранное значение), хотя
сервер всё ещё принял бы активное членство. В метках только живые метки доски,
максимум 20 на карточку.

### Чек-листы и связи

У неудалённых карточек рядом с редактором свойств есть панель
`Чек-листы и связи`. Она показывает тот же баннер атрибуции владельцу и
отправляет отдельную свежую команду на каждое изменение:

| Изменение | Команда |
| --- | --- |
| Добавить, переименовать или удалить чек-лист | `ADD_CHECKLIST`, `RENAME_CHECKLIST`, `DELETE_CHECKLIST` |
| Добавить, переключить, переименовать или удалить пункт | `ADD_CHECKLIST_ITEM`, `SET_CHECKLIST_ITEM_DONE`, `RENAME_CHECKLIST_ITEM`, `DELETE_CHECKLIST_ITEM` |
| Добавить или убрать связь карточек | `ADD_CARD_LINK`, `REMOVE_CARD_LINK` |

На карточку можно добавить не больше 20 чек-листов, в чек-лист — не больше
100 пунктов; сервер также отклоняет свежее добавление на этом лимите с
`409 conflict: "wip"` до записи команды и строки аудита. Удалённые чек-листы и
пункты в редакторе не показываются. Удаление чек-листа требует подтверждения.
Связи показываются в обоих направлениях с сохранённым типом и читаемой
формулировкой: исходящая `blocks` читается как «блокирует», входящая — как
«заблокирована» (та же обратная формулировка доступна при добавлении: связана
с, блокирует, заблокирована, дублирует, дублируется). Счётчики разделяют
живые исходящие строки просматриваемой карточки (её лимит 50) и живые входящие
строки; живая входящая строка с удалённой карточкой-владельцем остаётся
читаемой как висячая, но не считается. При обратном варианте формы
показывается собственный счётчик и лимит
выбранной карточки-владельца. Входящая связь удаляется через
карточку-владельца строки, а не через просматриваемую. Список целевых карточек
загружается лениво из контента доски при открытии редактора и исключает
текущую карточку, архивные и уже связанные пары; `blocks`-связь, создающая
цикл, отклоняется. Команды чек-листов и пунктов не перезагружают доску и не
закрывают редактор связи. Обе команды связей перезагружают агрегат:
`ADD_CARD_LINK` закрывает редактор после успеха, а `REMOVE_CARD_LINK` оставляет
его открытым. Висячие и мягко
удалённые строки связей остаются читаемыми, а живую висячую строку можно
убрать, чтобы освободить лимит.

Удалённые карточки скрывают редактор. У архивных карточек чек-листы и связи
редактируются; заблокировано только перемещение архивной карточки. Каждое
принятое изменение даёт строку аудита `board.command` с `commandId`,
`masterId` и `masterEmail`, а история доски по-прежнему называет владельца.
Отклонённая свежая запись не создаёт команду и строку аудита.

### Разделы

- Описание, когда есть, показано как предформатированный текст. Меню
  «Действия» карточки открывает `Редактировать описание`, которое отправляет
  команду `UPDATE_CARD` через тот же баннер атрибуции владельцу и журнал
  команд, что и редактор контента.
- Метки, цветными чипами.
- Чек-листы, каждый с названием, счётчиком прогресса `done/total`,
  неудалёнными пунктами и встроенными действиями добавления, переименования,
  переключения и удаления.
- Связи в обоих направлениях: исходящие со стрелкой вверх-вправо и входящие со
  стрелкой вниз-влево, каждая с сохранённым типом `blocks`, `relates_to` или
  `duplicates`, читаемой формулировкой связи, значком `Deleted` для мягко
  удалённой строки и значком `Карточка удалена` для висячей цели.
- Таблица вложений: Файл (миниатюра, имя, скачивание), Размер, Загрузил,
  Создано, Статус, Действия.
- Таблица комментариев: Комментарий, Автор (со ссылкой), Создан, Статус,
  Действия.
- Таймлайн, объединённая лента строк активности и команд, каждая со значком
  типа, email автора со ссылкой на профиль, деталями в виде JSON и временем.
  У команды, отправленной из панели, есть ссылка `Аудит` на точную строку
  аудита; у обычных пользовательских команд ссылки нет.

Комментарии, вложения и таймлайн — это окна, а не полные списки. В подвале
каждого блока показано `50 из N`, а пока `N` больше, доступна кнопка
`Показать ещё`. Общее число комментариев — точное число живых комментариев
(`Card.commentIds`); общее число вложений считает живые строки, показанные в
блоке, включая файлы, встроенные в описание (значок `attachmentCount` на
карточке учитывает только не встроенные файлы); общее число таймлайна —
точная сумма строк активности и команд, затронувших карточку. Комментарии и вложения по умолчанию показывают только
живые строки; `Показать удалённые (N)` добавляет удалённые. Если результат поиска указывает
на конкретный комментарий или вложение, ссылка использует `?comment=<id>` или
`?attachment=<id>`; страница карточки центрирует блок на этой строке,
подсвечивает её и предлагает `Показать с начала`. Удалённая цель тоже
открывается: блок с якорем включает удалённые строки. Окно блока
останавливается на 5 000 строк; для более глубокой истории используйте списки
«Команды» и «Активность» с поиском по id карточки.

Меню «Действия» у живого комментария или вложения удаляет одну строку
(с подтверждением; запись попадает в аудит). После этого блок перезагружается
с удалёнными строками, поэтому затронутая строка остаётся видимой со значком
`Deleted`, а не исчезает.

становится невидим для участников.

## Вложения

`/app/admin/attachments` перечисляет файлы, загруженные в карточки. Подзаголовок:
`Files uploaded to cards`.

| Колонка | Значение |
| --- | --- |
| Файл | миниатюра, имя файла и элемент скачивания |
| Карточка | название карточки, со ссылкой |
| Размер | размер файла |
| Тип | MIME-тип |
| Encode | состояние транскодинга видео: `none`, `pending`, `done` или `failed` |
| Загрузил | email загрузившего, со ссылкой |
| Создан | время создания |
| Статус | `Active` или `Deleted` |

На странице есть поле поиска, вкладки статуса и периода, постраничная навигация
и групповой выбор. Кнопка `Фильтры` предлагает:

| Грань | Значения | Примечания |
| --- | --- | --- |
| Доска | один точный id доски | |
| Карточка | один точный id карточки | |
| Кто загрузил | один точный id пользователя | |
| Тип файла | `Изображения`, `Видео`, `PDF`, `Документы`, `Другое` | сравнение с сохранённым MIME-типом без учёта регистра |
| Обработка видео | `Обработка: в очереди`, `Обработка: ошибка`, `Обработка: готово`, `Без перекодирования` | `Без перекодирования` — не-видео и видео с отключённой перекодировкой |

Вкладки периода применяются к `createdAt`. Изображения и видео совпадают по
префиксу MIME, PDF — по `application/pdf`, «Документы» включают `text/*`, RTF и
старые/Open XML форматы Office. «Другое» — остальные типы, включая JSON, аудио и
архивы. Вкладка показывает встроенные строки с бейджем `Встроено`, а
отсоединённые файлы описания — с бейджем `Отсоединено`; отдельного фильтра для
встроенных в этой версии нет. Фильтр карточки `С файлами карточки` считает
только файлы карточки, поэтому карточка только со встроенными файлами может
появиться здесь при активном чипе `Без файлов карточки`.

Действия в строке:

- `Delete file` (если запись не удалена): мягко удаляет вложение. Диалог
  подтверждения объясняет, что файл скрывается с карточки и его можно
  восстановить. Затем строка показывает `Restore`, а после истечения срока
  хранения файл окончательно удаляется из хранилища.
- `Restore` (когда строка удалена): снимает `deletedAt`, и файл снова доступен для скачивания.

## Публичные ссылки

`/app/admin/shares` — список публичных ссылок только для чтения на доски платформы.
Подзаголовок: `Read-only board links minted against any board, inspect and
revoke.`

| Колонка | Значение |
| --- | --- |
| Доска | название доски, со ссылкой, с путём `/s/<token>` ниже; значок `board gone`, когда доска удалена или в архиве |
| Режим | `Live` или `Snapshot` |
| Флаги | `comments` и `attachments`, когда включены, иначе прочерк |
| Просмотры | число просмотров |
| Создана | время создания |
| Действия | копировать, открыть и отозвать |

Можно искать по названию доски, токену или ID доски. Для каждой ссылки доступны действия:

- `Copy` копирует полный URL ссылки.
- `Open` открывает ссылку в новой вкладке.
- `Revoke` отзывает активную ссылку; отозванная ссылка показывает значок
  `revoked`.

После удаления доски её ссылки `Live` автоматически отзываются. Ссылки на снимки
(`Snapshot`) остаются доступны, поскольку сохраняют состояние доски на момент
создания.
