:::note
Дашборд — это хаб **Обзор** (`/app/admin`). Лента активности, журнал команд и аудит
теперь вкладки хаба **Аудит и активность** (`/app/admin/audit?tab=…`). Старые URL
`/app/admin/activity` и `/app/admin/commands` перенаправляются. Полная карта — в
[Редизайне админки](../redesign/).
:::

Раздел наблюдения отвечает на два вопроса: что происходит на платформе прямо
сейчас и что делали мастера и пользователи. Раздел включает четыре страницы:
дашборд, лента активности, журнал команд и журнал аудита.

## Дашборд

Дашборд — главная страница панели по адресу `/app/admin`. Для загрузки данных
отправляются два запроса: `GET /api/v1/admin/metrics` и небольшой `GET
/api/v1/admin/audit?limit=8`. Страница
состоит из трёх частей.

### Карточки статистики

| Карточка | Значение | Подсказка |
| --- | --- | --- |
| Пользователи | всего пользователей | `+N за 7 дней` |
| Заблокированы | пользователи с `disabledAt` | нет |
| Активные доски | доски не удалённые и не архивные | `N в архиве` |
| Активные карточки | карточки не удалённые и не архивные | `N в архиве` |
| Команды, 24 ч | команды за последние 24 часа | `N за 7 дней` |
| Активные сессии | живые refresh-сессии | нет |
| Комментарии | комментарии не удалённые | нет |
| Мастер-аккаунты | всего мастеров | нет |

### Состояние сервера

В этом блоке показаны четыре значения из `AdminMetricsDto.runtime`:

| Метка | Значение |
| --- | --- |
| Version | версия пакета backend |
| Uptime | время работы процесса, в формате `Nh Nm` или `Nm Ns` |
| Database | время выполнения `SELECT 1` с учётом обмена с базой данных, в миллисекундах |
| Environment | `NODE_ENV` |

Два графика показывают данные за последние 14 дней, от старых к новым: регистрации за

## Лента активности

`/app/admin/activity` перечисляет изменения членства и события комментариев по
доскам. Подзаголовок: `Membership changes and comment events`.

| Колонка | Значение |
| --- | --- |
| Событие | `type` активности |
| Автор действия | email автора действия, со ссылкой на страницу пользователя |
| Доска | название доски, со ссылкой на страницу доски |
| Карточка | название карточки, со ссылкой на страницу карточки, или прочерк |
| Детали | payload события в виде JSON |
| Когда | время создания |

На странице есть поле поиска, вкладки периода (любое время, 24 часа, 7 дней,
30 дней) и постраничная навигация. Действий в строках нет.

## Журнал команд

`/app/admin/commands` перечисляет каждое действие доски по всем доскам, от новых к
старым. Подзаголовок: `Every board action, newest first`. Строки упорядочены по
времени создания, затем по номеру последовательности.

| Колонка | Значение |
| --- | --- |
| Действие | `type` команды |
| Автор действия | email автора действия, со ссылкой на страницу пользователя |
| Доска | название доски, со ссылкой на страницу доски |
| Seq | номер последовательности команды |
| Payload | payload команды в виде JSON |
| Аудит | ссылка `Аудит`, когда команду отправил мастер, иначе прочерк |
| Когда | время создания |

На странице есть поле поиска, вкладки периода и постраничная навигация.
Действий в строках нет. Ссылка `Аудит` открывает
`/app/admin/audit?tab=audit&commandId=<id команды>` и фильтрует журнал аудита до
точной строки этой команды. Связываются только команды, отправленные из
мастер-панели; обычные пользовательские команды и исторические строки
показывают прочерк. Старый путь `/app/admin/log` перенаправляет на
`/app/admin/audit?tab=commands`.

## Журнал аудита

`/app/admin/audit` перечисляет действия мастеров в панели. Подзаголовок:
`{total} admin actions`.

| Колонка | Значение |
| --- | --- |
| Действие | имя действия аудита |
| Мастер | email мастера; для OWNER — ссылка на страницу мастеров, для OPERATOR — обычный текст с копированием; когда мастер удалён — тоже текст |
| Цель | тип и id цели; для user/board/card — ссылка на страницу сущности, для остальных типов — id с копированием, или прочерк |
| Детали | payload аудита в виде JSON |
| Когда | время создания |

На странице есть поле поиска, вкладки периода и постраничная навигация.
Действий в строках нет. `?commandId=<id команды>` фильтрует журнал до строки
аудита одной команды мастера; журнал команд и таймлайн карточки ведут на этот
точный вид. Детали `board.command` содержат `commandId`, `masterId` и
`masterEmail` рядом с `actorEmail` для владельца, поэтому настоящий мастер не
скрыт за атрибуцией владельца. Фильтр использует id команды, а не id строки
аудита, и дополнительно требует `action=board.command`. Изменения полей
карточки на `/app/admin/cards/:id` дают такую же строку `board.command`:
`UPDATE_CARD`, `SET_CARD_ASSIGN`, `SET_CARD_DUE_DATE`, `SET_CARD_PRIORITY`,
`SET_CARD_COVER` и `SET_CARD_LABEL` получают собственный `commandId` и
атрибуцию мастера. Правки чек-листов и связей связываются так же:
`ADD_CHECKLIST`, `RENAME_CHECKLIST`, `DELETE_CHECKLIST`, `ADD_CHECKLIST_ITEM`,
`SET_CHECKLIST_ITEM_DONE`, `RENAME_CHECKLIST_ITEM`, `DELETE_CHECKLIST_ITEM`,
`ADD_CARD_LINK` и `REMOVE_CARD_LINK` дают по одной строке `board.command` для
принятой свежей записи. Отклонённая свежая запись (нет строки или она удалена,
чужой id, ссылка на себя, дубль, цикл или лимит) не создаёт ни команду, ни
строку аудита, а повтор сохранённого `commandId` возвращает результат без
второй строки аудита.

### Действия аудита

В журнале аудита могут появляться следующие действия:

| Группа | Действия |
| --- | --- |
| Аутентификация мастера | `admin.login`, `admin.login_failed`, `admin.login_locked`, `admin.logout`, `admin.sessions_revoked` |
| Управление мастерами | `admin.create`, `admin.disable`, `admin.enable`, `admin.unlock`, `admin.update`, `admin.password_changed`, `admin.password_reset`, `admin.owner_granted` |
| Пользователи | `user.create`, `user.update`, `user.email_changed`, `user.disable`, `user.enable`, `user.sessions_revoked`, `user.tokens_revoked`, `user.verified`, `user.unverified`, `user.verification_resent`, `user.password_reset`, `user.delete`, `user.impersonated`, `user.promoted`, `user.demoted` |
| Доски | `board.create`, `board.archive`, `board.unarchive`, `board.delete`, `board.command`, `board.member_added`, `board.member_removed`, `board.member_role_changed`, `board.owner_transferred` |
| Карточки и контент | `card.archive`, `card.unarchive`, `card.delete`, `attachment.delete`, `entity.restored`, `entity.bulk_deleted`, `entity.bulk_restored`, `entity.bulk_archived`, `entity.bulk_unarchived`, `comment.delete` |
| Сессии и токены | `session.revoke`, `token.revoke` |
| Почта | `email.settings_changed`, `email.test_sent`, `email.sent`, `email.template_changed`, `email.template_reset` |
| Конфигурация | `oauth.settings_changed`, `throttle.settings_changed`, `flag.changed`, `ops.settings_changed` |
| Коммуникации | `announcement.created`, `announcement.updated`, `announcement.deleted`, `comms.digest_sent`, `comms.reminder_sent` |
| Данные | `data.exported`, `data.export_queued`, `data.export_downloaded`, `retention.changed` |
| Безопасность | `security.totp_enabled`, `security.totp_replaced`, `security.totp_disabled`, `security.ip_allowlist_changed` |
| Демо и ссылки | `demo.started`, `demo.stopped`, `share.created`, `share.refreshed`, `share.revoked` |
| Эксплуатация | `maintenance.run`, `queue.ticket_issued` |

`BoardShareAuditLog` — отдельный журнал по каждой ссылке, а не этот аудит
мастера. В нём используются короткие имена действий: `created`, `updated`,
`refreshed`, `revoked` и `deleted` — PATCH пишет `updated`, без префикса
`share.`. `share.revoked` в журнале мастера — только жёсткое удаление уже
отозванной ссылки администратором.

## Общее поведение списков

Каждый список в панели использует одну реализацию таблицы, поэтому поведение
везде одинаковое. На каждой странице есть поле поиска, постраничная навигация и
фильтры, которые поддерживает её сущность.

- Вкладки статуса появляются только у сущностей с фильтром статуса (например,
  active, archived, deleted).
- Вкладки периода появляются у пользователей, карточек, комментариев, вложений
  и лент по времени (активность, команды, сессии, токены, аудит): любое время,
  24 часа, 7 дней, 30 дней.
- Постраничная навигация показывает общее число записей, размер и номер текущей страницы.
  Размер страницы по умолчанию 50, минимум 1 и максимум 100.
- Состояние списков сущностей живёт в URL (`search`, `status`, `period`,
  `limit`, `offset` и точные id-фильтры). Перезагрузка, ссылка коллеге и кнопки «назад/вперёд»
  браузера восстанавливают ту же отфильтрованную страницу; ключи хаба вроде
  `tab` сохраняются. Ввод в поиске заменяет текущую запись истории, а фильтры
  и пагинация добавляют новую — «назад» возвращает предыдущий вид, а не одно
  нажатие клавиши. В URL попадают только фильтры — никогда токен, пароль или
  одноразовый код.
- Клик по строке передаёт `returnTo` с точным URL отфильтрованного списка, и
  кнопка «назад» на странице детали возвращает туда. Принимаются только
  внутренние пути панели мастера, поэтому подделанный query не уведёт с панели.
- На каждой странице есть индикатор загрузки, сообщение об ошибке с кнопкой
  повтора и сообщение об отсутствии записей.
- Если действие не выполнено, появляется уведомление `Access denied` при `403`, `No connection
  to the server`, когда запрос не ушёл, и `The action failed` в остальных
  случаях.

### Фильтры

В списках, где есть грани кроме статуса и периода, рядом с заголовком появляется
кнопка `Фильтры`. Число на кнопке считает активные грани, а не значения; статус и
период остаются во вкладках заголовка и в счётчик не входят.

- На компьютере кнопка открывает поповер, ниже 640 px — нижний лист высотой до
  70dvh с элементами 44 px и отступом под нижнюю safe-area. При закрытии фокус
  возвращается на кнопку.
- Грани сгруппированы в **Область поиска** (доска, колонка, карточка, команда),
  **Люди** (исполнитель, автор, кто загрузил, инициатор, администратор доски) и
  **Свойства** (метка, приоритет, срок, файлы, тип комментария, тип связи,
  действие аудита, тип цели). Набор зависит от списка; показываются только
  поддерживаемые грани.
- Каждый выборщик ищет по мере ввода (задержка 250 мс, не больше 20 вариантов) и
  отбрасывает устаревший ответ. Если ввод похож на id, `Использовать ID «…»`
  принимает его даже для удалённой или не найденной поиском строки.
- Одиночные выборщики применяются сразу при выборе и закрываются. Множественные
  держат черновик: `Применить` фиксирует всю грань один раз, `Очистить`
  очищает черновик, `Отмена`/`Escape` его отбрасывает. Выбранные значения
  закреплены сверху, показано `Выбрано: N`. В одной грани не больше 20 значений.
- Выбор из радио-граней применяется сразу: подтверждение почты, срок, файлы
  карточки, тип файла и обработка видео. `Любой вариант` убирает параметр и чип.
- В выборщике меток при двух и более выбранных появляется **Любая метка** /
  **Все метки**. «Все метки» добавляет чип `Совпадение меток: все`; если меток
  осталось меньше двух, режим сбрасывается на «любая».
- URL — это сохранённый вид. Добавление, удаление и применение фильтра добавляют
  одну запись истории; ввод в поиске по-прежнему заменяет текущую. Перезагрузка,
  «назад/вперёд», ссылка коллеге и `returnTo` восстанавливают тот же список,
  страницу и чипы.
- Смена фильтра сбрасывает страницу на первую и очищает массовый выбор. Смена
  страницы выбор сохраняет.
- `Сбросить поиск и фильтры` сбрасывает поиск, статус, период и все грани одной
  записью истории. Размер страницы сохраняется.
- Числа — точные серверные итоги (`N total`, `Страница X из Y`), а не число
  загруженных строк. Счётчиков вариантов фильтра нет.

#### Чипы фильтров

- Чип показывает человеческое название и собственный короткий id объекта (восемь
  символов). Зависимые чипы также показывают короткие id родительской доски и
  колонки; полное название и id есть в подсказке и в доступном имени кнопки
  удаления.
- Архивные, удалённые и отключённые объекты сохраняют название с пометкой
  `(в архиве)`, `(удалено)` или `(отключён)`.
- Если id больше не существует, чип становится `Неизвестная доска`,
  `Неизвестная колонка` и т. д. Фильтр остаётся активным, а список показывает
  обычное пустое состояние; чип не исчезает молча.
- Если объект существует, но относится к другой доске или колонке, панель
  показывает баннер конфликта с названием значения и действием
  `Устранить конфликт`. Фильтры сохраняются, список выполняет точное AND и может
  быть пустым. Для журнала команд исключение: его карточка и колонка совпадают
  с историческими `touches`.
- Если поиск значений не удался, чипы и строки остаются на месте, а над
  таблицей появляется `Повторить`. Страница никогда не показывает
  нефильтрованный список как совпавший с фильтром.
- Параметр, который список не поддерживает, отбрасывается при разборе URL.
  Прямой запрос к API с ним возвращает `400 unsupported_filter`; панель
  показывает явное состояние неподдерживаемого фильтра с действием
  `Удалить фильтр`.

#### Смена доски и вкладки хаба

Смена или очистка **Доски** удаляет колонку, метку, совпадение меток и карточку
в том же обновлении URL и сообщает, сколько фильтров сброшено. Исключение —
журнал команд: он сохраняет карточку и колонку при смене или очистке доски,
потому что эти грани совпадают с историческими `touches`, а не с текущим
родителем карточки.

При переключении вкладок хаба сохраняется `boardId` (и только он), если целевая
вкладка его поддерживает. Поиск, статус, период, колонка, метка, совпадение
меток, карточка и чек-лист сбрасываются, а `returnTo` сохраняется. Так «я
изучаю доску X» переживает переход между контентом и модерацией, но устаревший
поиск не скрывает строки на другой поверхности.

#### Клавиатура и сенсор

- `Tab` доводит до кнопки «Фильтры»; `Enter` или `Space` открывает её; `Escape`
  закрывает и возвращает фокус на кнопку.
- Выборщики — это combobox/listbox: стрелки, `Home`/`End`, `Enter`/`Space` и
  поиск вводом. Радиогруппа — одна точка табуляции с выбором стрелками.
- В мобильном листе каждый элемент не меньше 44 px, кнопки внизу остаются
  видимыми при прокрутке граней, лист учитывает нижнюю safe-area.
- Чипы переносятся. На 390 px длинное название сокращается многоточием, id
  остаются видимыми, а страница не прокручивается горизонтально.
- Ничто не требует наведения: у каждого чипа есть настоящая фокусируемая
  кнопка удаления с областью не меньше 24×24 px (32 px в плотной панели, 44 px
  на телефоне).

#### Что намеренно не фильтруется

- Нет сохранённых видов как на доске, восстановления из localStorage, счётчиков
  вариантов и экспорта в CSV.
- У сессий и API-токенов остаются только вкладки периода. Список сессий содержит
  только живые сессии, поэтому фильтр статуса обещал бы строки, которых список
  не показывает. У публичных ссылок пока только поиск, без фильтров.
- Мастера — небольшой список только для владельца, фильтров у него нет.
- Страницы деталей (пользователь, карточка, участники доски, дашборд) уже сужены
  родителем и не дублируют фильтры списка.
- У пунктов чек-листов нет отдельной вкладки; их читают на странице карточки.
- Настройки безопасности показывают ограниченную панель последних событий, а не
  полноценный журнал с фильтрами.

### Адресуемые фильтры

Счётчики доски и колонки/метки на странице доски ведут к точным строкам, а не
к поиску по названию:

| Откуда | Ссылка | Что означает |
| --- | --- | --- |
| Счётчики доски Cards / Comments / Files / Commands / Events | `?boardId=<id>` на соответствующей вкладке хаба | только строки этой доски |
| Название колонки или число карточек | `/app/admin/boards?tab=cards&columnId=<id>` | карточки этой колонки |
| Чип метки или число карточек | `/app/admin/boards?tab=cards&labelId=<id>` | карточки с этой меткой |
| Результат поиска «метка» | `/app/admin/boards?tab=cards&labelId=<id>` | карточки с этой меткой |
| Название карточки в редакторе контента | `/app/admin/cards/<id>` | страница карточки |
| Ссылка `Аудит` в строке команды | `/app/admin/audit?tab=audit&commandId=<id команды>` | точная строка аудита этой команды мастера |

`boardId`, `columnId`, `labelId`, `cardId` и `commandId` — проверяемые
идентификаторы, а не текст: некорректное значение отклоняется с `400`, а
одноимённые доски и метки не могут перепутаться. Фильтры сочетаются со `status` и периодом; запрос с
колонкой другой доски возвращает пустой список, а не расширяет выборку. Над
таблицей видны чипы активных фильтров с кнопкой сброса.

Удалённые и архивные строки подчиняются вкладкам статуса самого списка (у
контента доски и модерации они есть, у лент журналов — нет). Без явного
статуса список с `boardId` всё равно включает soft-deleted комментарии/файлы
и архивные или удалённые карточки с их бейджами; `status=active` их исключает,
`status=deleted` выбирает только их. Счётчики Comments и Files ведут со
`status=active` и совпадают со своим определением живых строк. Счётчик Cards
включает архивные карточки, но не удалённые, поэтому его список может показать
архивные сверх числа; счётчики Cards, Commands и Events не фильтруются по
статусу. Сузить список можно вкладками статуса (где они есть) и чипами
фильтров.

### Фильтры активности, журнала команд и аудита

У трёх лент мониторинга одна и та же поверхность фильтров:

| Список | Доступные грани |
| --- | --- |
| Активность | Доска, Карточка, Инициатор, Тип события |
| Журнал команд | Доска, Карточка, Колонка, Инициатор, Тип команды, ID команды |
| Журнал аудита | Мастер, Действие, Тип цели, ID цели, ID команды |

- **Активность**: типы событий берутся из реально сохранённых значений, поэтому
  доступны события участия, комментариев, согласований и агентов без
  захардкоженного списка. Грань «Инициатор» совпадает с автором события участия
  или комментария.
- **Журнал команд**: типы — точные коды вроде `ADD_CARD`, `MOVE_CARD` или
  `UPDATE_CARD`. Карточка и колонка совпадают с историческими `touches`,
  поэтому смена или очистка доски их сохраняет. Текущая доска или колонка
  карточки не ограничивает её историю команд.
- **Журнал аудита**: доступны только инициаторы, видимые в строках аудита: id
  мастера или адрес попытки входа при неудачном входе. `adminId` — не поиск по
  реестру мастеров, и OPERATOR видит обычный текст, а не ссылку на страницу
  мастеров, доступную владельцу. Для неудачного входа без id мастера очистите
  чип «Мастер», найдите адрес попытки и при необходимости сузьте действие до
  `admin.login_failed`.
- Выборщики действия и типа цели аудита показывают значения, которые вернул
  сервер; введённый вручную код API всё равно принимает как точное значение.
  ID цели — точный id; при выбранном одном типе цели чип ведёт на страницу
  пользователя, доски или карточки, если возвращённая строка аудита
  подтверждает существование объекта.

Дашборд описан здесь; списки пользователей, досок и контента на своих
страницах: смотрите [пользователи и мастера](/ru/docs/admin/people/) и
[доски, карточки и контент](/ru/docs/admin/content/).
