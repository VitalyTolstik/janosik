:::note
Дашборд — это хаб **Обзор** (`/admin`). Лента активности, журнал команд и аудит
теперь вкладки хаба **Аудит и активность** (`/admin/audit?tab=…`). Старые URL
`/admin/activity` и `/admin/commands` перенаправляются. Полная карта — в
[Редизайне админки](../redesign/).
:::

Раздел наблюдения отвечает на два вопроса: что происходит на платформе прямо
сейчас и что делали мастера и пользователи. Раздел включает четыре страницы:
дашборд, лента активности, журнал команд и журнал аудита.

## Дашборд

Дашборд — главная страница панели по адресу `/admin`. Для загрузки данных
отправляются два запроса: `GET /admin/metrics` и небольшой `GET
/admin/audit?limit=8`. Страница
состоит из трёх частей.

### Карточки статистики

| Карточка | Значение | Подсказка |
| --- | --- | --- |
| Пользователи | всего пользователей | `+N за 7 дней` |
| Заблокированы | пользователи с `disabledAt` | нет |
| Активные доски | доски не удалённые и не архивные | `N в архиве` |
| Активные карточки | карточки не удалённые и не архивные | `N в архиве` |
| Команды, 24 ч | команды за последние 24 часа | `N за 7 дней` |
| Активные сессии | живые refresh-сессии | нет |
| Комментарии | комментарии не удалённые | нет |
| Мастер-аккаунты | всего мастеров | нет |

### Состояние сервера

В этом блоке показаны четыре значения из `AdminMetricsDto.runtime`:

| Метка | Значение |
| --- | --- |
| Version | версия пакета backend |
| Uptime | время работы процесса, в формате `Nh Nm` или `Nm Ns` |
| Database | время выполнения `SELECT 1` с учётом обмена с базой данных, в миллисекундах |
| Environment | `NODE_ENV` |

### Графики и недавний аудит

Два графика показывают данные за последние 14 дней, от старых к новым: регистрации за
день и команды за день. Ниже них находится `Recent admin actions`, последние
восемь строк аудита (действие, email мастера, время), со ссылкой на полный
журнал аудита.

## Лента активности

`/admin/activity` перечисляет изменения членства и события комментариев по
доскам. Подзаголовок: `Membership changes and comment events`.

| Колонка | Значение |
| --- | --- |
| Событие | `type` активности |
| Автор действия | email автора действия, со ссылкой на страницу пользователя |
| Доска | название доски, со ссылкой на страницу доски |
| Карточка | название карточки, со ссылкой на страницу карточки, или прочерк |
| Детали | payload события в виде JSON |
| Когда | время создания |

На странице есть поле поиска, вкладки периода (любое время, 24 часа, 7 дней,
30 дней) и постраничная навигация. Действий в строках нет.

## Журнал команд

`/admin/commands` перечисляет каждое действие доски по всем доскам, от новых к
старым. Подзаголовок: `Every board action, newest first`. Строки упорядочены по
времени создания, затем по номеру последовательности.

| Колонка | Значение |
| --- | --- |
| Действие | `type` команды |
| Автор действия | email автора действия, со ссылкой на страницу пользователя |
| Доска | название доски, со ссылкой на страницу доски |
| Seq | номер последовательности команды |
| Payload | payload команды в виде JSON |
| Когда | время создания |

На странице есть поле поиска, вкладки периода и постраничная навигация.
Действий в строках нет. Старый путь `/admin/log` перенаправляет на
`/admin/commands`.

## Журнал аудита

`/admin/audit` перечисляет действия мастеров в панели. Подзаголовок:
`{total} admin actions`.

| Колонка | Значение |
| --- | --- |
| Действие | имя действия аудита |
| Мастер | email мастера; для OWNER — ссылка на страницу мастеров, для OPERATOR — обычный текст с копированием; когда мастер удалён — тоже текст |
| Цель | тип и id цели; для user/board/card — ссылка на страницу сущности, для остальных типов — id с копированием, или прочерк |
| Детали | payload аудита в виде JSON |
| Когда | время создания |

На странице есть поле поиска, вкладки периода и постраничная навигация.
Действий в строках нет.

## Общее поведение списков

Каждый список в панели использует одну реализацию таблицы, поэтому поведение
везде одинаковое. На каждой странице есть поле поиска, постраничная навигация и
фильтры, которые поддерживает её сущность.

- Вкладки статуса появляются только у сущностей с фильтром статуса (например,
  active, archived, deleted).
- Вкладки периода появляются только у лент по времени (активность, команды,
  сессии, токены, аудит): любое время, 24 часа, 7 дней, 30 дней.
- Постраничная навигация показывает общее число записей, размер и номер текущей страницы.
  Размер страницы по умолчанию 50, минимум 1 и максимум 100.
- Состояние списков сущностей живёт в URL (`search`, `status`, `period`,
  `limit`, `offset`). Перезагрузка, ссылка коллеге и кнопки «назад/вперёд»
  браузера восстанавливают ту же отфильтрованную страницу; ключи хаба вроде
  `tab` сохраняются. Ввод в поиске заменяет текущую запись истории, а фильтры
  и пагинация добавляют новую — «назад» возвращает предыдущий вид, а не одно
  нажатие клавиши. В URL попадают только фильтры — никогда токен, пароль или
  одноразовый код.
- Клик по строке передаёт `returnTo` с точным URL отфильтрованного списка, и
  кнопка «назад» на странице детали возвращает туда. Принимаются только
  внутренние пути `/admin`, поэтому подделанный query не уведёт с панели.
- На каждой странице есть индикатор загрузки, сообщение об ошибке с кнопкой
  повтора и сообщение об отсутствии записей.
- Если действие не выполнено, появляется уведомление `Access denied` при `403`, `No connection
  to the server`, когда запрос не ушёл, и `The action failed` в остальных
  случаях.

### Адресуемые фильтры

Счётчики доски и колонки/метки на странице доски ведут к точным строкам, а не
к поиску по названию:

| Откуда | Ссылка | Что означает |
| --- | --- | --- |
| Счётчики доски Cards / Comments / Files / Commands / Events | `?boardId=<id>` на соответствующей вкладке хаба | только строки этой доски |
| Название колонки или число карточек | `/admin/boards?tab=cards&columnId=<id>` | карточки этой колонки |
| Чип метки или число карточек | `/admin/boards?tab=cards&labelId=<id>` | карточки с этой меткой |
| Результат поиска «метка» | `/admin/boards?tab=cards&labelId=<id>` | карточки с этой меткой |
| Название карточки в редакторе контента | `/admin/cards/<id>` | страница карточки |

`boardId`, `columnId`, `labelId` и `cardId` — проверяемые идентификаторы, а не
текст: некорректное значение отклоняется с `400`, а одноимённые доски и метки
не могут перепутаться. Фильтры сочетаются со `status` и периодом; запрос с
колонкой другой доски возвращает пустой список, а не расширяет выборку. Над
таблицей видны чипы активных фильтров с кнопкой сброса.

Удалённые и архивные строки подчиняются вкладкам статуса самого списка (у
контента доски и модерации они есть, у лент журналов — нет). Без явного
статуса список с `boardId` всё равно включает soft-deleted комментарии/файлы
и архивные или удалённые карточки с их бейджами; `status=active` их исключает,
`status=deleted` выбирает только их. Счётчики Comments и Files ведут со
`status=active` и совпадают со своим определением живых строк. Счётчик Cards
включает архивные карточки, но не удалённые, поэтому его список может показать
архивные сверх числа; счётчики Cards, Commands и Events не фильтруются по
статусу. Сузить список можно вкладками статуса (где они есть) и чипами
фильтров.

страницах: смотрите [пользователи и мастера](/ru/docs/admin/people/) и
[доски, карточки и контент](/ru/docs/admin/content/).
