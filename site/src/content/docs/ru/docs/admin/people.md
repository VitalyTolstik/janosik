Раздел людей управляет обычными пользователями и мастер-аккаунтами. Список
пользователей виден каждому мастеру; страница мастеров доступна только
владельцу.

## Пользователи

`/admin/users` перечисляет зарегистрированные аккаунты. Подзаголовок:
`{total} registered`.

| Колонка | Значение |
| --- | --- |
| Email | адрес, со ссылкой на страницу пользователя и с кнопкой копирования |
| Имя | отображаемое имя, усечённое |
| Регистрация | время создания |
| Статус | `Active` или `Blocked` |

На странице есть поле поиска, вкладки статуса (все, активные, заблокированные),
постраничная навигация и кнопка `Create user`. Строки ведут на страницу
пользователя.

### Создание пользователя

Диалог `Create user` принимает:

| Поле | Ограничения |
| --- | --- |
| Email | обязательно, корректный адрес |
| Имя | необязательно, не более 50 символов |
| Пароль | необязательно, от 8 до 100 символов |

Когда пароль оставлен пустым, сервер генерирует его и возвращает ровно один
раз. Затем диалог показывает `Password (shown once)` с кнопкой копирования.

### Действия в строке

В каждой строке есть меню действий со следующими пунктами.

| Действие | Эффект | Примечания |
| --- | --- | --- |
| Block | выставляет `disabledAt` | разрушительное, с подтверждением; также сразу отзывает все сессии |
| Unblock | снимает `disabledAt` | с подтверждением; сессии не восстанавливаются |
| Change email | открывает диалог смены email | см. ниже |
| Revoke sessions | отзывает все живые refresh-сессии | разрушительное, с подтверждением |
| Revoke API tokens | отзывает все персональные API-токены | разрушительное, с подтверждением |
| Verify email | помечает адрес подтверждённым | показано, когда не подтверждён; с подтверждением |
| Unverify email | отзывает подтверждение | разрушительное, показано, когда подтверждён; с подтверждением |
| Resend verification | отправляет новый код подтверждения | показано всегда |
| Reset password | выдаёт временный пароль | на сервере только владелец; открывает диалог |
| Promote to master | создаёт мастера `OPERATOR` | цвет предупреждения; открывает диалог |
| Impersonate | открывает короткую сессию поддержки | только владелец; открывает приложение в новой вкладке |
| Export data | скачивает пакет GDPR | на сервере только владелец |
| Delete user | стирает аккаунт | на сервере только владелец; открывает диалог, требующий ввести email |

Список показывает часть этих действий; страница пользователя открывает полный
набор.

### Смена email

`Change email` открывает диалог с текущим адресом в описании и полем `New
email`. В отличие от самостоятельного потока здесь нет кода подтверждения:
мастер отвечает за действие через журнал аудита. При успехе все сессии
пользователя отзываются, изменение попадает в аудит как `user.email_changed`, и
на старый адрес уходит уведомление. Дублирующий адрес отвечает `409`, неверный
адрес отвечает `400`.

### Сброс пароля

`Reset password` выдаёт новый временный пароль, показанный один раз, и отзывает
все сессии пользователя. На сервере это только для владельца. Диалог запускает
запрос сразу при открытии.

### Повышение до мастера

`Promote to master` создаёт мастера `OPERATOR` с тем же email и новым временным
паролем. Диалог требует ввести email аккаунта для подтверждения, затем
показывает одноразовый пароль. Если мастер с таким email уже существует, ответ
`409`.

### Impersonate

`Impersonate` выпускает короткоживущий пользовательский токен (15 минут),
ограниченный одним аккаунтом, и открывает с ним приложение в новой вкладке.
Приложение показывает неубираемый баннер с именем мастера. Доступно только
владельцу и отказывает для отключённого аккаунта. Выпуск попадает в аудит как
`user.impersonated`.

### Экспорт данных

`Export data` запрашивает JSON-пакет всего, что связано с пользователем
(профиль, членства, комментарии, вложения, сессии, токены, команды,
активность). Небольшой аккаунт собирается сразу и скачивается; большой ставится
в очередь, и панель опрашивает состояние, пока артефакт не готов. Артефакт
живёт семь дней. На сервере это только для владельца.

### Удаление пользователя

`Delete user` стирает аккаунт и созданные им строки в одной транзакции, затем
удаляет его блобы. Это разрушительный близнец `Block`. Диалог требует ввести
точный email аккаунта для подтверждения. Отменить нельзя. На сервере это
действие только для владельца: оператор получает `403` с `Owner rights are
required`.

## Страница пользователя

`/admin/users/:id` показывает весь граф пользователя, нужный агенту поддержки.
Заголовок несёт отображаемое имя (или email), email, id, значок статуса, время
регистрации, время отключения при блокировке и значок подтверждения. Меню
действий повторяет полный набор.

### Карточки счётчиков

Показаны восемь счётчиков:

| Счётчик | Значение |
| --- | --- |
| Доски | доски, где пользователь участник |
| Созданные карточки | карточки, выведенные из журнала команд как созданные пользователем |
| Назначенные карточки | живые карточки, где пользователь исполнитель |
| Комментарии | написанные комментарии |
| Вложения | загруженные файлы |
| Сессии | refresh-сессии |
| API-токены | персональные токены |
| Команды | написанные команды |

### Вкладки

На странице девять вкладок, у каждой есть счётчик.

| Вкладка | Колонки |
| --- | --- |
| Членства | Доска, Роль, Принято, Истекает, Пригласил, Присоединился |
| Созданные карточки | Карточка, Доска, Колонка, Обновлено, Статус |
| Назначенные карточки | Карточка, Доска, Колонка, Обновлено, Статус |
| Комментарии | Комментарий, Карточка, Создан |
| Вложения | Файл, Карточка, Размер, Создан |
| Сессии | Начата, Истекает, Сессия |
| API-токены | Токен, Создан, Последнее использование, Истекает, Статус |
| Команды | Действие, Доска, Seq, Когда |
| Активность | Событие, Доска, Карточка, Когда |

Членства показывают значок `Deleted`, когда доска удалена, и значок `Pending`,
пока приглашение не принято. Созданные и назначенные карточки показывают
статус active, archived или deleted. Пустые вкладки показывают короткое
состояние пустоты.

## Мастера

`/admin/masters` доступна только владельцу. Она перечисляет аккаунты панели.
Подзаголовок: `Owner and operator accounts of the panel`.

| Колонка | Значение |
| --- | --- |
| ID | id мастера в виде чипа с копированием |
| Email | адрес |
| Роль | `Owner` (с короной) или `Operator` |
| Имя | отображаемое имя |
| Неудачные входы | счётчик блокировки |
| Последний вход | последний успешный вход или `never` |
| Заблокирован до | окончание блокировки или прочерк |
| Статус | `Active`, `Blocked` или `Locked` |

### Создание мастера

`Add master` открывает диалог с email, необязательным именем (не более 50
символов) и флажком `Grant owner rights`. Флажок выбирает `OWNER`, когда
установлен, и `OPERATOR`, когда нет. Сервер генерирует одноразовый пароль и
показывает его один раз с кнопкой копирования. Существующий мастер отвечает
`409`.

### Действия в строке

| Действие | Эффект | Примечания |
| --- | --- | --- |
| Block | выставляет `disabledAt` и отзывает все сессии | разрушительное; недоступно для своего аккаунта |
| Unblock | снимает `disabledAt`, счётчик и блокировку | |
| Unlock | снимает блокировку и счётчик неудачных входов | показано только при блокировке |
| Reset password | выдаёт одноразовый пароль и отзывает все сессии | показывает пароль один раз |
| Revoke sessions | отзывает все сессии этого мастера | |
| Remove from masters | удаляет мастер-аккаунт | разрушительное; недоступно для своего аккаунта |

### Самозащита

Сервер отказывает в действиях, которые оставили бы панель без владельца или
оператора без доступа:

- Нельзя отключить свой аккаунт.
- Нельзя отключить последнего активного владельца.
- Нельзя понизить свой аккаунт.
- Последнего владельца нельзя понизить.

Удаление мастера удаляет только мастер-аккаунт. Если у того же email есть
обычный пользовательский аккаунт, пользователь не затрагивается.
