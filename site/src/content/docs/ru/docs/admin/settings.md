Страницы настроек и эксплуатации настраивают платформу и запускают её
обслуживание. Запись на этих страницах на сервере доступна только владельцу;
оператор видит состояние только для чтения.

## Почтовая служба

`/admin/email` настраивает исходящий почтовый транспорт. Подзаголовок:
`Outgoing mail, pick a provider, enter credentials, no code changes needed`.
Сохранение перенастраивает работающий backend на месте, без перезапуска и без
изменений кода или окружения.

### Состояние

Баннер состояния сообщает, откуда берётся активный транспорт:

| Состояние | Значение |
| --- | --- |
| `Delivery is active via {provider} ({host}:{port}).` | сохранённая включённая строка |
| `Delivery is active via the server's SMTP_* env bootstrap` | используется bootstrap из окружения |
| `Delivery is off` | сохранённая строка хранится, но не используется |
| `Delivery is not configured` | письма пишутся в журнал сервера |

Когда проба уже запускалась, показывается последний результат теста и его
время.

### Провайдеры

Выберите один пресет провайдера; хост, порт и TLS берутся из пресета.

| Провайдер | Хост | Порт | TLS |
| --- | --- | --- | --- |
| Gmail | `smtp.gmail.com` | 465 | неявный TLS |
| Yandex | `smtp.yandex.ru` | 465 | неявный TLS |
| Mail.ru | `smtp.mail.ru` | 465 | неявный TLS |
| Brevo | `smtp-relay.brevo.com` | 587 | STARTTLS |
| SendGrid | `smtp.sendgrid.net` | 587 | STARTTLS, имя `apikey` |
| Custom SMTP | ваш собственный | 587 | редактируется |

`Custom SMTP` оставляет поля хоста, порта и неявного TLS редактируемыми. Порт
должен быть от 1 до 65535, а хост не длиннее 255 символов.

### Поля

| Поле | Примечания |
| --- | --- |
| From address | обязательно, кроме песочницы; не более 255 символов |
| SMTP username | обязательно, кроме песочницы; не более 255 символов |
| SMTP password | пустое сохраняет сохранённый пароль; не более 1024 символов |
| Enable delivery | переключатель включения и выключения |

Семантика пароля: пустое значение сохраняет сохранённый секрет, значение
заменяет его. Секрет не покидает backend; страница знает только, сохранён ли
он. Провайдеры требуют пароль приложения или API-ключ вместо пароля аккаунта, а
ссылка помощи ведёт к инструкциям провайдера.

### Тестовая доставка

Панель теста отправляет пробу на адрес. Результат возвращается и записывается.
Когда доставка выключена, проба пишется в журнал сервера, и панель сообщает об
этом. Неудачная проба показывает текст ошибки.

### Песочница

Тестовый провайдер `Mailpit (sandbox)` это локальный перехватчик почты, который
никогда не доходит до реальных ящиков. Он указывает на sidecar Mailpit на
хосте: SMTP `localhost:1025`, веб-ящик `http://localhost:8025`. Учётные данные
не нужны. Затем панель песочницы предлагает `Open the inbox`. Письма попадают
в локальный веб-ящик, который работает только на этой машине.

## OAuth-вход

`/admin/oauth` настраивает вход через внешних провайдеров. Подзаголовок:
`Sign-in through external providers (Google, Yandex)`. Клиентский секрет не
покидает backend; пустое поле сохраняет сохранённый.

Поддерживаются два провайдера:

| Провайдер | Поле статуса |
| --- | --- |
| Google | Enabled или Disabled |
| Yandex | Enabled или Disabled |

У панели каждого провайдера есть:

| Поле | Примечания |
| --- | --- |
| Client ID | обязательно, не более 255 символов |
| Client secret | пустое сохраняет сохранённый секрет; не более 255 символов |
| Callback URL | показан только для чтения, зарегистрируйте его в консоли провайдера |
| Enable sign-in | переключатель включения и выключения |

Callback URL выводится из публичного origin. Сохранение обновляет экран входа
в тот же момент, когда проходит: кнопка появляется, когда провайдер включён.

## Безопасность

`/admin/security` управляет собственной защитой вошедшего мастера. Примечание о
зоне действия гласит: эти настройки применяются только к вашему мастер-аккаунту,
обычные пользователи не затрагиваются.

### Двухфакторная аутентификация

| Элемент | Эффект |
| --- | --- |
| Enable 2FA | начинает регистрацию и показывает base32-секрет и `otpauth://` URL |
| Confirm | завершает регистрацию шестизначным кодом |
| Disable 2FA | выключает её; требует верный код |

Секрет хранится зашифрованным. TOTP это SHA-1, шесть цифр, период 30 секунд, с
проверкой в окне одного шага. После включения вход требует код после пароля.

### IP-список

Список это перечисление IP и CIDR-диапазонов через запятую или пробел. Пустой
список разрешает любой адрес. Проходит точное совпадение строки или совпадение
IPv4 CIDR. При сохранении список обрезается и дедуплицируется. Он доступен
только владельцу: оператор не может ограничить свой собственный источник входа.

Список проверяется на каждом запросе сессии мастера и при каждом обновлении,
а не только при входе. Поэтому сохранение списка, в который не входит ваш
текущий адрес, отклоняется с `400` (`The allowlist must include your current
address (…)`), чтобы нельзя было запереть себя посреди сессии. За обратным
прокси задайте `TRUST_PROXY`, чтобы сервер видел настоящий адрес клиента.

### Подозрительная активность

Лента предупреждений перечисляет неудачные и заблокированные входы за последние
24 часа, до 50 строк. Каждая строка показывает значок `locked` или `failed
sign-in`, email мастера, IP и время.

## Трафик и лимит

`/admin/traffic` показывает живой поток запросов к API и глобальный лимит
частоты. Подзаголовок: `Live API request rate and the global rate limit`.

Три значения показаны и опрашиваются раз в секунду, пока страница видима:

| Значение | Значение |
| --- | --- |
| Запросов / минуту | запросы, замеченные за последние 60 секунд |
| Отклонено (429) / минуту | запросы, отклонённые ограничителем за последние 60 секунд |
| Лимит | лимит, действующий сейчас |

График рисует запросы в секунду за последние 60 секунд, от старых к новым.

Редактор лимита это числовой шаг от 1 до 1 000 000. Значок источника говорит,
задан лимит `set in this panel` или `from environment (THROTTLE_LIMIT)`.
Сохранение действует на следующий запрос, без перезапуска. Лимит доступен
только владельцу; оператор видит его только для чтения.

## Демо-рой

`/admin/demo` запускает рой ИИ-агентов на одноразовой доске, наблюдает за их
работой и затем убирает за собой. Подзаголовок: `Seed a demo board of AI
agents, watch them work, then clean up`.

Три счётчика двигаются сами, пока запуск жив: Агентов, Карточек и Готово.
Строка доски показывает id доски запуска и, когда есть живая ссылка, ссылку
`Open live view` на `/s/<token>` и кнопку `Copy share link`.

Поля только для владельца:

| Поле | Диапазон | Примечания |
| --- | --- | --- |
| Board id | необязательно | пусто создаёт отдельную демо-доску |
| Агентов | от 1 до 100 | |
| Задач | от 1 до 1000 | сколько карточек засеять |

`Start demo` разворачивает население и запускает рой. `Stop & clean up`
доступно, пока след запуска ещё существует; оно подтверждается и удаляет ровно
записанные строки: доску, когда запуск её создал, её карточки, её демо-пользователей
и её ссылку.

Под капотом запускающий создаёт диспетчера и запрошенных агентов на
зарезервированном домене `@janosik.demo`, пять колонок потока (Новые, В работе,
На ревью, Тестирование, Готово), набор меток и одну карточку на агента, затем
проводит карточки по потоку. Каждый созданный id записывается, поэтому очистка
никогда не угадывает по имени.

## Эксплуатация

`/admin/ops` это панель управления runtime. Подзаголовок: `Flags,
maintenance, rate limits and data retention`. Каждое управление пишет напрямую
и действует без перезапуска. Все управления доступны только владельцу.

### Флаги функций

| Флаг | Описание | Источник по умолчанию |
| --- | --- | --- |
| `registration_open` | разрешить кому угодно создавать новый аккаунт | окружение `ALLOW_REGISTRATION` |
| `public_shares` | разрешить публичные ссылки на доски только для чтения | окружение `ALLOW_PUBLIC_SHARES` |
| `video_transcode` | перекодировать загруженные видео в компактный MP4 | включено |
| `realtime_sse` | стримить живые изменения доски по SSE | включено |

У каждого флага есть переключатель. Когда у флага есть пер-пользовательские
переопределения, показывается их число. Действующее значение для пользователя
это пер-пользовательское переопределение, когда оно есть, иначе глобальный
переключатель, иначе значение окружения по умолчанию. Флаги применяются во
время запроса.

### Режим обслуживания

Переключатель обслуживания принимает необязательное сообщение (не более 500
символов). Когда он включён, каждый пользовательский запрос получает `503` с
сообщением; панель и вход остаются открытыми, поэтому оператор может выключить
его.

### Лимит частоты

Пер-пользовательский лимит это числовой шаг от 1 до 100 000 запросов в минуту.
Пустое значение отключает его, оставляя только глобальный IP-лимит. Лимит
применяется ко всем аккаунтам одинаково, у каждого свой счётчик. Пути `/admin`,
`/auth` и `/health` освобождены.

### Мягко удалённые данные и срок хранения

Срок хранения это число дней до того, как очистка может удалить мягко
удалённые строки (от 1 до 3650, по умолчанию 30). Страница показывает, сколько
карточек, комментариев, вложений и колонок сейчас подходят, и расположение
резервных копий, когда настроен `BACKUP_DIR`.

`Purge now` навсегда удаляет уже удалённые карточки, комментарии, вложения и
колонки старше окна. Живые данные никогда не затрагиваются. Действие
подтверждается.

### Плановое обслуживание

Интервал очистки в минутах (от 0 до 10 080; 0 отключает расписание; по
умолчанию 60). `Run sweeps now` запускает весь набор сразу. Именованные
очистки:

| Очистка | Что удаляет |
| --- | --- |
| `purge-soft-deleted` | мягко удалённые строки старше срока хранения |
| `sweep-codes` | истёкшие или использованные коды подтверждения и смены email |
| `sweep-tokens` | истёкшие или давно отозванные refresh-токены (пользователя и админа) |
| `sweep-shares` | ссылки на доски старше их TTL |
| `sweep-invitations` | просроченные ожидающие приглашения |
| `sweep-exports` | истёкшие фоновые экспорты данных и их файлы |
| `sweep-commands` | строки журнала команд старше срока хранения |
| `sweep-reminders` | устаревшие строки дедупликации напоминаний о сроке |
| `sweep-orphan-blobs` | блобы, на которые не ссылается ни одна строка, старше часового льготного окна |

Когда настроен Redis, очистка идёт по устойчивому расписанию; без Redis она
идёт на месте, и расписание теряется при перезапуске.

### Плановая почта

Отсюда идут две повторяющиеся задачи. Интервал дайджеста в часах (от 0 до 720;
0 отключает). Окно напоминания о сроке в часах (от 0 до 720; 0 отключает).
Получатели могут отказаться от обоих. Дайджест суммирует, что изменилось на
каждой доске с прошлого запуска. Напоминание перечисляет карточки, назначенные
пользователю, срок которых попадает в окно. Каждое напоминание отправляется
один раз на карточку, пользователя и срок.

### Панель очередей

Когда панель очередей включена, кнопка `Open queue dashboard` открывает
`/api/v1/admin/queues` в новой вкладке. Она просматривает и повторяет фоновые
задачи (Bull Board). Доступна только владельцу и требует Redis.

## Коммуникации

`/admin/comms` составляет рассылки и редактирует почтовые шаблоны.
Подзаголовок: `Announcements, mail and templates`. Запись доступна только
владельцу.

### Объявления

`New announcement` открывает диалог:

| Поле | Примечания |
| --- | --- |
| Заголовок | не более 200 символов |
| Текст | не более 2000 символов |
| Уровень | `Info`, `Warning` или `Alert` |
| Аудитория | все пользователи или выбранные |
| Получатели | для выбранных, автодополнение по каталогу пользователей |
| Also send by email | ставит письмо в очередь получателям |

Объявление с `Also send by email` показывается баннером в приложении и также
отправляется почтой разрешённым получателям.

### Разовое письмо

Панель отправки письма принимает получателя, тему (не более 200 символов) и
текст сообщения (не более 20 000 символов). Результат возвращается, а отправка
попадает в аудит.

### Почтовые шаблоны

Редактируются пять шаблонов:

| Ключ | Метка |
| --- | --- |
| `verification_code` | Email verification code |
| `email_change_code` | Email change code |
| `email_changed_notice` | Email changed notice |
| `digest` | Board digest |
| `due_reminder` | Due-date reminder |

У каждого шаблона есть тема и HTML-тело. Плейсхолдеры показаны как `{{name}}`.
`Preview` рендерит письмо с примерными значениями во фрейме. `Save` сохраняет
переопределение и помечает шаблон как `custom`; `Reset to default` убирает
переопределение, и встроенное письмо снова вступает в силу. Без
переопределения показывается встроенное письмо, поэтому редактор не пуст.

### История объявлений

Полная история объявлений на отдельной странице `/admin/announcements`.
Подзаголовок: `{total} broadcasts, the full announcement history`.

| Колонка | Значение |
| --- | --- |
| Заголовок | заголовок объявления |
| Текст | тело |
| Уровень | info, warning или alert |
| Аудитория | все пользователи или сегмент |
| Email | значок `email`, когда письмо тоже отправляется |
| Активно | вкл или выкл |
| Создано | время создания |
| Автор | создавший мастер |

На странице есть поле поиска и вкладки статуса (активные, неактивные). Действия
в строке:

| Действие | Эффект |
| --- | --- |
| Edit | открывает диалог для смены заголовка, текста, уровня, аудитории, сегмента, времени начала и конца, активности и отправки по email |
| Activate | выставляет `active` в true |
| Deactivate | выставляет `active` в false |
| Delete | удаляет объявление |

## Наблюдаемость

`/admin/observability` показывает runtime, базу данных и состояние задач.
Подзаголовок: `Runtime, database and jobs`.

- Панель runtime показывает Version, Environment, Uptime, Started, Database
  size и Commit.
- Панель frontend описывает сборку приложения, обслуживающую панель: App
  version, Build, Commit, Theme, Service worker, Display и Connection.
- Панель jobs показывает Transcode (pending/done/failed), Realtime
  (boards/clients) и Demo runner (вкл или выкл).
- Сетка очередей показывает имя каждой очереди, счётчики pending, done и
  failed и её backend (`redis` или `memory`).
- Таблица `Biggest tables` перечисляет до 12 таблиц со строками и размером.
- Панель health перечисляет `database` (`SELECT 1` и его задержку),
  `realtime` (каналы доски) и `maintenance` (вкл или выкл).

## Баннер объявлений для пользователей

Активные объявления доходят до вошедших пользователей баннером под заголовком
приложения. Эндпоинт это `GET /announcements/active`, доступный через обычный
пользовательский контур аутентификации, поэтому вышедший посетитель не получает
ничего, а пользователь видит только объявления, адресованные ему.

Каждый баннер стилизован по уровню (info, warning, danger) и может быть скрыт.
Скрытие запоминается для каждого объявления в `localStorage`, поэтому
пользователь видит каждое один раз.
