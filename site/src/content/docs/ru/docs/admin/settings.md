## Почтовая служба

`/admin/email` настраивает исходящий почтовый транспорт. Подзаголовок:
`Outgoing mail, pick a provider, enter credentials, no code changes needed`.
Сохранение применяет настройки к работающему серверу, без перезапуска и без
изменений кода или окружения.

### Состояние

Баннер состояния сообщает, откуда берётся активный транспорт:

| Состояние | Значение |
| --- | --- |
| `Delivery is active via {provider} ({host}:{port}).` | используются сохранённые настройки отправки |
| `Delivery is active via the server's SMTP_* env bootstrap` | используются SMTP-настройки из переменных окружения |
| `Delivery is off` | настройки сохранены, но отправка выключена |
| `Delivery is not configured` | письма пишутся в журнал сервера |

После проверки отображаются её последний результат и время запуска.

### Провайдеры

Выберите один пресет провайдера; хост, порт и TLS берутся из пресета.

| Провайдер | Хост | Порт | TLS |
| --- | --- | --- | --- |
| Gmail | `smtp.gmail.com` | 465 | неявный TLS |
| Yandex | `smtp.yandex.ru` | 465 | неявный TLS |
| Mail.ru | `smtp.mail.ru` | 465 | неявный TLS |
| Brevo | `smtp-relay.brevo.com` | 587 | STARTTLS |
| SendGrid | `smtp.sendgrid.net` | 587 | STARTTLS, имя `apikey` |
| Custom SMTP | ваш собственный | 587 | редактируется |

`Custom SMTP` оставляет поля хоста, порта и неявного TLS редактируемыми. Порт
должен быть от 1 до 65535, а хост не длиннее 255 символов.

### Поля

| Поле | Примечания |
| --- | --- |
| From address | обязательно, кроме песочницы; не более 255 символов |
| SMTP username | обязательно, кроме песочницы; не более 255 символов |
| SMTP password | оставьте пустым, чтобы сохранить текущий пароль; не более 1024 символов |
| Enable delivery | переключатель включения и выключения |

Оставьте поле пароля пустым, чтобы сохранить текущий секрет. Введите новое
значение, чтобы заменить его. Секрет не покидает backend; страница знает только,
сохранён ли
он. Провайдеры требуют пароль приложения или API-ключ вместо пароля аккаунта, а
ссылка помощи ведёт к инструкциям провайдера.

### Тестовая доставка

Укажите адрес для отправки тестового письма. Результат проверки сохраняется и
отображается в панели. Если доставка выключена, письмо записывается в журнал
сервера. При неудачной отправке показывается текст ошибки.

### Песочница

Тестовый провайдер `Mailpit (sandbox)` перехватывает почту локально и не
отправляет её реальным получателям. Он указывает на sidecar Mailpit на
хосте: SMTP `localhost:1025`, веб-ящик `http://localhost:8025`. Учётные данные
не нужны. Затем панель песочницы предлагает `Open the inbox`. Письма попадают
в локальный веб-ящик, который работает только на этой машине.

## OAuth-вход

`/admin/oauth` настраивает вход через внешних провайдеров. Подзаголовок:
`Sign-in through external providers (Google, Yandex)`. Клиентский секрет не
покидает backend; оставьте поле пустым, чтобы сохранить текущий секрет.

Поддерживаются два провайдера:

| Провайдер | Поле статуса |
| --- | --- |
| Google | Enabled или Disabled |
| Yandex | Enabled или Disabled |

У панели каждого провайдера есть:

| Поле | Примечания |
| --- | --- |
| Client ID | обязательно, не более 255 символов |
| Client secret | оставьте пустым, чтобы сохранить текущий секрет; не более 255 символов |
| Callback URL | показан только для чтения, зарегистрируйте его в консоли провайдера |
| Enable sign-in | переключатель включения и выключения |

Callback URL выводится из публичного origin. После сохранения настроек на экране
входа появляется кнопка включённого провайдера.

## Безопасность

`/admin/security` управляет собственной защитой вошедшего мастера. Настройки
действуют только для вашего аккаунта: эти настройки применяются только к вашему
мастер-аккаунту,
обычные пользователи не затрагиваются.

### Двухфакторная аутентификация

| Элемент | Эффект |
| --- | --- |
| Enable 2FA | начинает регистрацию и показывает base32-секрет и `otpauth://` URL |
| Confirm | завершает регистрацию шестизначным кодом |
| Disable 2FA | выключает её; требует верный код |

Секрет хранится в зашифрованном виде. TOTP использует SHA-1, шестизначные коды и
период 30 секунд. Проверка допускает отклонение на один временной шаг. После
включения вход требует код после пароля.

### IP-список

Введите IP-адреса и CIDR-диапазоны через запятую или пробел. Пустой
список разрешает любой адрес. Поддерживаются адреса IPv4 и IPv6, а также
CIDR-диапазоны IPv4 и IPv6. При сохранении удаляются лишние пробелы и дубликаты.
Оператор может посмотреть свой список, но изменить его может только владелец.

Чтобы настроить доступ другого мастера, откройте **Masters**, выберите в меню
его действий **Доступ по IP** и сохраните адреса или диапазоны. Изменение сразу
действует на открытые сессии и записывается в журнал аудита.

Список проверяется на каждом запросе сессии мастера и при каждом обновлении,
а не только при входе. При изменении собственного списка сохранение без вашего
текущего адреса отклоняется, чтобы нельзя было потерять доступ во время работы.
В список другого мастера ваш адрес добавлять не требуется. За обратным
прокси задайте `TRUST_PROXY`, чтобы сервер видел настоящий адрес клиента.

### Подозрительная активность

Лента показывает до 50 групп событий за последние 24 часа: ошибки входа,
блокировки и отказы по IP при входе, обновлении сессии и запросах. В строке
указаны причина, этап, аккаунт, IP и время последнего события; неизвестные
аккаунт или IP отмечены явно. Повторы с одинаковыми аккаунтом, IP, причиной и
этапом объединяются за минуту; показываются их количество и время первого
события. Более ранние события доступны в журнале аудита в пределах срока его
хранения. Изменения IP-списка записываются в аудит отдельно, с автором и
целевым мастером.

## Трафик и лимит

`/admin/traffic` показывает живой поток запросов к API и глобальный лимит
частоты. Подзаголовок: `Live API request rate and the global rate limit`.

Три значения показаны и опрашиваются раз в секунду, пока страница видима:

| Показатель | Описание |
| --- | --- |
| Запросов / минуту | запросы, замеченные за последние 60 секунд |
| Отклонено (429) / минуту | запросы, отклонённые ограничителем за последние 60 секунд |
| Лимит | лимит, действующий сейчас |

График рисует запросы в секунду за последние 60 секунд, от старых к новым.

В поле лимита можно задать число от 1 до 1 000 000. Значок источника говорит,
задан лимит `set in this panel` или `from environment (THROTTLE_LIMIT)`.
Сохранение действует на следующий запрос, без перезапуска. Лимит доступен
только владельцу; оператор видит его только для чтения.

## Демо-рой

`/admin/demo` запускает рой ИИ-агентов на одноразовой доске, наблюдает за их
работой и затем убирает за собой. Подзаголовок: `Seed a demo board of AI
agents, watch them work, then clean up`.

Во время демонстрации автоматически обновляются три счётчика: Агентов, Карточек и Готово.
Строка доски показывает id доски запуска и, когда есть живая ссылка, ссылку
`Open live view` на `/s/<token>` и кнопку `Copy share link`.

Поля только для владельца:

| Поле | Диапазон | Примечания |
| --- | --- | --- |
| Board id | необязательно | пусто создаёт отдельную демо-доску |
| Агентов | от 1 до 100 | |
| Задач | от 1 до 1000 | количество создаваемых карточек |

`Start demo` создаёт демонстрационных пользователей и карточки, затем запускает сценарий. `Stop & clean up`
доступно, пока существуют созданные сценарием данные; оно подтверждается и удаляет ровно
записанные строки: доску, когда запуск её создал, её карточки, её демо-пользователей
и её ссылку.

Демонстрационный сценарий создаёт диспетчера и запрошенных агентов на
зарезервированном домене `@janosik.demo`, пять колонок рабочего процесса (Новые, В работе,
На ревью, Тестирование, Готово), набор меток и одну карточку на агента, затем
перемещает карточки по этапам. Каждый созданный id записывается, поэтому очистка
удаляет записи по сохранённым ID.

## Эксплуатация

`/admin/ops` позволяет менять настройки работающего сервера. Подзаголовок: `Flags,
maintenance, rate limits and data retention`. Изменения применяются сразу, без
перезапуска. Все настройки доступны только владельцу.

### Флаги функций

| Флаг | Описание | Источник по умолчанию |
| --- | --- | --- |
| `registration_open` | разрешить кому угодно создавать новый аккаунт | окружение `ALLOW_REGISTRATION` |
| `public_shares` | разрешить публичные ссылки на доски только для чтения | окружение `ALLOW_PUBLIC_SHARES` |
| `video_transcode` | перекодировать загруженные видео в компактный MP4 | включено |
| `realtime_sse` | стримить живые изменения доски по SSE | включено |

У каждого флага есть переключатель. Когда у флага есть индивидуальные значения
для пользователей, показывается их число. Действующее значение для пользователя
это индивидуальное значение, когда оно есть, иначе глобальный
переключатель, иначе значение окружения по умолчанию. Флаги применяются во
время запроса.

### Режим обслуживания

Переключатель обслуживания принимает необязательное сообщение (не более 500
символов). Когда он включён, каждый пользовательский запрос получает `503` с
сообщением; панель и вход остаются открытыми, поэтому владелец может отключить режим обслуживания.

### Лимит частоты

Для каждого пользователя можно задать лимит от 1 до 100 000 запросов в минуту.
Пустое значение отключает его, оставляя только глобальный IP-лимит. Лимит
применяется ко всем аккаунтам одинаково, у каждого свой счётчик. На пути
`/admin`, `/auth` и `/health` этот лимит не распространяется.

### Мягко удалённые данные и срок хранения

Срок хранения — это число дней до того, как очистка может удалить мягко
удалённые строки (от 1 до 3650, по умолчанию 30). Страница показывает число
карточек, комментариев, вложений и колонок с истёкшим сроком хранения, а также
расположение резервных копий, когда настроен `BACKUP_DIR`.

`Purge now` навсегда удаляет уже удалённые карточки, комментарии, вложения и
колонки, срок хранения которых истёк. Живые данные никогда не затрагиваются. Действие
подтверждается.

### Плановое обслуживание

Интервал очистки в минутах (от 0 до 10 080; 0 отключает расписание; по
умолчанию 60). `Run sweeps now` запускает весь набор сразу. Именованные
очистки:

| Очистка | Что удаляет |
| --- | --- |
| `purge-soft-deleted` | мягко удалённые строки (и целые доски) старше срока хранения |
| `sweep-codes` | истёкшие или использованные коды подтверждения и смены email |
| `sweep-tokens` | истёкшие или давно отозванные refresh-токены (пользователя и админа) |
| `sweep-shares` | ссылки на доски старше их TTL или отозванные более суток назад |
| `sweep-invitations` | просроченные ожидающие приглашения |
| `sweep-exports` | истёкшие фоновые экспорты данных и их файлы |
| `sweep-commands` | строки журнала команд старше срока хранения |
| `sweep-reminders` | устаревшие строки дедупликации напоминаний о сроке |
| `sweep-activity` | строки фида участников/комментариев старше срока хранения |
| `sweep-audit` | строки журнала аудита старше `AUDIT_RETENTION_DAYS` |
| `sweep-orphan-blobs` | файлы без ссылок из базы данных и оставшиеся `.tmp-*`, созданные более часа назад |

При настроенном Redis расписание очистки сохраняется в очереди задач. Без Redis
задачи выполняются внутри процесса, а расписание не сохраняется между
перезапусками.

### Плановая почта

В разделе настраиваются две периодические рассылки. Интервал дайджеста в часах (от 0 до 720;
0 отключает). Окно напоминания о сроке в часах (от 0 до 720; 0 отключает).
Получатели могут отказаться от обоих. Дайджест суммирует, что изменилось на
каждой доске с прошлого запуска. Напоминание перечисляет карточки, назначенные
пользователю, срок которых попадает в окно. Каждое напоминание отправляется
один раз на карточку, пользователя и срок.

### Панель очередей

Когда панель очередей включена, кнопка `Open queue dashboard` открывает
`/api/v1/admin/queues` в новой вкладке. В ней можно просматривать фоновые задачи
и запускать их повторно (Bull Board). Доступна только владельцу и требует Redis.

## Коммуникации

`/admin/comms` составляет рассылки и редактирует почтовые шаблоны.
Подзаголовок: `Announcements, mail and templates`. Запись доступна только
владельцу.

### Объявления

`New announcement` открывает двуязычный редактор:

| Поле | Примечания |
| --- | --- |
| Вкладки English / Русский | один логический анонс, по одному тексту на язык |
| Язык оригинала | исходная версия; используется как fallback |
| Заголовок | не более 200 символов на язык |
| Текст | не более 2000 символов на язык |
| Если перевода нет | `Требовать оба языка` (по умолчанию) блокирует публикацию, пока нет EN и RU; `Разрешить один язык с пометкой` публикует оригинал и показывает остальным явную плашку «доступно только на …» |
| Уровень | `Info`, `Warning` или `Alert` |
| Аудитория | все пользователи или выбранные |
| Получатели | для выбранных, автодополнение по каталогу пользователей |
| Also send by email | ставит локализованное письмо в очередь получателям |
| Расписание | необязательные начало и конец показа баннера |

Редактор показывает полноту каждого языка и предпросмотр баннера и письма для
обеих аудиторий. `Сохранить черновик` сохраняет недописанный анонс без письма;
`Опубликовать` применяет выбранную политику. Повторное редактирование уже
опубликованного анонса не отправляет письмо ещё раз: рассылка идёт только при
переходе из черновика в активное состояние, а `Email sent` это фиксирует.

Текст объявления — часть коммуникации продукта, а не данные доски, поэтому он
переводится. Баннер показывается на языке пользователя. Если перевода нет и
включён fallback, показывается оригинал с локализованной плашкой и правильным
`lang` для экранных дикторов. Письмо уходит каждому получателю на его языке, с
той же пометкой в теме и теле при отсутствии перевода. Аккаунты без сохранённого
языка получают язык браузера/приложения и запоминают его при следующем входе;
сохранённый язык действует на всех устройствах.

### Разовое письмо

Панель отправки письма принимает получателя, тему (не более 200 символов) и
текст сообщения (не более 20 000 символов). Результат возвращается, а отправка
попадает в аудит.

### Почтовые шаблоны

Редактируются пять шаблонов:

| Ключ | Метка |
| --- | --- |
| `verification_code` | Email verification code |
| `email_change_code` | Email change code |
| `email_changed_notice` | Email changed notice |
| `digest` | Board digest |
| `due_reminder` | Due-date reminder |

У каждого шаблона есть тема и HTML-тело. Плейсхолдеры показаны как `{{name}}`.
`Preview` показывает письмо с тестовыми данными во встроенном окне. `Save` сохраняет
переопределение и помечает шаблон как `custom`; `Reset to default` убирает
переопределение, и снова используется стандартный шаблон. Если шаблон не
изменён, показывается стандартный вариант, поэтому редактор не пуст.

### История объявлений

Полная история объявлений на отдельной странице `/admin/announcements`.
Подзаголовок: `{total} broadcasts, the full announcement history`.

| Колонка | Значение |
| --- | --- |
| Заголовок | исходный (или legacy) заголовок |
| Текст | тело |
| Языки | заполненные чипы `EN`/`RU` или `Legacy`, если язык неизвестен |
| Политика | `EN+RU` для строгой или `Fallback` для одного языка |
| Уровень | info, warning или alert |
| Аудитория | все пользователи или сегмент |
| Email | значок `email` и `письмо отправлено`/`письмо ожидает` |
| Активно | вкл или выкл |
| Создано | время создания |
| Автор | создавший мастер |

На странице есть поле поиска и вкладки статуса (активные, неактивные). Поиск
идёт по всем переводам, а не только по исходному тексту. Действия в строке:

| Действие | Эффект |
| --- | --- |
| Edit | открывает двуязычный редактор (вкладки, политика, предпросмотр, черновик/публикация) |
| Activate | выставляет `active` в true |
| Deactivate | выставляет `active` в false (баннер исчезает; отправленное письмо не отозвать) |
| Delete | удаляет объявление и его переводы |

## Наблюдаемость

`/admin/observability` показывает runtime, базу данных и состояние задач.
Подзаголовок: `Runtime, database and jobs`.

- Панель состояния сервера показывает Version, Environment, Uptime, Started, Database
  size и Commit.
- Панель frontend описывает версию и параметры клиентского приложения: App
  version, Build, Commit, Theme, Service worker, Display и Connection.
- Панель jobs показывает Transcode (pending/done/failed), Realtime
  (boards/clients) и Demo runner (вкл или выкл).
- Сетка очередей показывает имя каждой очереди, счётчики pending, done и
  failed и её backend (`redis` или `memory`).
- Таблица `Biggest tables` перечисляет до 12 таблиц с числом записей и размером.
- Панель health перечисляет `database` (`SELECT 1` и его задержку),
  `realtime` (каналы доски) и `maintenance` (вкл или выкл).

## Баннер объявлений для пользователей

Активные объявления доходят до вошедших пользователей баннером под заголовком
приложения. Эндпоинт — это `GET /announcements/active`, доступный через обычный
пользовательский контур аутентификации, поэтому посетитель без авторизации не
получает объявления, а пользователь видит только объявления, адресованные ему.
Баннер запрашивает текущий язык интерфейса и перезапрашивается при его смене.

Каждый баннер стилизован по уровню (info, warning, danger) и может быть скрыт.
Скрытие запоминается для каждого объявления в `localStorage`, поэтому
пользователь видит каждое один раз; смена языка не возвращает скрытый баннер.
Если перевода на язык пользователя нет, политика объявления решает: строгое
объявление в таком состоянии не публикуется, а fallback-объявление показывает
оригинал с локализованной плашкой «Это объявление доступно только на …».
