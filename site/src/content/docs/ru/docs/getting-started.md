Janosik это канбан-приложение для планирования работы на колонках с
карточками. Оно устанавливается как PWA и работает в одном из двух режимов.

## Два режима работы

| Режим | Бэкенд | Где хранятся данные | Для чего подходит |
| --- | --- | --- | --- |
| Локальный | нет | в браузере (`localStorage`) | знакомство, работа офлайн, один человек |
| Серверный | API на NestJS и PostgreSQL | в базе данных за учётной записью | учётные записи, общие доски, реальное время |

Режим задаётся сборкой. Когда интерфейс настроен на работу с API
(`VITE_API_URL`, по умолчанию `/api/v1`), он работает в серверном режиме; без
бэкенда он остаётся в локальном режиме. Подробно оба режима описаны в
[Руководстве пользователя](user-guide/).

Меню «Помощь» ссылается на доки на том же источнике, так их и отдаёт
self-host образ. При раздельном деплое (приложение и сайт на разных хостах)
интерфейс указывается на сайт через `VITE_SITE_URL` (источник сайта, со
слешем на конце).

## Самый быстрый путь: образ для self-hosting

Один контейнер обслуживает всё приложение (API по `/api/v1`, собранное SPA и
маркетинговый сайт) рядом с PostgreSQL и Redis.
[Self-hosting](self-hosting/) содержит полное руководство; короткая версия:

```bash
curl -O https://raw.githubusercontent.com/VitalyTolstik/janosik/main/docker-compose.yml
curl -o .env https://raw.githubusercontent.com/VitalyTolstik/janosik/main/.env.example
# отредактируйте .env: задайте JWT_SECRET (openssl rand -hex 32) и PUBLIC_ORIGIN
docker compose up -d
```

Миграции выполняются при запуске. Откройте приложение, создайте учётную
запись, затем закройте регистрацию. [Self-hosting](self-hosting/) описывает
первый запуск по шагам.

## Из исходников (разработка)

Требования: Node.js 22.17 или новее и npm.

Локальному режиму бэкенд не нужен:

```bash
npm install
npm run dev
# http://localhost:5173/
```

Серверный режим добавляет контейнер PostgreSQL и API. Шаги из исходников для
каждой платформы описаны в [Self-hosting](self-hosting/).
