Janosik — канбан-приложение для планирования задач с помощью колонок и карточек.
Его можно установить как PWA. Приложение работает в **серверном режиме**: доски
хранятся в PostgreSQL и доступны после входа через API на NestJS.

Локальная логика доски может работать без сервера, но **выпускаемая версия и
сервер разработки всегда обращаются к API**. При запуске через `npm run dev` или
открытии собранного приложения вы увидите **экран входа**, а не
демо-доску без логина. Единственный режим без бэкенда («локальный») — это тот,
что используют **модульные тесты**: редьюсер с хранением в `localStorage` и
заранее заполненной демонстрационной доской.

Образ для самостоятельного размещения обслуживает документацию и приложение по одному базовому адресу. При
раздельном деплое (приложение и сайт на разных хостах) ссылки между ними нужно
настроить вручную: `VITE_SITE_URL` (сборка UI) направляет **Help →
Documentation** на сайт, а `PUBLIC_APP_URL` (сборка сайта) направляет **Sign
in** / **Create account** на приложение — см.
[Раздельный деплой](/ru/docs/self-hosting/). При разработке используются два сервера (приложение
`:5173`, сайт `:4321`), так что задавайте обе.

## Самый быстрый путь: образ для self-hosting

Один контейнер обслуживает всё приложение (API по `/api/v1`, собранное SPA и
маркетинговый сайт) рядом с PostgreSQL и Redis.
[Установка на своём сервере](/ru/docs/self-hosting/) содержит полное руководство; короткая версия:

```bash
curl -fsSLO https://raw.githubusercontent.com/VitalyTolstik/janosik/main/install.sh && bash install.sh
```

При установленных Docker, Compose, curl и OpenSSL команда запустит пробную
версию на `http://localhost:3210/app/`. Для этого нужны опубликованные
стабильный релиз и образ. Создайте учётную запись и закройте регистрацию.
Раздел [Установка на своём сервере](/ru/docs/self-hosting/) описывает установку,
обновление, MCP и HTTPS.

## Из исходников (разработка)

Требования: Node.js 22.17 или новее — в `.nvmrc` указана основная версия **24**
(`nvm install && nvm use`).

Сначала настройте API, потом поднимайте базу: dev-compose читает `POSTGRES_*`
из `backend/.env`, поэтому файл должен существовать до `docker compose up`.

```bash
cp backend/.env.example backend/.env                 # задайте JWT_SECRET
docker compose -f backend/docker-compose.yml up -d   # PostgreSQL на :5433
npm run prisma:deploy -w backend
npm run build:backend
npm run start -w backend                             # API на :3000
npm run dev                                          # UI на :5173 (проксирует /api → :3000)
```

Зарегистрируйтесь на `http://localhost:5173` (регистрация открыта по умолчанию)
и создайте первого мастера командой
`npm run admin:create -w backend -- --email me@example.com` для панели
`/admin`. Инструкции запуска из исходников для каждой платформы — в
[Установка на своём сервере](/ru/docs/self-hosting/).

### Маркетинговый сайт (Astro) в dev

Сайт и документация запускаются на отдельном сервере разработки (`npm run dev:site`, порт 4321). В dev
приложение **не** отдаётся по `/app/` на сайте — этот путь принадлежит
образ для самостоятельного размещенияу, где один сервер отдаёт сайт по `/`, а приложение по `/app/`.
Поэтому для кнопок «Sign in» и «Create account» на сайте нужно указать адрес
сервера разработки интерфейса, иначе откроется страница 404:

```bash
PUBLIC_APP_URL=http://localhost:5173 npm run dev:site
```

### Исходящая почта по умолчанию выключена

Без настроенного SMTP API работает в **режиме записи в журнал**, а регистрация
с паролем недоступна. До регистрации настройте почтовый транспорт
(см. [Почтовая служба](/ru/docs/admin/settings/) и
[Инструкции по эксплуатации](/ru/docs/runbooks/)). Для локальной песочницы:

```bash
docker run -d --name janosik-mailpit --restart unless-stopped \
  -p 1025:1025 -p 8025:8025 axllent/mailpit
# SMTP localhost:1025, веб-ящик http://localhost:8025
```
