Сервер `@janosik/mcp` открывает доску любому MCP-клиенту (Claude, Cursor,
VS Code, opencode, Codex). Агент умеет перечислять доски, читать доску и
создавать, перемещать, комментировать, отмечать, назначать, связывать и
расшаривать карточки по персональному API-ключу. Записи идут через тот же
журнал команд, что и приложение, поэтому их можно откатить, и они видны
всем, кто смотрит доску, в реальном времени.

## Настройка

Создайте ключ в разделе **Аккаунт → API-ключи** (он начинается с `jnk_`) и
добавьте сервер в MCP-клиент:

```json
{
  "mcpServers": {
    "janosik": {
      "command": "npx",
      "args": ["-y", "@janosik/mcp"],
      "env": {
        "JANOSIK_URL": "https://boards.example.com",
        "JANOSIK_TOKEN": "jnk_…"
      }
    }
  }
}
```

`JANOSIK_URL` это источник вашего инстанса, `JANOSIK_TOKEN` это ключ. Оба
можно передать и флагами `--url` и `--token` (токен лучше задавать через
`env`: флаг виден в списке процессов). Серверу нужен запущенный инстанс,
доступный по `JANOSIK_URL` — например `http://localhost:3000`, если запускаете
из исходников. Добавьте `JANOSIK_APP_BASE` (например `/app`), если приложение
живёт не в корне сайта; он нужен для сборки ссылок на доску. Self-host образ
отдаёт приложение по `/app/`, так что там задайте `JANOSIK_APP_BASE=/app`.

Загрузка и скачивание вложений, а также экспорт доски в файл трогают диск
машины, где запущен сервер, поэтому они выключены, пока не задан
`JANOSIK_MCP_ALLOW_FS=1`. Добавьте `JANOSIK_MCP_FS_ROOT=/path`, чтобы
ограничить их одним каталогом: симлинки за его пределы отклоняются, а
существующие файлы никогда не перезаписываются.

## Инструменты

Инструменты разбиты на группы. По умолчанию включены группы для работы с
доской: доски, колонки, карточки, метки, чек-листы, связи карточек,
комментарии, активность и вложения. Группы, которые меняют, кто видит доску,
или действуют от имени аккаунта (`members`, `invitations`, `shares`,
`account`), включаются явно:

| Настройка | Что делает |
| --- | --- |
| `JANOSIK_MCP_TOOLSETS` | Группы через запятую, например `default,members`, или `all`. |
| `JANOSIK_MCP_READONLY=1` | Только инструменты, которые ничего не меняют. |

У каждого инструмента данных есть `response_format`: `"markdown"` (по
умолчанию) или `"json"`. Имена всех инструментов начинаются с `janosik_`,
чтобы не конфликтовать с другими серверами.

Типичный прогон:

1. `janosik_list_boards` находит доску.
2. `janosik_get_board` читает колонки, карточки и метки (на большой доске
   передайте `columnId`).
3. Дальше точечные инструменты, например `janosik_create_card`, затем
   `janosik_move_card` и `janosik_add_comment`.

Запись, которая ничего не изменила (например, id нет на доске), возвращается
как ошибка, поэтому агент не примет её за успех. Инструменты, которые строят
запись по прочитанной доске, повторяют попытку, если другой агент успел её
изменить, а `janosik_update_card` принимает `expectedDescription`, чтобы
править общий текст, только если его никто не менял.

## Скилл: научите агента, как работать

Сервер даёт агенту инструменты, но не объясняет, как пользоваться ими хорошо.
**Скилл `janosik`** — это вторая половина, поведение: плейбук, по которому
агент ведёт карточку как хороший напарник:

- **Сначала читать, потом писать** — перечислить доски, прочитать доску,
  прочитать комментарии и активность карточки, прежде чем что-то трогать.
- **Взять и наполнить карточку** — назначить на себя, перевести в *In Progress*,
  написать описание и чек-лист, которые понятны сами по себе.
- **Комментировать на каждом шаге** — короткая заметка, когда берёт карточку,
  когда шаг готов и когда передаёт дальше. Лента комментариев — это история
  карточки.
- **Вести вперёд** — Backlog → In Progress → Review → Done, с ручной проверкой
  на шаге Review.
- **Возвращать при баге** — если карточка неверна или что-то ломает, агент
  переводит её **назад** (в Bugs или In Progress), с комментарием про дефект и
  пунктом чек-листа на фикс, вместо того чтобы отметить Done. Этот обратный
  перевод вместе с комментарием и есть след истории.

Установите скилл, положив каталог `skills/janosik/` в каталог скиллов вашего
харнесса:

| Харнесс | Куда |
| --- | --- |
| Claude Code | `~/.claude/skills/janosik/` (или `.claude/skills/` в проекте) |
| opencode | `~/.config/opencode/skills/janosik/` (или `.opencode/skills/`) |
| Agent-compatible харнессы | `~/.agents/skills/janosik/` (или `.agents/skills/`) |
| Codex / без поддержки скиллов | Вставьте `SKILL.md` в свой `AGENTS.md` |

Скилл ссылается на инструменты по именам и не требует настройки. Он лежит в
репозитории в каталоге `skills/janosik/` (поведение в `SKILL.md`, плюс
`references/templates.md` и `references/recipes.md`).

### Agent-ready карточка

Скилл просит агента оставить карточку, которую рой подхватит без человека —
одна форма, одинаковая на каждой карточке:

- **Секции описания** — `## Why`, `## Scope`, `## Acceptance criteria`
  (чек-боксы), `## Out of scope`, `## Verify` (точная проверка, доказывающая
  результат).
- **Чек-лист `Definition of Done`** — карточка Done только когда все пункты
  отмечены; неотмеченный объясняется комментарием, а не пропадает молча.
- **Типизированные комментарии** — каждый начинается с `[status]`, `[question]`,
  `[blocker]`, `[evidence]` или `[handoff]`, поэтому тред машиночитаем и
  фильтруем.
- **Зарезервированные метки** — `agent:blocked`, `agent:needs-human`,
  `agent:verified`, чтобы человек видел состояние роя одним взглядом.

## Права

Ключ действует от имени создавшего его пользователя с теми же ролями: агент
видит только доски, где этот пользователь участник, редактирование требует
роли `MEMBER`, а управление участниками и ссылками требует `ADMIN`. Отзовите
ключ в панели аккаунта, чтобы отключить агента.

Текст карточек и комментарии пишут другие люди и агенты, поэтому всё, что
агент читает с доски, считайте недоверенным вводом. Дайте каждому агенту свой
аккаунт и ключ: в ленте активности будет видно, какой агент что сделал, а
отзыв одного ключа остановит одного агента.

Сервер открыт в репозитории, в каталоге `mcp/`, а скилл — в `skills/janosik/`;
полный список инструментов в README сервера.
