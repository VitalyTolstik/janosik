Рабочий процесс — необязательный слой правил над колонками доски. Колонка
карточки и есть её статус; процесс определяет, в какую колонку карточка может
перейти дальше. По умолчанию он выключен: доска без процесса разрешает любые
перемещения, как и до появления функции.

Редактировать процесс может только **ADMIN** доски. Платформенный `OWNER` или
`OPERATOR` открывает тот же редактор из мастер-панели от имени владельца
доски; изменение идёт через журнал команд и `AdminAuditLog`.

## Открыть редактор

Администратор доски нажимает шестерёнку в шапке (`Настройки доски`). Диалог
открывается на вкладке `По колонкам`, а в рельсе выбрана самая нагруженная
колонка-источник. Все участники могут прочитать правила только для чтения в
контекстном меню карточки — `Правила процесса`, — а также в меню шапки
`Данные и резервные копии`; второй путь работает и на доске без карточек.

## Включить контроль

Переключатель `Контроль включён` в шапке диалога включает проверку. Пока он
выключен, правила сохраняются на будущее, но все перемещения разрешены.

Включённому процессу нужны минимум две колонки и хотя бы один активный
переход. Иначе редактор не даст сохранить, а API отклонит ту же форму — доска
не может «замёрзнуть» из-за списка, где все переходы выключены.

## Правила по колонкам

Колонки доски образуют горизонтальный рельс. У каждой видны акцент, число
карточек и число правил, которые на неё ведут. Выбор колонки показывает по
строке на каждую другую колонку в порядке доски:

- **Вперёд / назад** — находится ли цель позже или раньше источника.
- **Роли** — `ADMIN`, `MEMBER` или обе. Наблюдатель не двигает карточки.
  Пустой список ролей запрещён.
- **Условия** — должны выполняться все выбранные:
  - задан исполнитель;
  - задан срок;
  - описание не пустое;
  - все пункты чек-листов выполнены (карточка без чек-листов проходит).
- **Разрешено / запрещено** — для отсутствующего правила есть `Разрешить`;
  выключенное правило остаётся в списке (пунктиром), но не пропускает карточки.

Выбор строки открывает инспектор справа (на планшете — под списком):

- **Обратный переход** — создаёт зеркальное ребро с теми же ролями и
  условиями. Без него отмена этого перемещения будет запрещена.
- **Переход действует** — временно выключает одно ребро, не удаляя его.
- **Проверка на карточке** — проверяет выбранное правило на реальной карточке
  и показывает причину, если перемещение заблокировано.

Сортировка внутри колонки (мышью или клавиатурой) разрешена всегда:
диагональ — не переход.

`Применить шаблон` и `Сбросить правила…` живут в компактном меню `…` в шапке
диалога. Шаблон заполняет цепочку соседних прямых и обратных рёбер; дальше её
можно править. Колонка без входящих и исходящих рёбер помечается в редакторе
как «вне процесса».

## Полная матрица

Вкладка `Матрица` показывает полную сетку «откуда × куда» для аудита покрытия.
Нажмите клетку, чтобы разрешить переход или открыть его; галочка — разрешено,
пунктир — выключено, точка — правила нет, янтарная метка — у правила есть
условия. На компьютере инспектор остаётся рядом с матрицей.

## Глобальные переходы

Глобальный переход (`Из любой колонки → колонка`) действует, только если для
пары нет специфичного ребра. Специфичное ребро всегда важнее, поэтому
глобальное правило «эскалация» с ролью не обходит более строгую пару.
Глобальные переходы вынесены в одну компактную строку под списком колонки.

## Начальная и завершающие колонки

Настройки старта и готовности живут в одной компактной строке под глобальными
переходами:

- **Стартовая колонка** — семантический старт. MCP использует её для
  `janosik_list_ready_cards` и `janosik_wait_for_work`, а также как колонку
  восстановления по умолчанию, вместо предположения «первая колонка».
- **Колонки готовности** — семантическое завершение. Проверка Definition of
  Done в MCP смотрит на них, а не на последнюю колонку; колонок готовности
  может быть несколько. Пустой список означает последнюю колонку для
  совместимости.

В этой версии обе настройки не ограничивают создание карточек.

## Клавиатура и мобильный вид

- В рельс можно войти одним `Tab`; `←`/`→`, `Home` и `End` переключают
  колонки.
- В списке правил `↑`/`↓` двигают по строкам, `Space` включает или выключает
  существующее правило, `Enter` открывает его в инспекторе.
- В матрице вся сетка — одна остановка `Tab`; стрелки двигают фокусную клетку,
  `Home`/`End` прыгают внутри строки, `Space`/`Enter` активируют клетку.
- На телефоне диалог открывается на весь экран, рельс прокручивается
  горизонтально со снапом, а инспектор становится аккордеоном под списком.
  Футер учитывает safe-area; сохранение, ошибки и несохранённое состояние
  объявляются через `aria-live`.

`Esc` или кнопка закрытия закрывают чистый диалог сразу. При несохранённых
изменениях появится подтверждение, а после закрытия фокус вернётся на
шестерёнку. `prefers-reduced-motion` отключает переходы рельса и инспектора.

## Как выглядит запрещённое перемещение

Запрещённая цель остаётся видимой, но недоступной: колонка при перетаскивании
затемняется, показывает замок и причину; меню карточки, диалог карточки и
выбор колонки в таблице показывают цель неактивной с причиной. Если всё же
отпустить карточку, появится тост с причиной и списком доступных колонок, а
карточка останется на месте.

Общий reducer и API применяют одно и то же правило. API отвечает
`409 { "conflict": "workflow", ... }` с машинным кодом и доступными целями;
оптимистичное состояние откатывается. Лимиты WIP проверяются после процесса,
поэтому запрещённый переход никогда не выдаётся за «колонка заполнена».

Архивация и удаление не обходят процесс: восстановление архивной карточки или
отмена удаления тоже меняет колонку. Карточка может вернуться в исходную
колонку, а любая другая цель должна быть разрешённым переходом с теми же
проверками роли и условий. Диалог архива показывает запрещённые цели
неактивными с причиной, а прямой вызов API получает тот же
`409 workflow`.

## Отмена, колонки и старые доски

- Сохранение процесса — одна отменяемая команда; Ctrl/Cmd+Z возвращает
  предыдущие правила. Если другой администратор изменит правила, пока ваш
  редактор открыт, он предупредит об этом; перед сохранением перезагрузите
  актуальные правила.
- Сохранённый процесс, который не удаётся прочитать (повреждённые данные или
  более новая схема), работает по принципу fail-closed: все межколоночные
  перемещения запрещены, пока администратор не исправит и не сохранит его.
- Удаление колонки не переписывает процесс: её правила «засыпают» и оживают,
  если отмена вернёт колонку с тем же id.
- Новая колонка не подключается автоматически; добавьте её рёбра в редакторе.
- Экспорт/импорт доски переносит процесс и переназначает id колонок; переход,
  чья колонка исчезла, отбрасывается. Файлы версии 1 (без процесса) по-прежнему
  импортируются; новый экспорт имеет версию 2 и требует клиент, который её
  понимает.
- Публичные ссылки показывают правила только для чтения и никогда не
  принимают перемещение.
