TASK-179 разделяет работу с агентами на три слоя: глобальную контрольную
комнату, операционную модалку доски и настройку в Board Settings. Все слои
используют одни и те же компоненты согласований, сессий, запусков и статусов,
поэтому свидетельства не расходятся между экранами.

## Три поверхности

| Поверхность | Адрес | Для чего |
| --- | --- | --- |
| Глобальная страница | `/agents` | Всё, что требует человека или охватывает несколько досок: Attention, Sessions, Runs. |
| Agent Control на доске | кнопка-бот в шапке доски | Операционная работа по одной доске: Inbox, Live, Runs. |
| Board Settings → Agents & automation | шестерёнка → Agents & automation | Настройка: destructive mode, триггеры согласования, лимиты, TTL и роли согласующих. |

На доске в шапке ровно одна кнопка-бот. Она открывает Agent Control.
Глобальная страница доступна из ссылки модалки **All agents across boards** и
из Account. На `/agents` шапка глобальная: названия доски, участников, share,
шестерёнки и undo/redo там намеренно нет.

## Глобальная страница `/agents`

В левом рейле три раздела:

- **Attention** — ожидающие согласования на досках, где вы ADMIN, плюс живые
  сессии без свежего heartbeat. MEMBER и VIEWER видят только stale-сессии;
  запросы согласований для них не отправляются, поэтому раздел не
  превращается в 403 с кнопкой Retry.
- **Sessions** — все доступные вам сессии, по умолчанию сгруппированные по
  доске, внутри доски — по токену. Переключатель **Group by Agent (token)**
  меняет группировку. У сессии остаётся настоящий lifecycle-статус (`active`,
  `idle`, `waiting_approval`, `completed`, `failed`, `cancelled`); пауза и
  stale — отдельные признаки рядом с ним. «No heartbeat · N min» — не
  lifecycle-статус.
- **Runs** — история запусков в выбранной области, сначала новые: фильтры по
  статусу, типу, времени, токену и сессии, total/load more, деталь и
  условный откат.

В верхней панели есть выбор доски (`All boards` или одна доска), счётчик
раздела, поиск, `Updated Ns ago` с Refresh и **Manage tokens**
(Account → API keys). Поиск и фильтры живут в URL, поэтому перезагрузка,
копирование ссылки и back/forward возвращают тот же вид.

### Пустые состояния и ошибки

- Если сессий ещё нет, показываются **Create API key** и **Read docs**; ссылка
  ведёт в Account → API keys, а не в тупик.
- Если фильтр ничего не нашёл, есть **Clear filters**.
- Неизвестный или отозванный `?board=` показывает понятное сообщение и
  действие восстановления, а не притворяется пустой областью.
- Если запрос сессий одной доски упал, уже загруженные строки остаются,
  недоступная доска помечается stale, а баннер предлагает Retry.
  Подтверждённые 403/отзыв/удаление доски удаляют её данные, а не держат их
  как «stale». Один общий timestamp не объявляет частично упавший fan-out
  свежим.

### Согласования в Attention

Согласование — это запрос агента применить точный план. Откройте его, чтобы
увидеть человеческое описание, риск, доску и цель, заявителя/агента/сессию,
точные команды или операции, хеш плана и TTL, а также запись решения.

- **Approve** просит подтвердить точный хеш плана. Одобрение разрешает только
  этот план; агент должен повторить ту же операцию с id согласования.
  Одобрение не применяет план за агента.
- **Reject** требует причину в UI и записывает её в запись решения.
- **Cancel request** отменяет запрос, который вы вправе отозвать.
- Действующий срок вычисляется из статуса и TTL на клиенте. Если TTL истёк
  при открытой странице, Approve отключается без перезагрузки, а сохранённая
  строка `pending` читается как `Expired`.
- `Consumed` означает, что план применён; согласование одноразовое и не может
  быть повторено.
- Откат условен: поздние правки создают конфликты, отсутствующие preimages
  или истёкшее окно хранения могут его заблокировать. UI не обещает
  гарантированного восстановления и не выдумывает before/after diff.

### Сессии и ручное управление

Строка сессии показывает доску, имя токена/агента, lifecycle-статус,
heartbeat, метки stale/paused, текущую карточку и запуск, последнее имя
сессии.

| Действие | ADMIN | MEMBER/VIEWER | Примечание |
| --- | --- | --- | --- |
| Пауза/продолжение сессии | да | нет | Причина + подтверждение; начатые запросы завершаются, claims остаются. |
| Завершение сессии | да | нет | Подтверждение; необратимо, освобождает claims. |
| Пауза/продолжение доски | да | нет | Подтверждение + причина, один баннер; чтение, heartbeat и завершение работают. |
| Остановить токен / всех / отозвать | владелец в Account | владелец в Account | Никогда не действие board ADMIN. |
| Открыть доску/карточку | да | да | `Open board` сохраняет deep link доски или карточки. |

Пауза токена или доски показывается меткой и не снимается из действий
сессии. `Token settings` виден только для собственного токена; чужой токен
доступен только для чтения и не ведёт в чужой Account.

## Agent Control на доске (модалка)

Модалка использует shell настроек доски и вертикальный рейл:

- **Inbox** — согласования этой доски, все статусы, с той же деталью, хешем,
  TTL и действиями решения. Только ADMIN.
- **Live** — пауза/продолжение доски и пауза/продолжение/завершение сессий.
  ADMIN получает действия; MEMBER/VIEWER видят те же данные только для чтения
  и начинают с Live. Здесь нет Stop token или Stop all: единственный путь к
  токену — **Manage tokens** → Account → API keys.
- **Runs** — запуски доски, деталь, preview и revert. Участники могут
  смотреть и делать preview; применять revert может только ADMIN.
  Preimages/diff — только ADMIN; участники видят таймлайн, атрибуцию,
  конфликты и уведомление о режиме только для чтения.
- **Политики в модалке нет.** Ссылка **Open policy settings** закрывает
  модалку и открывает Board Settings на разделе Agents & automation.

Мобильный режим: полный экран на 390, одна прокрутка, вкладки рейла и
закрытие не меньше 44 px, фокус возвращается на кнопку-бот, которая открыла
модалку. На 1024 лист и его scrim начинаются ниже реальной шапки доски и не
накрывают её невидимым оверлеем.

## Board Settings → Agents & automation

Шестерёнка доступна только ADMIN. В shell настроек два верхних раздела:

- **Workflow** — прежний редактор Columns/Matrix.
- **Agents & automation** — политика агентов:
  - destructive mode: **Require approval** или **Hard deny**;
  - триггеры согласования: non-destructive действия редактируются,
    destructive показаны отключёнными с «covered by destructive mode»;
  - максимум команд на запуск (1–100), карточек на запуск (1–50), TTL
    согласования (5–1440 минут);
  - роли согласующих: фиксированный `ADMIN`, только чтение;
  - `Using safe defaults` и сброс, отключённый, когда политика уже по
    умолчанию;
  - dirty-состояние общее для обоих разделов, защита от закрытия, Save/Cancel
    и inline-валидация;
  - сохранение через compare-and-swap: если политику уже изменил другой
    администратор, Reload сохраняет ваш черновик, а merge применяет только
    реально изменённые вами поля. Если одно и то же поле изменили с обеих
    сторон, появляется явный выбор; устаревший черновик целиком никогда не
    перезаписывает новую политику.

## Права

| Возможность | ADMIN | MEMBER | VIEWER | Токен агента (PAT) |
| --- | --- | --- | --- | --- |
| Список/деталь согласований | да | нет (не запрашивается) | нет (не запрашивается) | не через эту страницу |
| Approve / reject | да | нет | нет | нет |
| Cancel approval | да | нет | нет | только requester |
| Список/деталь сессий | да | да | да | observer+ |
| Пауза/продолжение сессии | да | нет | нет | нет |
| Завершение сессии | да | нет | нет | владелец |
| Пауза/продолжение доски | да | нет | нет | нет |
| Остановить токен / всех | владелец в Account | владелец в Account | владелец в Account | нет |
| Список/деталь/preview запусков | да | да | да | да |
| Preimages / diff | да | нет | нет | нет |
| Применение revert | да | нет | нет | нет |
| Чтение/изменение политики | да | нет | нет | нет |
| Создание API-ключа | да | да | да | нет |

Роли — по доске. Быть ADMIN на одной доске и MEMBER на другой — поддерживаемый
случай: счётчики, вкладка Inbox, шестерёнка и уведомления только для чтения
следуют роли доски в области видимости. `/agents` — страница браузерной
сессии; read-only aggregation отклоняет PAT с `pat_forbidden`, а не разносит
scope PAT по доскам.

## URL и deep links

Глобальная страница хранит фильтры и выбор в URL:

| Параметр | Значение |
| --- | --- |
| `?section=attention\|sessions\|runs` | Раздел рейла; по умолчанию `attention`. |
| `?board=<id>` | Одна доска или `All boards`, если параметра нет. |
| `?token=<id>` | Старый фильтр токена; по-прежнему принимается. |
| `?agent=<id>` | Канонический фильтр токена/агента (приоритет над `token`). |
| `?status=…`, `?time=…`, `?q=…` | Статус, окно последней активности и поиск. |
| `?group=board\|token` | Группировка сессий. |
| `?session=<id>` | Открыть деталь сессии. |
| `?approval=<id>` | Открыть деталь согласования; **требует `board`**. |
| `?run=<id>` | Открыть деталь запуска; **требует `board`**. |

Примеры:

```text
/agents?section=sessions&board=b1&token=t1
/agents?section=attention&board=b1&approval=a1
/agents?section=runs&board=b1&run=r1
/agents?section=runs&board=b1&status=failed&time=24h&agent=t1
```

Copy-link запуска всегда включает `board`; скопированный URL переживает
перезагрузку и back/forward. `/agents/:tokenId` остаётся каноническим deep link
токен → сессии и не редиректится. `?approval=` или `?run=` без `?board=`
показывают сообщение восстановления вместо угадывания доски.

У модалки доски нет отдельного URL; используйте маршрут доски и единственную
кнопку-бот. Закрытие/Escape возвращает фокус на бота, а глобальная ссылка —
на `Agents` в шапке.
