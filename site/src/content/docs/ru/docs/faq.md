Короткие ответы на частые вопросы. Каждый ссылается на страницу, где
описаны детали.

## Под какой лицензией Janosik?

AGPL-3.0, авторские права 2026 Vitali Toustsik. Вы можете использовать,
размещать у себя, форкать и изменять его, в том числе коммерчески.
Единственное условие, которое AGPL-3.0 добавляет: если вы запускаете
изменённую версию как сетевой сервис, вы должны предложить её исходный код
людям, которые ею пользуются.

Лицензия покрывает код, а не имя. «Janosik» и логотип-перо обозначают этот
проект. Форки приветствуются под другим именем и логотипом и не должны
выдавать себя за официальный Janosik. См.
[Политику товарных знаков](https://github.com/VitalyTolstik/janosik/blob/main/TRADEMARK.md).

## Можно ли разместить Janosik на своём сервере?

Да. Облачная версия пока недоступна, но вы можете запустить Janosik на своём
сервере одним контейнером приложения. Данные будут храниться у вас. Инструкции —
в [руководстве по установке](/ru/docs/self-hosting/).

## Где хранятся мои данные?

Janosik работает в серверном режиме: доски хранятся в PostgreSQL, на Docker-томе
`janosik-pgdata`, а вложения и аватары на томе `janosik-uploads`.
[Установка на своём сервере](/ru/docs/self-hosting/) перечисляет все места хранения данных.
(Режим без бэкенда, «локальный», существует только в unit-тестах, где данные
лежат в `localStorage`.)

## Работает ли приложение офлайн?

PWA кэширует свою оболочку, поэтому открывается при отключённой сети. Для
загрузки досок и сохранения изменений нужна сеть. Если API недоступен,
приложение откатывает правку и показывает сообщение. Уже загруженные данные
остаются доступны в открытой вкладке. Постоянной очереди отправки нет: при
перезагрузке несохранённые изменения теряются.

## Как сделать резервную копию данных?

Снимите дамп базы данных и архив загрузок; и то, и другое описано в
[инструкциях по эксплуатации](/ru/docs/runbooks/). Доску также можно экспортировать
в JSON и импортировать обратно из **«Данные и бэкапы»** в приложении.

## Можно ли переносить доски между экземплярами?

Да — экспортируйте доску в JSON и импортируйте её в другой экземпляр (из
**«Данные и бэкапы»**). Чтобы перенести весь экземпляр, восстановите дамп базы
данных на целевом (см. [Инструкции по эксплуатации](/ru/docs/runbooks/)).

## Какие браузеры поддерживаются?

Janosik — PWA-приложение на React 18. Оно устанавливается и работает в
современных браузерах, поддерживающих service workers и прогрессивные
веб-приложения.

## Какая версия Node.js нужна бэкенду?

Node.js 22.17 или новее; в репозитории выбрана основная версия **24** в `.nvmrc` (`nvm use`), и
она используется в CI. Минимальная версия указана в поле `engines` пакета backend. Проверьте
командой `node -v`. Шаги из исходников описаны в
[Установка на своём сервере](/ru/docs/self-hosting/).

## Почта отправляется «из коробки»?

Нет — **доставка почты по умолчанию выключена.** Без настроенного SMTP API
работает в **режиме записи в журнал**: коды подтверждения и уведомления пишутся в лог сервера,
а не отправляются, и адрес электронной почты подтверждается автоматически при
регистрации. Ничего не отправляется,
пока вы не настроите транспорт в [Почтовая служба](/ru/docs/admin/settings/) (или
переменными `SMTP_*`). Для локального теста письма ловит Mailpit на
`localhost:1025`, веб-ящик — `http://localhost:8025`:

```bash
docker run -d --name janosik-mailpit --restart unless-stopped -p 1025:1025 -p 8025:8025 axllent/mailpit
```

## Как агенты и скрипты используют API?

Они аутентифицируются личным API-токеном. Создайте его в панели учётной
записи, затем отправляйте в заголовке `Authorization` как `Bearer jnk_<token>`.
Токен работает с досками, участниками, ссылками и приглашениями, но не с
управлением ключами, паролем или почтой: для этого нужен вход в браузере.
Базовый путь API — это `/api/v1`. Изменения доски проходят через журнал команд
по `POST /boards/:id/commands`. См. [Справочник API](/ru/docs/api/) и
[API команд](/ru/docs/api/commands/).
