## 0. Как работать с этим файлом (для ИИ-агентов)

1. **Одна задача = одна ветка = один пулл-реквест.** Перед началом итерации
   создай ветку `feature/TASK-{номер}-{slug}`. Пушишь — человек делает ревью
   и мержит сам. **Не мержить свою работу самостоятельно.**
2. **Иди строго по порядку §6.** Не прыгай на TASK-10, пока не сделан TASK-1,
   если явно не сказано обратное.
3. **После мержа** — отметь задачу в §6 как `✅` и при необходимости обнови
   §1 (что сделано). Не переписывай весь файл.
4. **Правила, которые нельзя нарушать:**
   - Бэкенд не трогаем (NestJS/Prisma/SQL/auth — отложено, §7).
   - E2E-тесты (Playwright/Cypress) **исключены** — только Vitest + React Testing Library.
   - Каждая новая строка UI добавляется **синхронно** в `src/locales/en` и `src/locales/ru`.
   - Данные (названия карточек, колонок, досок) **не переводятся** — только UI-хром.
   - Дизайн-токены: не хардкодить цвета — только переменные из `src/index.css`.

### 1.2. Архитектура (кратко)

- **Модель** — `Board { columns[], cards: Record<string,Card>, labels[] }`, `Card { id, title, description?, labelIds[], createdAt, updatedAt }`. Нормализовано: перестановка = перестановка id-массивов. `Board[]` на верхнем уровне — мультидоски уже заложены, но используется только `[0]`.
- **Состояние** — чистый `boardReducer` (15 экшенов) + `BoardContext` (дебаунс-персистентность, история, хоткеи, авто-бэкап). Компоненты вызывают типизированные удобные экшены.
- **Персистентность** — интерфейс `DebouncedPersistence` поверх `localStorage`; позже бэкенд = второй адаптер `fetch` **без изменения reducer и UI**.
- **UI** — shadcn/ui + Radix (dialog/dropdown/popover/tooltip/slot), dnd-kit, react-day-picker.
- **Тесты** — 103 теста в 11 файлах (reducer, history, persistence, serialization, backup, dnd, filter, storage, migrate, i18n, интеграционный BoardSection).

### 1.3. Ключи и точки интеграции

- Состояние/редьюсер: `src/store/BoardContext.tsx`, `src/store/board-reducer.ts`, `src/store/history.ts`.
- Модель: `src/types/kanban.ts` (туда добавлять новые поля карточки).
- Персистентность/данные: `src/utils/persistence.ts`, `src/utils/backup.ts`, `src/utils/board-serialization.ts`, `src/utils/storage.ts`.
- Миграции/сид: `src/store/migrate.ts`, `src/store/seed-data.ts`.
- Карточка UI: `src/components/board/CardItem.tsx`, `CardDialog.tsx`, `CardComposer.tsx`.
- Шапка: `src/components/Header.tsx` (+ `DataMenu.tsx`, `BackgroundSwitcher.tsx`, `LanguageSwitcher.tsx`).
- i18n: `src/locales/{en,ru}/translation.json`, типы из EN в `src/i18n/i18n.ts`.
- Токены: `src/index.css` (`:root`/`.light`, `@theme inline`).

## 2. Недочёты (архитектурные и продуктовые)

1. **Одна доска из `Board[]`** — модель готова к мультидоскам, но UI/роутинга нет; `state[0]` везде.
2. **Нет роутинга** — нет `react-router-dom`, нет deep-link на доску/карточку.
3. **Карточка минимальна** — нет срока, чек-листа, обложки, активности; описание — plain text без Markdown. Главный разрыв с Trello/Linear/Jira.
4. **Заголовок доски не редактируется**, нет создания/удаления/архивирования/дублирования доски.
5. **Хранилище — только `localStorage`** (лимит ~5 МБ, одно устройство). Риск снят экспортом/бэкапами, но синхронизации нет (нужен бэкенд, §7).
6. **Нет дублирования карточки/колонки**, нет сортировки внутри колонки.
7. **Поиск только по заголовку текущей доски** — не ищет по описанию и по другим доскам.
8. **Фильтр меток — только ANY** (нет переключателя ANY/ALL).
9. **Нет WIP-лимитов**, нет ленты активности, нет календарного вида, нет PWA/офлайн.
10. **Мелкое:** `updatedAt` обновляется на каждый символ при живом редактировании (шумит в timestamps, хотя сохранение уже дебаунсится).

## 6. План итераций (мелкие шаги, по порядку)

Каждая задача — отдельная ветка и отдельный PR. Внутри блока: цель, что трогаем,
критерий готовности (DoD), зависимости.

### Фаза A — Карточка и контент (акцент по запросу)

#### TASK-1 — `card-markdown` · Markdown-рендер описания

- **Зачем:** описание сейчас plain-text; Markdown — база для rich-редактора.
- **Что:** рендер `**жирный**`, `*курсив*`, `` `код` ``, списки, ссылки, заголовки в описании карточки. Переключатель «Редактировать / Просмотр» в `CardDialog`; превью-фрагмент на `CardItem`.
- **Затрагивает:** `src/types/kanban.ts` (без изменений модели), `src/components/board/CardDialog.tsx`, `CardItem.tsx`, `src/locales/*`, возможно `react-markdown`+`remark-gfm` (обсудить добавление зависимости).
- **DoD:** описание с Markdown рендерится в диалоге и на карточке; plain-text сохраняется как есть (обратная совместимость); тесты на рендерер; tsc/build/test зелёные.

#### TASK-2 — `card-editor-toolbar` · Панель форматирования (как в Jira)

- **Зачем:** кнопки жирный/курсив/код/ссылка/список вместо ручного ввода Markdown.
- **Что:** тулбар над полем описания; вставка Markdown-синтаксиса в позицию курсора; undo внутри textarea остаётся нативным.
- **Затрагивает:** `CardDialog.tsx` (компонент тулбара), `src/locales/*`, `src/index.css` (стили кнопок тулбара).
- **Зависит:** TASK-1.
- **DoD:** все кнопки вставляют корректный Markdown; работает выделение текста; tsc/build/test зелёные.

#### TASK-3 — `card-checklists` · Чек-листы (подзадачи)

- **Зачем:** todo-списки внутри карточки с прогрессом — запрошено.
- **Что:** модель `Checklist { id, title, items: [{id, text, done}] }` + `Card.checklists[]`; UI в `CardDialog` (добавление/галочки/переименование/удаление); бейдж «2/5» на `CardItem`; миграция старых данных (поле опционально — не ломает).
- **Затрагивает:** `src/types/kanban.ts`, `board-reducer.ts` (экшены ADD/UPDATE/DELETE checklist + toggle item), `BoardContext.tsx`, `CardDialog.tsx`, `CardItem.tsx`, `migrate.ts`, `locales/*`, тесты.
- **DoD:** чек-листы сохраняются/восстанавливаются; прогресс на карточке; undo/redo работает; экспорт/импорт включает чек-листы; тесты.

#### TASK-4 — `card-due-dates` · Сроки

- **Зачем:** классическая функция Trello; `react-day-picker` уже в стеке.
- **Что:** `Card.dueDate?: number`; выбор даты/времени в `CardDialog` (поповер с календарём); бейдж на карточке: просрочено (красный), скоро ≤24 ч (жёлтый); очистка срока.
- **Затрагивает:** `types/kanban.ts`, `board-reducer.ts`, `CardDialog.tsx`, `CardItem.tsx`, `locales/*`, тесты.
- **DoD:** срок ставится/снимается; подсветка просрочено/скоро; undo/redo; экспорт/импорт.

#### TASK-5 — `card-cover` · Обложка/цвет карточки

- **Зачем:** визуальное различие карточек (есть только метки).
- **Что:** `Card.cover?: { type: "color"|"gradient", value }`; пикер цвета/градиента в диалоге; цветная полоса/обложка на карточке.
- **Затрагивает:** `types/kanban.ts`, `board-reducer.ts`, `CardDialog.tsx`, `CardItem.tsx`, `locales/*`.
- **DoD:** обложка ставится/меняется/снимается; рендерится в обеих темах; тесты.

## 7. Бэкенд — отложено (НЕ делать сейчас)

Делаем **только после** того, как модель данных устоится (после TASK-1…TASK-5
`Card` получит чек-листы/сроки/обложку). Тогда:

- NestJS + Prisma + SQL + JWT-авторизация; схема копирует устоявшийся payload.
- Фронтенд получает **второй адаптер** `DebouncedPersistence` (`fetch` → `/api`), reducer/UI не трогаются.
- Бэкенд разблокирует: комментарии, исполнителей, вложения, синхронизацию устройств, embed-снапшот доски (публичная read-only HTML-страница без JS).

**Пока бэкенда нет — эти пункты в задачи не добавлять.**
