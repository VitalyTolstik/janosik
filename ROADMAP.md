## 0. Как работать с этим файлом (для ИИ-агентов)

1. **Одна задача = одна ветка = один пулл-реквест.** Перед началом итерации
   создай ветку `feature/TASK-{номер}-{slug}`. Пушишь — человек делает ревью
   и мержит сам. **Не мержить свою работу самостоятельно.**
2. **Иди строго по порядку:** §7.7 — для бэкенд-задач (TASK-22…30),
   §6 — для фронтенд-добивки (TASK-13…18). Не прыгай через задачи, если
   явно не сказано обратное.
3. **После мержа** — отметь задачу в §6 как `✅` и при необходимости обнови
   §1 (что сделано). Не переписывай весь файл.
4. **Правила, которые нельзя нарушать:**
   - Репозиторий — monorepo (см. §7.0): `ui/` (фронт), `backend/`,
     `shared/` (общий контракт). Фронтенд-правила действуют для `ui/`.
   - Бэкенд-стек зафиксирован (§7.1): NestJS/Prisma/PostgreSQL/JWT —
     не менять без явного решения пользователя.
   - E2E-тесты (Playwright/Cypress) **исключены** — только Vitest + React Testing Library.
   - Каждая новая строка UI добавляется **синхронно** в `src/locales/en` и `src/locales/ru`.
   - Данные (названия карточек, колонок, досок) **не переводятся** — только UI-хром.
   - Дизайн-токены: не хардкодить цвета — только переменные из `src/index.css`.

### 1.2. Архитектура (кратко)

- **Модель** — `Board { columns[], cards: Record<string,Card>, labels[] }`, `Card { id, title, description?, checklists?, labelIds[], createdAt, updatedAt }` (`Checklist { id, title, items: [{id, text, done}] }`). Нормализовано: перестановка = перестановка id-массивов. `Board[]` на верхнем уровне — мультидоски уже заложены, но используется только `[0]`.
- **Состояние** — чистый `boardReducer` (30 экшенов) + `BoardContext` (дебаунс-персистентность, история, хоткеи, авто-бэкап). Компоненты вызывают типизированные удобные экшены.
- **Персистентность** — интерфейс `DebouncedPersistence` поверх `localStorage`; позже бэкенд = второй адаптер `fetch` **без изменения reducer и UI**.
- **UI** — shadcn/ui + Radix (dialog/dropdown/popover/tooltip/slot), dnd-kit, react-day-picker, MDXEditor (описание карточки).
- **Тесты** — 287 тестов в 23 файлах (reducer, history, persistence, serialization, backup, backup-timestamp, dnd, filter, storage, migrate, i18n, интеграционные BoardSection + CardDialog + свитчер).

#### TASK-2 — `card-mdx-editor` · WYSIWYG-редактор описания (MDXEditor)

- **Статус:** ✅ реализовано (ветка `feature/TASK-2-mdx-description-editor`).
- **Зачем:** кнопки форматирования вместо ручного ввода Markdown; живой
  WYSIWYG вместо пары «textarea + превью».
- **Решение (обновлено пользователем):** официальный `@mdxeditor/editor`
  вместо самописного тулбара над textarea. react-markdown/remark-*
  полностью удалены — MDXEditor используется и для редактирования, и для
  read-only превью на карточке.
- **Что сделано:**
  - `DescriptionEditor` (edit, тулбар: undo/redo, тип блока, bold/italic,
    strikethrough, inline code, bullet/numbered/checklist, link) и
    лицо карточки текст описания не показывает (как в Trello): если
    описание есть — компактный бейдж с lucide-иконкой и тултипом
    `card.hasDescription`, если нет — ничего; полный текст живёт в диалоге
    карточки;
  - курируемый набор фич: заголовки, списки (включая `- [x]`), цитаты,
    ссылки, inline-код, `---`. Таблицы/код-блоки/картинки — плагины
    включены без кнопок, чтобы старые данные (сид/импорт) круглосуточно
    реэкспортировались без ошибок;
  - безопасность: `suppressHtmlProcessing` — сырой HTML из текста
    (импорт JSON/вставка) остаётся буквальным текстом, не исполняется;
    плюс собственная санитизация `sanitizeMarkdownForImport`: у image-плагина
    MDXEditor есть `innerHTML`-сток (`MdastImageVisitor` для HTML-`<img>`,
    подтверждено PoC — `<img src=x onerror=…>` исполняется даже с
    `suppressHtmlProcessing`), а прочий сырой HTML роняет импорт целиком.
    Санитайзер вырезает сырой HTML до подачи в редактор; инвариант —
    «в AST после санитизации нет ни одного `html`-узла» — проверяется
    дифференциально против настоящего remark-парсера: регрессионные
    обходы (backtick в info-строке fence, пары бэктиков, escaped-бэктики,
    продолжение html-блока) + 10 000 детерминированных fuzz-комбинаций;
    HTML в fenced-блоках сохраняется (там он для remark — инертный текст),
    в inline-коде — вырезается (fail-safe: точное зеркало парсинга
    бэктиков в micromark невоспроизводимо, а ошибочная «защита» экранирует
    живой тег); ссылки дополнительно защищены `@lexical/link`
    (протокол-allowlist, `javascript:` → `about:blank`);
  - иконки заменены на lucide через официальный проп `iconComponentFor`;
  - i18n: проп `translation` завязан на каталоги `editor.*` (en/ru);
  - темы: все цвета редактора — на дизайн-токенах (`index.css`, блок
    MDXEditor), тёмная/светлая работают автоматически, без классов
    `dark-theme`; тулбар/контент переписаны под токены (Tailwind preflight
    обнуляет типографику — она восстановлена явно);
  - попапы (link dialog, dropdown типа блока) порталится в `document.body`
    и поднимаются `z-index` над диалогом: центрирование диалога делает
    `transform`, который ломает координаты `position: fixed` внутри него —
    поэтому `overlayContainer` внутрь диалога передавать нельзя;
    тултипы кнопок оформлены (токены вместо нечитаемого дефолта);
  - модалка ссылки центрирована (`:has()` по классу попапа) с крестиком
    в правом верхнем углу (Cancel-контрол с lucide X через CSS-маску —
    в библиотеке он текстовый, без иконки); центрируется ТОЛЬКО форма
    редактирования, а превью-поповер при клике на ссылку остаётся
    привязанным к самой ссылке: для этого Radix-диалог центрируется
    через `inset-0 + margin auto`, а не `transform` — transform делает
    диалог containing block для `position: fixed` потомков, и якорь
    превью (viewport-координаты) молча улетал мимо ссылки; у
    центрированной формы библиотечный «хвостик»-стрелка скрыт (Radix
    ставит инлайн `display: block` — гасится `!important`); полей два —
    URL и текст ссылки (текст показывается, только когда некуда
    крепить), поле HTML-`title` выключено (`showLinkTitleField: false`);
    в превью-поповере ссылки кнопки (редактировать/копировать/убрать)
    приведены к размеру остального хрома редактора (иконки 15px вместо
    24px);
    чекбоксы чек-листа выровнены в одну линейку с маркерами списков и
    стилизованы единообразно с чек-листами карточки (TASK-3): прозрачные
    с бордером-токеном, отмеченные — заливка `--primary` + белая галочка;
  - диалог карточки расширен до `sm:max-w-3xl`, грид-трек `minmax(0,1fr)`
    против переполнения на мобильных.
- **Затрагивает:** `src/components/editor/*` (новое), `CardDialog.tsx`,
  `CardItem.tsx`, `ui/dialog.tsx`, `src/index.css`, `src/locales/*`,
  `package.json` (`+ @mdxeditor/editor`, `- react-markdown`, `- remark-gfm`,

- **DoD:** ✅ форматирование применяется/сериализуется в Markdown; чек-лист,

## 7. Бэкенд — полный план (фаза активна)

> Решение пользователя: **совместные доски** (много юзеров, логины, шаринг,
> видно кто что сделал) → бэкенд проектируется **нормализованным**: сущности
> в таблицах, гранулярный REST, фронт работает optimistic поверх редьюсера.
> Порядок: §7.7, TASK-22 → 30. Фронтенд-добивка TASK-13…18 параллельна.

### 7.0. Ключевые решения (зафиксированы, не пересматривать без явной причины)

- **Monorepo, npm workspaces**: `ui/` (фронт), `backend/` (NestJS),
  `shared/` (`@janosik/shared` без build-степа): модель, `LIMITS`, envelope
  экспорта, `STORAGE_KEYS`, **DTO-типы API** (контракт фронт↔бэк).
- **Нормализованная схема** — «полный канбан на бэке»: колонки/карточки/
  метки/чеклисты/активность/комментарии — SQL-таблицы (§7.3), не Json-документ.
  Позиции — целочисленные `position` (drag → `reorder` endpoint с перенумерацией
  при необходимости).
- **API — гранулярный REST `/api/v1`** (~30 endpoints, §7.4). Каждый экшен
  редьюсера получает свой endpoint; сервер — единственный источник истины.
- **Фронт — optimistic без переписывания UI**: редьюсер остаётся
  единственным источником UI-состояния (мгновенный отклик, undo/redo
  работают). Адаптер шлёт API-вызов асинхронно и **reconcile**-ит canonical
  ответ (позиции, серверные поля). Провал вызова → откат экшена + тост.
  **id генерирует клиент** (`createId()`) и передаёт в POST → идемпотентные
  ретраи, undo создания = `DELETE` того же id.
- **Доступ — membership**: `BoardMember {board, user, role: OWNER|MEMBER}`
  (VIEWER — позже). Guard проверяет membership на каждом board-scoped
  endpoint. `actorId` во всей активности — реальный юзер.
- **Синхронизация мульти-юзеров:** MVP — refetch агрегата доски при focus
  окна; затем **SSE** (`GET /boards/:id/events`) в TASK-30 — живые изменения
  чужих курсоров/карточек. WebRTC/CRDT не нужны (разрешение конфликтов —
  last-write-wins на уровне сущности + активность).
- **Auth:** JWT access (15 мин, память SPA) + refresh (30 дней, httpOnly
  Secure SameSite=Strict, ротация с детектом реюза). Пароли — argon2id.
- **Валидация — `LIMITS`** (TASK-20) на DTO + серверный normalize — тот же
  код, что `migrate.ts`. Импорт клампит всё, что пришло мимо UI.
- **Ошибки:** дефолтный envelope NestJS; `403` — нет membership, `409` —
  конфликт позиций/версии, `404` — чужая сущность (не раскрываем существование).

### 7.5. Фронтенд-адаптер (TASK-29)

- **Optimistic:** компоненты по-прежнему зовут экшены редьюсера; редьюсер —
  источник UI-состояния (отклик мгновенный, undo/redo без сети).
- **Sync-слой:** каждый экшен → API-вызов → canonical ответ → reconcile
  (позиции, счётчики). Провал → откат экшена (обратный dispatch) + тост.
- **id клиента проходит в POST** — идемпотентные ретраи; undo создания
  карточки = `DELETE /cards/:id`.
- **Старт:** `GET /boards/:id` → маппинг агрегата в текущую модель `Board[]`
  (формат ответа шейпится под редьюсер) → `REPLACE_STATE`. Компоненты/UI не
  меняются.
- **Первый логин:** локальный `janosik-boards` (если есть) →
  `POST /boards/import` (данные переезжают в БД) → localStorage очищается.
- **Чужие изменения:** refetch агрегата на window focus (MVP), с TASK-30 —
  SSE-патчи на месте.
- **Офлайн:** тост «нет сети, изменения не сохранены», очередь экшенов —
  с PWA (TASK-15).

## 8. Definition of Done (для каждой задачи)

Перед пушем ветки обязательны, иначе PR не готов. После TASK-22
(monorepo, §7.0) команды выполняются в пакете через `-w`:

```bash
# фронтенд (ui/)
npm test -w ui              # все тесты зелёные
npx tsc -b --force          # 0 ошибок (команда без пайпа!)
npm run build -w ui         # сборка зелёная

# бэкенд (backend/, с TASK-23)
npm test -w backend         # unit + e2e (supertest, тестовая БД)
npx tsc -b --force          # 0 ошибок
```

Плюс:

- новые строки UI есть и в `en`, и в `ru`;
- типы ключей не сломаны (`tsc` ловит рассинхрон);
- токены/цвета — только из `src/index.css`, без хардкода;
- `prefers-reduced-motion` учтён для новых анимаций;
- dev-сервер поднимается на `http://localhost:5199/` (HTTP 200);
- backend-задачи: `npx prisma migrate dev` применяется чисто, e2e против
  тестовой БД из docker-compose, секреты — только в `.env` (в git не попадает).
